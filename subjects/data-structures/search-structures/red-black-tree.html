Red-Black Tree 紅黑樹用紅黑兩色限制路徑長度，插入最多旋轉 2 次、刪除最多 3 次的平衡 BST

Ch10 Search Structures 難度 balanced BST rotation insert delete 2-3-4 tree

為什麼需要紅黑樹

Binary Search Tree 二元搜尋樹的搜尋、插入、刪除都是 O(h)，h 是樹高。資料隨機時 h 大約是 log n，可是只要資料是遞增插入（例如 1, 2, 3, …, n），BST 就會退化成一條鏈，h = n，所有操作都變成 O(n)，和直接用鏈結串列沒有差別。

解法是讓樹在插入、刪除之後自己調整形狀，一直把高度壓在 O(log n)，這類結構叫做 Self-Balancing BST（自我平衡二元搜尋樹）。最有名的兩種是 AVL 樹（籌備中）和本頁的 Red-Black Tree（紅黑樹）：

  • AVL 樹要求每個節點左右子樹高度差 ≤ 1，平衡得很嚴格，搜尋最快，但插入、刪除時常常要一路往上檢查、旋轉。
  • 紅黑樹把條件放寬：只保證「最長的路徑不超過最短路徑的 2 倍」。樹可能比 AVL 高一點，但每次插入最多旋轉 2 次、刪除最多 3 次，調整的成本比較低，所以實務上用得最多，例如 C++ 的 std::map、Java 的 TreeMap、Linux 的行程排程器都用紅黑樹。

紅黑樹的做法是替每個節點塗上紅或黑，用幾條顏色規則間接限制樹高。讀這一頁的順序是：先看五條性質，再看它們為什麼保證 O(log n)，然後學旋轉，最後是插入與刪除的修正規則。搜尋和 BST 完全一樣，不用另外學。

本頁的畫法：圖和動畫裡方形 = 黑色節點、圓形 = 紅色節點（和許多考卷的畫法一樣，不靠顏色也看得出來）；節點外框的顏色只代表「目前正在處理哪個節點」，和紅黑無關。文字中寫 50B、62R 代表 50 是黑、62 是紅。

定義：五條性質

紅黑樹是一棵 BST，每個節點多存一個顏色欄位，而且要同時滿足下面五條：

  1. 每個節點不是紅就是黑。
  2. 根是黑色。
  3. 所有 External Node（外部節點，NIL）都是黑色。NIL 就是空指標的位置，n 個內部節點的二元樹一定有 n + 1 個 NIL。
  4. 紅色節點的兩個子節點都是黑色，也就是路徑上不會出現連續兩個紅色。
  5. 對每個節點，從它往下走到任何一個 NIL 的路徑，經過的黑色節點數都相同。

第 5 條的那個數字叫做 Black Height（黑高度，bh，有些題目叫 rank）。常見的算法有兩種：「從根往下、含根、不含 NIL 的黑色節點數」或「不含根、含 NIL」。因為根一定是黑，這兩種算出來的數字一樣；但如果「根和 NIL 都算」就會多 1。作答時先寫清楚自己的定義，本頁一律用「含根、不含 NIL」。

幾個容易誤會的地方，考題很愛拿來出是非題：

  • 黑黑可以相連：規則只禁止紅紅相連。全部塗黑的完美二元樹也是合法的紅黑樹，紅色節點可以是 0 個。
  • 每條路徑「黑色」數一樣，紅色數不一定一樣。圖 1 中 30 → 15 → 20 → 25 → NIL 經過 2 個紅，30 → 15 → 10 → NIL 只經過 1 個紅，但兩條都是 2 個黑。
  • 紅黑樹不保證左右子樹高度差 ≤ 1，那是 AVL 的條件。
  • 它本身就是 BST，中序走訪一樣是遞增排序。

判斷一棵樹是不是合法的紅黑樹，要依序檢查：(1) 是不是 BST、(2) 根是不是黑、(3) 有沒有紅紅相連、(4) 每條根到 NIL 的路徑黑色數是不是都一樣。第 (4) 點最容易漏看只有一個子節點的節點：它的空的那一邊也是一條到 NIL 的路徑。

看程式碼：節點結構與 NIL 的顏色
節點結構、colorOf()
typedef enum { RED, BLACK } Color;

typedef struct Node {
  int key;
  Color color;
  struct Node *left, *right, *parent;
} Node;

Node *root = NULL;

Color colorOf(Node *x) { return x == NULL ? BLACK : x->color; } /* NIL 是黑 */

為什麼高度是 O(log n)

五條性質看起來和「高度」沒有直接關係，關鍵在第 4、5 條合起來的效果：

  • 每條路徑的黑色數都是 bh，所以最短的路徑至少有 bh 個節點（全黑）。
  • 紅色不能相連，紅色最多只能夾在黑色之間，所以最長的路徑最多 2·bh 個節點（黑紅交錯）。

所以任何一條根到 NIL 的路徑，長度都不會超過最短路徑的 2 倍。再來估計節點數：

引理：黑高度為 b 的紅黑樹至少有 2b − 1 個內部節點。直覺是「只看黑色節點，它們撐起一棵高度 b 的完美二元樹」，嚴格證明用數學歸納法（見 例題）。

設樹高為 h（根到最深 NIL 經過的內部節點數），最長路徑上至少一半是黑，所以 bh ≥ h/2。代入引理：

n ≥ 2^bh − 1 ≥ 2^(h/2) − 1
⇒ h ≤ 2 log2(n + 1)

也就是說，紅黑樹最高也只是完美平衡樹（約 log2 n 層）的 2 倍，搜尋最差是 O(log n)。例如 n = 106 時，log2 n ≈ 20，紅黑樹最多約 40 層，而退化的 BST 可能有一百萬層。

給定黑高度：最少、最多幾個節點

這是常見的計算題。黑高度 b（含根、不含 NIL）時：

  • 最少：完全不用紅色，全黑的完美二元樹，高度 b，共 2b − 1 個。
  • 最多：每條路徑都黑紅交錯到長度 2b，而且每層都塞滿，是一棵高度 2b 的完美二元樹（黑、紅一層一層交替，最底層是紅），共 22b − 1 = 4b − 1 個。

給定節點數：最高能多高

反過來，n 個節點的紅黑樹最高幾層？不能直接套 2 log2(n + 1)，那只是保證的上限，通常達不到。正確做法是算「高度 h 最少要幾個節點」：讓最長的那條路徑黑紅交錯，旁邊掛的子樹都用剛好補足黑高度的全黑完美樹。用程式算出來：

高度 h（層）12345678
紅黑樹最少節點124610142230
AVL 最少節點124712203354

例如 n = 15：紅黑樹最少節點 14 ≤ 15 < 22，最高 6 層；AVL 是 12 ≤ 15 < 20，最高 5 層；完美平衡的話是 4 層。上界 2 log2 16 = 8 層則根本達不到。從表也看得出 AVL 比紅黑樹「更平衡」：同樣的高度，AVL 需要的最少節點數比較多。

旋轉：只改指標、不破壞 BST

調整形狀的基本工具是 Rotation（旋轉），和 AVL 用的是同一種。左旋 x：把 x 的右子 y 轉上來當這棵子樹的根，x 變成 y 的左子，原本 y 的左子樹 β 改掛到 x 的右邊。右旋是鏡像。

旋轉只改常數個指標（x、y、β 的 parent 和 child，再加上原本父節點指向誰），所以是 O(1)。旋轉本身不改顏色，紅黑樹的修正都是「旋轉＋重新著色」一起用。要注意如果 x 原本是根，旋轉後 root 要改成 y，程式最容易漏掉這一步。

看程式碼：左旋／右旋
leftRotate()
void leftRotate(Node *x) {
  Node *y = x->right;
  x->right = y->left;                     /* β 搬到 x 的右邊 */
  if (y->left != NULL) y->left->parent = x;
  y->parent = x->parent;                  /* y 接到 x 原本的父節點 */
  if (x->parent == NULL) root = y;
  else if (x == x->parent->left) x->parent->left = y;
  else x->parent->right = y;
  y->left = x;                            /* x 變成 y 的左子 */
  x->parent = y;
}
rightRotate()
void rightRotate(Node *x) {
  Node *y = x->left;
  x->left = y->right;                     /* β 搬到 x 的左邊 */
  if (y->right != NULL) y->right->parent = x;
  y->parent = x->parent;
  if (x->parent == NULL) root = y;
  else if (x == x->parent->right) x->parent->right = y;
  else x->parent->left = y;
  y->right = x;                           /* x 變成 y 的右子 */
  x->parent = y;
}

插入：塗紅，再看叔叔

插入分兩步：先照 BST 的規則把新節點 z 放到葉子的位置，塗成紅色；再呼叫 insertFixup 修正。為什麼塗紅？塗黑的話，經過 z 的路徑黑色數會多 1，第 5 條馬上被破壞，而且影響整棵樹；塗紅則黑色數完全不變，唯一可能出問題的是父節點也是紅（紅紅相連），這只牽涉 z 附近的幾個節點，可以局部修好。

如果父節點 p 是黑，什麼都不用做。如果 p 是紅，因為根是黑，p 一定不是根，祖父 g 一定存在而且是黑。這時看 z 的叔叔 u（p 的兄弟，也就是 g 的另一個子節點）。以下以「p 是 g 的左子」為例，p 是右子時左右對調：

情況條件處理之後
case 1叔叔 u 是紅p、u 塗黑，g 塗紅g 變紅後可能又和它的父節點紅紅相連，令 z = g 往上繼續
case 2u 是黑，z 是 p 的右子（g → p → z 是折線）對 p 左旋，令 z = 原本的 p變成 case 3
case 3u 是黑，z 是 p 的左子（一直線）p 塗黑、g 塗紅，對 g 右旋子樹的根是黑，結束

另一種常見的命名是用兩個字母加叔叔的顏色：第一個字母是 p 在 g 的哪一邊、第二個是 z 在 p 的哪一邊，r / b 是叔叔的顏色。例如 LLr、LRr、RLr、RRr 都是 case 1（只變色）；LRb、RLb 是 case 2 加 case 3（旋轉 2 次）；LLb、RRb 是 case 3（旋轉 1 次）。兩套名字講的是同一件事。

為什麼這樣做是對的

  • case 1：g 原本是黑、兩個子是紅，變色後 g 紅、兩個子黑。g 底下每條路徑的黑色數不變，只是 g 自己可能和上面紅紅相連，所以問題往上移兩層。一路移到根的話，最後把根塗黑，整棵樹的黑高度 +1——這是黑高度唯一會增加的方式。
  • case 3：右旋 g 之後，p 成為子樹的根並塗黑，原本的 g 變成 p 的紅色子節點。子樹的根仍是黑、黑高度不變，上面不可能再出問題，迴圈直接結束。
  • case 2 只是把折線轉成直線，再交給 case 3。所以一次插入最多旋轉 2 次，case 1 則可能往上做 O(log n) 次（只變色，每次 O(1)）。

特別注意：叔叔是 NIL 時當成黑色，要旋轉，不能變色。考題的陷阱幾乎都在這裡。

例子：依序插入 40, 20, 10, 30, 35, 50, 45

插入發生什麼事插入後的樹
40成為根，塗黑40B
20父 40 黑，不用修40B(20R, -)
10父 20 紅、叔叔 NIL（黑），40 → 20 → 10 一直線：case 3（LLb），右旋 4020B(10R, 40R)
30父 40 紅、叔叔 10 紅：case 1（RLr），10、40 塗黑、20 塗紅，20 是根再塗回黑20B(10B, 40B(30R, -))
35父 30 紅、叔叔 NIL：40 → 30 → 35 是折線，case 2 左旋 30，再 case 3 右旋 4020B(10B, 35B(30R, 40R))
50父 40 紅、叔叔 30 紅：case 1（RRr），35 變紅，35 的父 20 是黑，停20B(10B, 35R(30B, 40B(-, 50R)))
45父 50 紅、叔叔 NIL：40 → 50 → 45 是折線（RLb），右旋 50、再左旋 4020B(10B, 35R(30B, 45B(40R, 50R)))

7 次插入共旋轉 5 次、case 1 變色 2 次，最後樹高 4 層、黑高度 2。這組資料用普通 BST 也是 4 層，紅黑樹的好處要在「不好的」資料才看得出來：遞增插入 1～7，普通 BST 是 7 層的鏈，紅黑樹只有 4 層。

補充：有些教材介紹 top-down 的插入法，往下找位置的途中只要看到「黑節點有兩個紅子」就先變色（等於預先拆開 2-3-4 tree 的 4-node），到底之後最多再旋轉一次，不用往回走。結果的樹可能和本頁的 bottom-up 做法不同；考題沒特別說明時，都用本頁的做法。

看程式碼：插入與修正
insertFixup()：依叔叔顏色變色或旋轉
void insertFixup(Node *z) {
  while (colorOf(z->parent) == RED) {     /* 父紅 → 祖父一定存在且是黑 */
    Node *p = z->parent, *g = p->parent;
    if (p == g->left) {
      Node *u = g->right;                 /* 叔叔 */
      if (colorOf(u) == RED) {            /* case 1：叔叔紅 → 變色，問題上移 */
        p->color = BLACK;
        u->color = BLACK;
        g->color = RED;
        z = g;
      } else {
        if (z == p->right) {              /* case 2：LR 型，先左旋父變 LL */
          z = p;
          leftRotate(z);
          p = z->parent;
        }
        p->color = BLACK;                 /* case 3：LL 型，父祖換色再右旋 */
        g->color = RED;
        rightRotate(g);
      }
    } else {                              /* 鏡像：父是祖父的右子 */
      Node *u = g->left;
      if (colorOf(u) == RED) {            /* case 1（鏡像）：叔叔紅 → 變色 */
        p->color = BLACK;
        u->color = BLACK;
        g->color = RED;
        z = g;
      } else {
        if (z == p->left) {               /* case 2（鏡像）：RL 型，先右旋父 */
          z = p;
          rightRotate(z);
          p = z->parent;
        }
        p->color = BLACK;                 /* case 3（鏡像）：RR 型，再左旋祖父 */
        g->color = RED;
        leftRotate(g);
      }
    }
  }
  root->color = BLACK;                    /* 根一定塗黑 */
}
rbInsert()：BST 插入後塗紅
int rbInsert(int key) {
  Node *p = NULL, *x = root;
  while (x != NULL) {
    p = x;
    if (key == x->key) return 0;          /* 已存在，不插入 */
    x = key < x->key ? x->left : x->right;
  }
  Node *z = malloc(sizeof(Node));
  z->key = key;
  z->left = z->right = NULL;
  z->parent = p;
  z->color = RED;                         /* 新節點一律塗紅 */
  if (p == NULL) root = z;
  else if (key < p->key) p->left = z;
  else p->right = z;
  insertFixup(z);
  return 1;
}

刪除：處理少掉的那個黑

刪除的前半段和 BST 一樣：要刪的節點有兩個子節點時，找左子樹最大（中序前驅）或右子樹最小（中序後繼），把它的 key 複製過來（只換 key、不換顏色），改成刪除那個前驅或後繼。它最多只有一個子節點，所以問題一定會變成「刪除一個最多只有一個子節點的節點 z」。本頁預設用前驅，動畫可以切換成後繼；兩種都對，但結果的樹可能不同，題目有指定時要照題目做。

三種起點

  • z 是紅色葉子：直接拿掉。紅色不影響任何路徑的黑色數，也不會造成紅紅相連，不用任何調整。
  • z 只有一個子節點：這時一定是「z 黑、子紅」（若子是黑，z 兩邊的黑色數就不一樣了）。讓子節點頂替 z 的位置並塗黑，補回拿掉的那個黑，結束。
  • z 是黑色葉子：拿掉後經過那裡的路徑少了一個黑，這是唯一麻煩的情況。想像那個位置多帶了一個黑，叫做 Double Black（雙黑），記為 x，接著要把這個多出來的黑「還掉」。

double black 的四種 case

以「x 是父節點 p 的左子」為例，s 是 x 的兄弟；s 靠近 x 那一側的子節點叫近姪、另一側叫遠姪（x 是右子時左右對調）：

情況條件處理之後
case 1兄弟 s 是紅s 塗黑、p 塗紅，對 p 左旋x 換到一個黑色兄弟，進 case 2～4
case 2s 黑，兩個姪子都黑s 塗紅，x 往上移到 pp 紅：塗黑結束；p 黑：p 成為新的 x，繼續
case 3s 黑，遠姪黑、近姪紅近姪塗黑、s 塗紅，對 s 右旋變成 case 4
case 4s 黑，遠姪紅s 取 p 的顏色、p 塗黑、遠姪塗黑，對 p 左旋結束

直覺：x 這一邊少一個黑，要嘛從兄弟那邊借（case 3、4 靠旋轉把一個黑節點搬到 x 這邊），要嘛兄弟那邊也減一個黑扯平（case 2 把 s 塗紅），再把問題丟給上一層。case 1 只是準備動作，把紅色兄弟轉走。所以 case 4 做完一定結束，case 2 才可能一路往上走 O(log n) 次；整個刪除最多旋轉 3 次（case 1 → 3 → 4）。

例子

從上一節插入完的樹 20B(10B, 35R(30B, 45B(40R, 50R))) 開始，依序刪除：

  1. 刪 10：黑色葉子，x = 10。兄弟 35 是紅 → case 1：35 塗黑、20 塗紅、左旋 20，新的兄弟是 30（黑，兩個子都是 NIL）→ case 2：30 塗紅、x 移到 20；20 是紅，塗黑結束。結果 35B(20B(-, 30R), 45B(40R, 50R))。
  2. 刪 45：兩個子節點，前驅是 40，把 40 複製上去，改刪原本的 40。它是紅色葉子，直接拿掉。結果 35B(20B(-, 30R), 40B(-, 50R))。
  3. 刪 20：黑色、只有一個紅子 30 → 30 頂上並塗黑。結果 35B(30B, 40B(-, 50R))。

case 3、case 4 可以在下面動畫按「例：刪除 42（前驅取代）」看到。

看程式碼：刪除（左子樹最大／右子樹最小）與修正
rbDelete()：兩個子節點時用中序前驅
int rbDelete(int key) {
  Node *z = search(key);
  if (z == NULL) return 0;                /* 找不到 */
  if (z->left != NULL && z->right != NULL) {
    Node *s = z->left;                    /* 左子樹最大 */
    while (s->right != NULL) s = s->right;
    z->key = s->key;                      /* 複製前驅的值 */
    z = s;                                /* 改成刪除前驅，它沒有右子 */
  }
  removeOne(z);
  return 1;
}
rbDeleteSucc()：兩個子節點時用中序後繼
int rbDeleteSucc(int key) {
  Node *z = search(key);
  if (z == NULL) return 0;
  if (z->left != NULL && z->right != NULL) {
    Node *s = z->right;                   /* 右子樹最小 */
    while (s->left != NULL) s = s->left;
    z->key = s->key;                      /* 複製後繼的值 */
    z = s;                                /* 改成刪除後繼，它沒有左子 */
  }
  removeOne(z);
  return 1;
}
removeOne()：拿掉最多一個子節點的節點
void replaceNode(Node *u, Node *v) {
  if (u->parent == NULL) root = v;
  else if (u == u->parent->left) u->parent->left = v;
  else u->parent->right = v;
  if (v != NULL) v->parent = u->parent;
}

void removeOne(Node *z) {
  Node *child = z->left != NULL ? z->left : z->right;
  if (child != NULL) {                    /* z 黑、child 紅：child 頂上並塗黑 */
    child->color = BLACK;
    replaceNode(z, child);
  } else {
    if (z->color == BLACK) deleteFixup(z); /* 黑色葉子：先修 double black */
    replaceNode(z, NULL);                 /* 紅色葉子：直接拿掉 */
  }
  free(z);
}
deleteFixup()：消除 double black
void deleteFixup(Node *x) {
  while (x != root && x->color == BLACK) {
    Node *p = x->parent;
    if (x == p->left) {
      Node *s = p->right;                 /* 兄弟 */
      if (colorOf(s) == RED) {            /* case 1：兄弟紅 → 旋轉成兄弟黑 */
        s->color = BLACK;
        p->color = RED;
        leftRotate(p);
        s = p->right;
      }
      if (colorOf(s->left) == BLACK && colorOf(s->right) == BLACK) {
        s->color = RED;                   /* case 2：兄弟黑、兩姪黑 → 兄弟變紅，上移 */
        x = p;
      } else {
        if (colorOf(s->right) == BLACK) { /* case 3：遠姪黑、近姪紅 → 先右旋兄弟 */
          s->left->color = BLACK;
          s->color = RED;
          rightRotate(s);
          s = p->right;
        }
        s->color = p->color;              /* case 4：遠姪紅 → 左旋父，結束 */
        p->color = BLACK;
        s->right->color = BLACK;
        leftRotate(p);
        x = root;
      }
    } else {                              /* 鏡像：x 是右子 */
      Node *s = p->left;
      if (colorOf(s) == RED) {            /* case 1（鏡像）：兄弟紅 */
        s->color = BLACK;
        p->color = RED;
        rightRotate(p);
        s = p->left;
      }
      if (colorOf(s->left) == BLACK && colorOf(s->right) == BLACK) {
        s->color = RED;                   /* case 2（鏡像）：兩姪黑 */
        x = p;
      } else {
        if (colorOf(s->left) == BLACK) {  /* case 3（鏡像）：遠姪黑、近姪紅 */
          s->right->color = BLACK;
          s->color = RED;
          leftRotate(s);
          s = p->left;
        }
        s->color = p->color;              /* case 4（鏡像）：遠姪紅 → 右旋父 */
        p->color = BLACK;
        s->left->color = BLACK;
        rightRotate(p);
        x = root;
      }
    }
  }
  x->color = BLACK;                       /* 紅色節點吸收多出來的黑 */
}

程式的小技巧：黑色葉子的情況，先把 z 本身當成 x 做修正，修完才把它拿掉。這樣 x 一定是真正存在的節點，不必處理「x 是 NULL 時找不到父節點」的麻煩。

動手操作

輸入一個 key，或用逗號隔開的一串 key（例如 10,20,30,15），按 insert 或 delete。右側程式碼會亮起正在執行的那一行，上方的指標標出 z、p（父）、g（祖父）、u（叔叔）或 x（雙黑）、s（兄弟）；叔叔或兄弟是 NIL 時會畫出虛線框。初始示範是插入 62，一次就看完 case 1、2、3；下面的例子按鈕分別示範空樹插入、刪除時兄弟紅（case 1 → 2）和前驅取代後的 case 3 → 4。

紅黑樹就是 2-3-4 tree

2-3-4 樹（籌備中）是一種多路搜尋樹：每個節點放 1～3 個 key（稱為 2-node、3-node、4-node），而且所有葉子都在同一層。把紅黑樹中每個黑節點和它的紅色子節點合併成一個節點，就會得到一棵 2-3-4 tree：

  • 黑節點沒有紅子 → 2-node；有一個紅子 → 3-node；兩個紅子 → 4-node。
  • 紅色節點不能相連，保證合併後每個節點最多 3 個 key。
  • 紅黑樹的黑高度 = 2-3-4 tree 的高度，所以「每條路徑黑色數相同」就是「所有葉子同一層」。

反過來，一棵 2-3-4 tree 可以對應好幾棵紅黑樹：4-node 只有一種畫法（中間的 key 黑、兩邊紅），3-node 有兩種（紅子在左或在右）。這個對應也解釋了插入的 case：case 1 變色就是把 4-node 拆開、把中間的 key 往上推（2-3-4 tree 的 split）；旋轉則是在同一個節點內換一個 key 當黑色代表。

注意：一般的紅黑樹對應的是 2-3-4 tree，不是 2-3 tree。只有限制「紅色只能當左子」的變形（Left-Leaning Red-Black Tree）才和 2-3 tree 一一對應。

常見的誤會是「紅黑樹插入是 O(1)」：O(1) 的是旋轉次數，往下找位置本身就要 O(log n)。

BST最差 n不調整資料隨機、不在乎最差情況

紅黑樹每個節點只有 2 個分支，放在磁碟上時樹太高，每走一層就要讀一次 page，所以資料庫索引用 B-tree（籌備中）、B+ tree（籌備中）而不是紅黑樹。

紅黑樹也常被擴充：例如每個節點多存子樹大小 size，就能在 O(log n) 找出第 i 小的 key（order statistic tree）。擴充的欄位不影響顏色規則，只要在旋轉時順便更新兩個節點的 size 即可（旋轉只改變這兩個節點的子樹）。

  • 叔叔是 NIL，就當作沒有叔叔、只要變色 → NIL 是黑色，叔叔黑就要旋轉（直線 1 次、折線 2 次） 例題
  • case 1 變色完就結束了 → 祖父變紅後要往上兩層再檢查，可能連續變色，或接著旋轉 例題
