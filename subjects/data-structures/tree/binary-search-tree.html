Binary Search Tree（二元搜尋樹）左子樹都比我小，右子樹都比我大

Ch5 Trees 難度 ★★☆ BST insert delete

什麼是 Binary Search Tree

假設要維護一群會不斷新增、刪除的資料，又要能很快地找到某個值。排序好的陣列可以用二分搜尋，在 O(log n) 找到資料，但插入或刪除時要搬動一大堆元素，要 O(n)；鏈結串列插入、刪除很方便，搜尋卻只能從頭一個一個找，也是 O(n)。有沒有辦法同時擁有兩者的優點？

Binary Search Tree（二元搜尋樹，BST）就是答案。它是一棵二元樹，每個節點存一個 key（鍵值），並且所有節點都滿足：

📌 BST 性質：節點的左子樹中所有 key 都比它小，右子樹中所有 key 都比它大；而且左、右子樹本身也都是 BST。

注意是「整棵左子樹」，不是只看直接相連的左子節點。圖 1 (b) 中，每個節點和自己的子節點比都沒問題，但 12 落在 10 的左子樹裡，卻比 10 大，所以整棵樹就不是 BST。這是考題最常設的陷阱。

一般的 BST 定義中 key 不重複。如果真的要存重複值，常見做法是在節點加一個計數器，或約定相同的 key 一律放右邊。考試沒特別說明時，就當作不允許重複。

搜尋：每一步丟掉一半

要找 key = x，從 root 開始比較：

  1. x 等於目前節點的 key → 找到了。
  2. x 比較小 → 答案只可能在左子樹，往左走。
  3. x 比較大 → 答案只可能在右子樹，往右走。
  4. 走到 NULL 還沒找到 → 樹裡沒有 x。

每比較一次就排除了整棵另一側的子樹，這和二分搜尋把範圍砍半是同一個想法。比較的次數最多等於樹高 h，所以搜尋是 O(h)。

插入：新節點一定是葉子

插入 x 的過程就是「搜尋 x，直到走到 NULL」：照搜尋的規則一路往下比較，走到哪個空位，就把新節點接在那裡。所以新插入的節點一定是葉節點，不需要調整任何既有節點。如果途中遇到相同的 key，就代表已經存在，不插入。

插入的花費和搜尋一樣是 O(h)。但要特別注意：同一組資料，插入順序不同，長出來的樹形狀就不同，高度也可能差很多。如果資料剛好是排序好的才依序插入，每個新節點都會接在最右邊，整棵樹退化成一條鏈，搜尋就變回 O(n)。

刪除：三種情況

刪除比插入麻煩，因為被刪的節點可能在樹的中間，拿掉之後要確保樹還連得起來、而且仍然符合 BST 性質。先用搜尋找到要刪的節點，再依它有幾個子節點分成三種情況：

Case 1：葉節點（沒有子節點）

直接移除，把父節點指向它的指標設成 NULL。例如在動畫的初始樹刪除 20，30 的左指標變成 NULL 即可。

Case 2：只有一個子節點

讓它唯一的子節點（連同整棵子樹）直接接到它原本的位置。因為那棵子樹原本就在被刪節點的同一側，所以 BST 性質不會被破壞。例如刪除 60（只有右子節點 65），65 直接接到 70 的左邊。

Case 3：有兩個子節點

這時不能直接拿掉，否則兩棵子樹沒地方接。做法是找一個「最適合頂替它」的值：要比左子樹所有值都大、比右子樹所有值都小。符合的只有兩個候選：

  • Inorder Predecessor（中序前驅）：左子樹中最大的節點，從左子節點出發一路往右走到底。
  • Inorder Successor（中序後繼）：右子樹中最小的節點，從右子節點出發一路往左走到底。

把候選者的值複製到要刪的節點上，再去它原本所在的子樹把候選者刪掉。關鍵觀察：左子樹最大的節點一定沒有右子節點（不然右邊還有更大的），所以刪它時只會是 Case 1 或 Case 2，不會無限遞迴下去。右子樹最小的節點同理，一定沒有左子節點。

用前驅或後繼都正確，但刪完的樹形狀不同。考試題目通常會指定用哪一種，沒有指定時，要在答案中寫清楚自己用的是哪一種。本頁的動畫預設用左子樹最大，可以切換成右子樹最小來比較。

動手操作

上面講的搜尋、插入、刪除都可以在這裡自己試，右側程式碼會跟著操作切換、並亮起正在執行的那一行。建議依序刪除 20（葉節點）、60（一個子節點）、30（兩個子節點），比較三種情況；也可以按「中序走訪」驗證結果是不是排序好的。

中序走訪一定是排序好的

Inorder Traversal（中序走訪）的順序是「左子樹 → 自己 → 右子樹」。對 BST 來說，左子樹的值都比自己小、右子樹的值都比自己大，所以先輸出整棵左子樹、再輸出自己、最後輸出整棵右子樹，得到的序列自然是遞增的。對每棵子樹套用同樣的理由（數學歸納法），就能證明整棵樹的中序結果一定是排序好的。

這個性質很好用：

  • 判斷一棵二元樹是不是 BST：做一次中序走訪，看結果是否嚴格遞增。這比逐一檢查「整棵子樹」簡單很多。
  • Tree Sort：把 n 個數依序插入 BST，再做中序走訪，就完成排序。平均 O(n log n)，最差（輸入已排序）O(n²)。
  • 由 preorder 重建 BST：BST 的中序就是排序後的結果，所以「preorder + 排序」等於「preorder + inorder」，可以唯一決定一棵樹。

樹高決定一切

BST 的搜尋、插入、刪除全都是 O(h)，所以效能完全取決於樹高 h：

  • 最好：樹很平衡，n 個節點的高度約為 ⌊log₂n⌋ + 1 層。例如 n = 1,000,000 時只有 20 層，最多比較 20 次。
  • 最差：退化成一條鏈，h = n。同樣 100 萬筆資料，最多要比較 100 萬次，和線性搜尋一樣慢。
  • 平均：如果資料以隨機順序插入，節點的平均深度約為 2 ln n ≈ 1.39 log₂n，仍然是 O(log n)，只比完全平衡多約 39%。

問題在於實務上資料常常是有順序的，最差情況並不罕見。所以後面會學到 AVL Tree、Red-Black Tree（紅黑樹）這類自我平衡的 BST：在插入和刪除時做旋轉調整，保證樹高一直維持在 O(log n)。

操作與複雜度整理

操作 Operation做法平均最差（退化成鏈）

刪除的三種情況

情況 Case處理方式
Case 1：葉節點 leaf直接移除，父節點對應的指標設為 NULL
Case 2：一個子節點讓唯一的子節點接到被刪節點的位置
Case 3：兩個子節點用左子樹最大（前驅）或右子樹最小（後繼）的值取代，再刪掉那個節點。子樹的最大、最小值所在的節點最多只有一個子節點，所以會變成 Case 1 或 2

程式碼

typedef struct Node {
  int key;
  struct Node *left, *right;
} Node;

Node* search(Node* root, int x) {
  while (root != NULL && root->key != x)
    root = (x < root->key) ? root->left : root->right;
  return root;                       /* NULL 表示找不到 */
}

Node* insert(Node* root, int x) {
  if (root == NULL) return newNode(x);
  if (x < root->key)      root->left  = insert(root->left, x);
  else if (x > root->key) root->right = insert(root->right, x);
  return root;                       /* 重複的 key 不插入 */
}

Node* delete(Node* root, int x) {
  if (root == NULL) return NULL;
  if (x < root->key)      root->left  = delete(root->left, x);
  else if (x > root->key) root->right = delete(root->right, x);
  else {
    if (root->left == NULL)  { Node* r = root->right; free(root); return r; }
    if (root->right == NULL) { Node* l = root->left;  free(root); return l; }
    Node* s = root->left;            /* 中序前驅：左子樹最大 */
    while (s->right) s = s->right;
    root->key = s->key;
    root->left = delete(root->left, s->key);
    /* 改用右子樹最小：s = root->right; 一路往左；最後刪 root->right */
  }
  return root;
}

考研重點

追蹤給一串插入順序，畫出 BST，再依序刪除某些節點，畫出每一步的樹。

解題方向：插入就是一路比較往下走。刪除前先確認題目要用後繼還是前驅，答案會不同；題目沒說時要註明你用哪一種。

計算n 個不同的 key 可以組成幾種不同形狀的 BST？

解題方向：答案是 Catalan number C(n) = (2n)! / ((n+1)! n!)：n=3 有 5 種、n=4 有 14 種。和 Stack 合法輸出序列的個數是同一個數列。

實作給 BST 的 preorder（或 postorder）序列，重建這棵樹。

解題方向：BST 的 inorder 就是 key 排序後的結果，所以「preorder + 排序」等於「preorder + inorder」，可以唯一重建。也可以直接把 preorder 依序 insert 進空樹。

比較BST 的最差情況是什麼？要怎麼避免？

解題方向：輸入已經排序時樹會變成一條鏈，h = n，所有操作退化成 O(n)。用自平衡樹（AVL Tree、Red-Black Tree）把高度維持在 O(log n)。

易錯點

  • ❌ 只要每個節點「左子 < 自己 < 右子」就是 BST → ✅ 必須是左「整棵子樹」都比較小。例如 10 的左子 5 底下若有右子 15，就不是 BST
  • ❌ BST 的操作都是 O(log n) → ✅ 是 O(h)。沒有平衡機制時，最差是 O(n)
  • ❌ 左子樹最大的節點一定是葉節點 → ✅ 它沒有右子節點，但可能有左子節點，刪掉後要把左子節點接上去（右子樹最小則可能有右子節點）
  • ❌ 刪除兩個子節點的節點只有一種正確答案 → ✅ 用後繼或前驅都正確，但結果的樹不同，要照題目指定的方式

自我測驗

依序插入 50, 30, 70, 20, 40, 60, 80，樹高（以層數計）是多少？

3 層。50 是 root，30、70 在第 2 層，20、40、60、80 在第 3 層，是一棵完全平衡的樹。

依序插入 10, 20, 30, 40, 50，搜尋 50 要比較幾次？

5 次。排序好的輸入讓樹退化成往右延伸的一條鏈，搜尋就變成線性搜尋。

上面動畫的初始樹刪除 50，用「左子樹最大」，新的 root 是誰？改用右子樹最小呢？

用左子樹最大：40。50 的左子樹中最大的是 40，用它取代 root；40 原本有左子節點 35，刪掉 40 後 35 接到 30 的右邊。改用右子樹最小：60，它的右子節點 65 接到 70 的左邊。兩個答案都對，但樹的形狀不同，所以考試要照題目指定的方式。

3 個不同的 key 可以組成幾種不同的 BST？

5 種，C(3) = 6! / (4!·3!) = 5。

只看一棵二元樹的 inorder 結果，怎麼判斷它是不是 BST？

檢查 inorder 是否嚴格遞增。是就是 BST，否則就不是。這是最簡單也最不容易出錯的判斷方法。
