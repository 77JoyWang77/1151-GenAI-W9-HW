Heap 堆積只要隨時知道誰最大，不必整個排好序

Ch5 Trees 難度 priority queue max heap insert delete-max

為什麼需要 Heap：優先佇列

一般的 Queue 是先來先處理，但很多時候我們要的是「最重要的先處理」：急診室先看病情最重的病人、作業系統先執行優先權最高的行程、Dijkstra 演算法每次先處理距離最短的點。這種資料結構叫做 Priority Queue（優先佇列），需要兩個操作：加入一個元素（insert），以及取出優先權最高的元素（delete-max）。

用已經學過的結構來做，都會有一個操作很慢：

實作方式insertdelete-max問題
沒排序的陣列O(1)O(n)每次取最大都要掃過全部
排序好的陣列O(n)O(1)每次插入都要搬動元素
BSTO(h)O(h)沒有平衡時 h 可能是 n
HeapO(log n)O(log n)兩個操作都快，而且一定是 log n

Heap（堆積）的關鍵想法是：既然只需要隨時知道「最大的是誰」，就不必把全部資料排好序，只要維持一個比較弱、但比較容易維護的順序就夠了。當 n = 1,000,000 時，log₂n 約為 20，代表每次 insert 或 delete-max 最多只要往上或往下調整約 20 層，而不是動到一百萬個元素。

定義：完全二元樹 + 父節點比子節點大

一棵 Max Heap（最大堆積）要同時滿足兩個條件：

形狀：是一棵 Complete Binary Tree（完全二元樹），除了最後一層，每層都填滿，最後一層的節點全部靠左。
順序：每個節點的值都 ≥ 它的子節點（所以根一定是最大值）。

把「≥」改成「≤」就是 Min Heap（最小堆積），根是最小值，操作完全對稱。本頁以 max heap 為例。

注意 heap 的順序條件只規定「上下」，不規定左右：兄弟節點之間誰大都可以，左子樹的值也可能比右子樹大。所以 heap 不是排序好的結構，對它做中序走訪不會得到排序結果；它只保證「從根往下的每條路徑都是遞減的」。這是 heap 和 BST 最大的差別，也是最常被拿來出選擇題的地方。

用陣列存放：不需要指標

完全二元樹的節點是一層一層、由左到右「擠在一起」的，中間沒有空洞，所以可以直接依層序編號放進陣列，用索引算出父子關係，完全不需要 left、right 指標。習慣上從 heap[1] 開始放（heap[0] 不用），公式最乾淨：

父節點 = i / 2（整數除法）　　左子 = 2i　　右子 = 2i + 1　　i 是葉子 ⇔ 2i > n

如果陣列從 0 開始，公式要改成：父節點 (i − 1) / 2、左子 2i + 1、右子 2i + 2。考試兩種都會出現，一定要先看清楚題目從哪裡開始編號。

因為是完全二元樹，n 個節點的高度一定是 ⌊log₂n⌋ + 1 層，不會像 BST 那樣退化成鏈。這就是 heap 能保證 O(log n) 的原因：所有操作都只沿著一條從根到葉（或從葉到根）的路徑走。

insert：放在最後，往上浮

插入新元素時，先顧好形狀：把它放在陣列的下一格（heap[n + 1]），也就是最下層最左邊的空位，樹仍然是完全二元樹。接著修正順序：新元素可能比父節點大，就和父節點交換，一路往上比較，直到它不比父節點大、或已經到了根為止。這個過程叫 Bubble Up（上浮，也叫 sift-up）。

為什麼交換後其他地方不會壞掉？交換時，原本的父節點 p 往下移到新元素的位置，而 p 本來就比它原本的所有子孫都大，所以 p 移下來後仍然比新的子節點大；往上移的新元素又比 p 大，自然也比 p 的另一個子節點大。所以每次交換只會讓問題往上移一層，不會在別處產生新的錯誤。

例子：依序 insert 30、50、20、70、60、10、80

insert過程陣列 heap[1..n]
30空 heap，直接當根30
50放在 [2]，50 > 30，交換50 30
20放在 [3]，20 < 50，停50 30 20
70放在 [4]，70 > 30 交換到 [2]，70 > 50 再交換到 [1]70 50 20 30
60放在 [5]，60 > 50 交換到 [2]，60 < 70 停70 60 20 30 50
10放在 [6]，10 < 20，停70 60 20 30 50 10
80放在 [7]，80 > 20 交換到 [3]，80 > 70 交換到 [1]80 60 70 30 50 10 20

每個新元素最多往上換 ⌊log₂n⌋ 次（樹高減一），所以 insert 是 O(log n)。上面 7 次插入總共交換了 6 次。

看程式碼：insert()：往上浮
insert()：往上浮
#define MAX 100
int heap[MAX + 1];                             /* 用 heap[1..n]，heap[0] 不用 */
int n = 0;

void swap(int *a, int *b) { int t = *a; *a = *b; *b = t; }

void insert(int x) {
  if (n == MAX) { printf("Heap Full\n"); exit(1); }
  int i = ++n;                                 /* 先放在最後一個位置 */
  heap[i] = x;
  while (i > 1 && heap[i] > heap[i / 2]) {     /* 比父節點大就往上換 */
    swap(&heap[i], &heap[i / 2]);
    i /= 2;
  }
}

delete-max：最後一個補到根，往下沉

最大值一定在根，取走它很容易，難的是補洞。如果直接把較大的子節點往上提，最後空出來的位置可能在最下層的中間，形狀就不再是完全二元樹。正確做法同樣是先顧形狀、再修順序：

  1. 記下根 heap[1]（要回傳的最大值）。
  2. 把最後一個元素 heap[n] 搬到根，n 減 1。最後一格消失，形狀仍是完全二元樹。
  3. 新的根通常很小，要往下沉：和兩個子節點中較大的那個比較，比它小就交換，一路往下，直到比兩個子節點都大或已經是葉子。這叫 Sift Down（下沉，也叫 heapify）。

為什麼一定要挑較大的子節點交換？因為換上來的節點會成為另一個子節點的父親，只有挑較大的，它才會 ≥ 另一個子節點。如果挑錯成較小的那個，換上去後馬上就違反 heap 性質。

以上一節的結果 80 60 70 30 50 10 20 為例：取走 80，把最後的 20 搬到根；20 的子節點是 60、70，較大的是 70，交換；20 到了 [3]，唯一的子節點是 10，20 ≥ 10，停。結果是 70 60 20 30 50 10。往下沉每層要比較 2 次（先比兩個子節點，再和較大的比），最多沉 ⌊log₂n⌋ 層，所以 delete-max 也是 O(log n)。

看程式碼：deleteMax() 與 siftDown()
deleteMax() 與 siftDown()
void siftDown(int a[], int i, int size) {
  while (2 * i <= size) {                      /* 還有子節點就繼續 */
    int c = 2 * i;                             /* 先假設左子比較大 */
    if (c + 1 <= size && a[c + 1] > a[c]) c++; /* 右子更大就改選右子 */
    if (a[i] >= a[c]) break;                   /* 比兩個子節點都大，停 */
    swap(&a[i], &a[c]);
    i = c;
  }
}

int deleteMax(void) {
  if (n == 0) { printf("Heap Empty\n"); exit(1); }
  int top = heap[1];
  heap[1] = heap[n--];                         /* 最後一個移到根 */
  siftDown(heap, 1, n);
  return top;
}

動手操作

上方是樹、下方是陣列，兩者是同一份資料：交換時節點在樹上和陣列裡會一起移動，可以對照索引公式。輸入一個數字按 insert；按 delete-max 取出最大值；輸入一串數字（例如按「範例數列」）再按 build heap，可以看下一節的由下往上建堆。

建立 heap：由下往上只要 O(n)

手上已經有 n 個數字，要把它們變成一個 heap，有兩種做法：

  • 由上往下（逐一 insert）：從空 heap 開始，一個一個 insert。每次最多 O(log n)，總共 O(n log n)。
  • 由下往上（bottom-up）：先把 n 個數照原順序放進陣列（形狀已經是完全二元樹），再從最後一個內部節點 ⌊n / 2⌋ 開始往前，對每個節點做 siftDown。輪到節點 i 時，它的兩棵子樹都已經是 heap，只要把 i 沉到正確位置，以 i 為根的子樹就變成 heap。做到根就完成。

由下往上為什麼只要 O(n)？關鍵是「大部分的節點都在底層，而底層節點沉不了幾層」。以 n = 15 的完全二元樹為例（圖 3）：8 個葉節點不用動，4 個節點最多沉 1 層，2 個最多沉 2 層，只有根最多沉 3 層，總交換次數最多 4·1 + 2·2 + 1·3 = 11 次，比 n 還少。一般化：高度為 h 的節點約有 n / 2ʰ⁺¹ 個，每個最多沉 h 層：

總成本 ≤ Σ (n / 2ʰ⁺¹) · h = (n / 2) · Σ h / 2ʰ ≤ (n / 2) · 2 = n　→　O(n)

要特別注意：兩種做法得到的 heap 不一定相同，都是合法的 heap 但陣列內容可能不同。例如 15 25 10 40 35 50 20，由下往上得到 50 40 20 25 35 10 15（交換 4 次），逐一 insert 得到 50 35 40 15 25 10 20（交換 6 次）。考題問「建出來的 heap」時，要看清楚指定哪一種方法。

看程式碼：buildHeap()：由下往上
buildHeap()：由下往上
void buildHeap(int a[], int size) {
  for (int i = size / 2; i >= 1; i--)          /* 從最後一個內部節點往前 */
    siftDown(a, i, size);
}

應用與比較

  • Priority Queue：作業系統的行程排程、事件模擬、網路封包排隊，幾乎都用 heap 實作。
  • Heap Sort：先 build heap（O(n)），再做 n 次 delete-max，每次把取出的最大值放到陣列尾端，總共 O(n log n)，而且只需要 O(1) 額外空間。
  • Top-k 問題：要從大量資料中找出最大的 k 個，用一個大小 k 的 min heap，每來一個數就和堆頂比較，總共 O(n log k)。
  • 圖的演算法：Dijkstra 最短路徑、Prim 最小生成樹每次都要取出「目前最小」的候選，用 min heap 可以加速。

和 BST 比較：heap 只能快速找到最大（或最小）的一個，要搜尋任意值只能整個掃過，O(n)；BST 可以搜尋任意值、也能依序輸出，但沒有平衡時可能退化。所以只需要「反覆取最值」時用 heap，需要「查詢任意值或依序列出」時用（平衡的）BST。

考研重點：題型地圖

題型常見度解題步驟例題
判斷是否為 heap很常考檢查每個 i ≥ 2：heap[i] ≤ heap[i / 2]；還要確認沒有空洞例題
依序 insert 畫出結果很常考每次放在最後一格，和父節點比，大就換，畫表格逐步記錄陣列例題
delete-max 追蹤很常考最後一個補到根，每層和「較大的子節點」比較例題
build heap 兩種方法比較常考由下往上從 ⌊n / 2⌋ 開始 siftDown；兩種方法結果可能不同例題
索引公式常考先確認從 0 還是 1 開始編號例題
第 k 大可能的位置偶爾第 k 大的祖先一定都比它大，所以深度 ≤ k − 1例題
複雜度證明偶爾build heap：Σ h · n / 2ʰ⁺¹ = O(n)例題

易錯點

  • heap 是排序好的，中序走訪會遞增 → heap 只規定父 ≥ 子，兄弟、左右子樹之間沒有順序 例題
  • delete-max 後把較大的子節點直接提上來補洞 → 這樣會破壞完全二元樹的形狀；要把最後一個元素搬到根再往下沉 例題
  • 往下沉時和左子節點比就好 → 要和兩個子節點中「較大」的交換，否則換上來的節點比另一個子節點小 例題
  • 逐一 insert 和由下往上建出來的 heap 一樣 → 兩者都是合法 heap，但內容常常不同；而且一個 O(n log n)、一個 O(n) 例題
  • 左子一律是 2i → 從 1 開始才是 2i；從 0 開始是 2i + 1，父節點是 (i − 1) / 2 例題
