Circular Queue 環狀佇列把陣列頭尾接起來，空位就能一直重複使用

Ch3 Stacks and Queues 難度 FIFO front / rear modulo

為什麼需要環狀佇列

Queue（佇列）就像排隊買飲料：先來的人先買到、新來的人排在最後面，叫做 FIFO（First In, First Out，先進先出）。它只有兩個主要操作：enqueue（加入佇列）把資料放到隊尾，dequeue（移出佇列）從隊頭拿出最早進來的資料。我們用兩個索引記錄隊伍的兩端：front 管出口、rear 管入口。

和 Stack 只動同一端不一樣，Queue 的兩端都會動：enqueue 讓 rear 往後走，dequeue 讓 front 也往後走。用一般陣列實作時，問題就出現了：兩個索引都只會往後、不會回頭，整條隊伍會慢慢往陣列尾巴「漂移」。

圖 1 是一個大小 8 的陣列，已經放進 8 個元素、又取出了 4 個。前面 4 格明明空著，但 rear 已經到最後一格，程式判斷 rear == MAX - 1 就說「滿了」，再也放不進去。這種「還有空間卻放不下」的情況叫做假性溢位（false overflow）。

最直覺的補救是每次 dequeue 後把所有元素往前搬一格，但這樣 dequeue 會從 O(1) 變成 O(n)，每取一個都要搬一整排，非常浪費。Circular Queue（環狀佇列）的想法是：不要搬資料，讓索引繞回來。rear 走到最後一格後，下一格就是 [0]，前面空出來的位置可以一直重複使用。

看程式碼：線性佇列（對照用）
線性佇列（對照用）
#define LMAX 8
int lq[LMAX];
int lfront = -1, lrear = -1;                   /* front 指向第一個元素的前一格 */

void lenqueue(int x) {
  if (lrear == LMAX - 1) { printf("Queue Full\n"); exit(1); }   /* 前面有空位也算滿 */
  lq[++lrear] = x;
}

int ldequeue(void) {
  if (lfront == lrear) { printf("Queue Empty\n"); exit(1); }
  return lq[++lfront];
}

用取餘數把陣列接成一個環

電腦的記憶體並沒有「環」，環狀佇列底層仍然是一般的陣列，只是我們規定：最後一格的下一格是第 0 格。實作上只要在索引加 1 之後取餘數：

下一格 = (i + 1) % MAX        例：MAX = 8 時，(7 + 1) % 8 = 0，從最後一格繞回開頭

i 從 0 到 MAX − 2 時，加 1 不會超過 MAX − 1，取餘數不影響結果；只有 i = MAX − 1 時，(MAX − 1 + 1) % MAX = 0，剛好繞回開頭。所以這一行公式同時處理了「一般往後走」和「到底繞回」兩種情況，不需要寫 if。

從圖 2 可以看到，環狀佇列裡 rear 的索引可能比 front 還小（rear = 1、front = 5），這是正常現象，代表佇列已經繞過陣列尾端。計算元素個數時也要考慮這點：直接算 rear − front 會得到負數，要先加 MAX 再取餘數。

元素個數 = (rear − front + MAX) % MAX      例：front = 5、rear = 1，(1 − 5 + 8) % 8 = 4 個

環狀佇列裡所有「往前一格」都寫成 (i + 1) % MAX，所有「兩個索引相減」都寫成 (a − b + MAX) % MAX，先加 MAX 才不會出現負數。

空與滿：front == rear 的兩難

先約定 front 和 rear 的意義。最常見的做法是：

  • rear：指向最後一個元素。
  • front：指向第一個元素的前一格。一開始 front = rear = 0，代表空的。

這樣 enqueue 時 rear 先前進一格再放；dequeue 時 front 先前進一格，就剛好指到第一個元素，把它取出來。問題在判斷空和滿：

  • 佇列空的時候，front 和 rear 指在同一格（圖 3 (a)）。
  • 如果把 8 格全部放滿，rear 會一路繞一圈，又追上 front，同樣是 front == rear（圖 3 (b)）。

只看 front 和 rear 兩個數字，空和滿長得一模一樣，程式分不出來。這不是寫法不夠聰明，而是資訊量真的不夠：front 和 rear 只有 MAX × MAX 種組合，但佇列可以有 0、1、……、MAX 共 MAX + 1 種個數，對同一個 front 來說，rear 只有 MAX 種值，卻要表示 MAX + 1 種狀態，一定有兩種狀態撞在一起（鴿籠原理）。

解法一：犧牲一格（最常考）

規定 front 指的那一格永遠不放資料。當 rear 再往前一格就會撞到 front 時，就宣告已滿。於是：

空：front == rear
滿：(rear + 1) % MAX == front      容量 = MAX − 1

代價是浪費一格空間，MAX = 8 時只能放 7 個。好處是程式最簡單，只靠 front、rear 兩個變數就能判斷，所以考試沒有特別說明時，通常就是這種做法。

解法二：多記一個變數

另一種想法是補足缺少的資訊：多記一個 count（目前個數），或一個 tag 旗標記錄「最後一次操作是 enqueue 還是 dequeue」。front == rear 時，如果最後一次是 enqueue 就是滿、是 dequeue 就是空。這樣 MAX 格全部用得到，但每次操作都要多更新一個變數。後面「其他做法」一節會詳細比較。

enqueue 與 dequeue 怎麼做

以下都採用「犧牲一格」的做法，兩個操作都是先檢查、再移動索引、最後存取資料：

  1. enqueue(x)：檢查 (rear + 1) % MAX == front，成立就是滿了；否則 rear = (rear + 1) % MAX，再把 x 放進 queue[rear]。
  2. dequeue()：檢查 front == rear，成立就是空的；否則 front = (front + 1) % MAX，回傳 queue[front]。

注意 dequeue 並不需要把資料「清掉」，front 往前走之後，那一格就變成新的犧牲格，裡面的舊資料之後會被覆蓋。兩個操作都只做固定幾個步驟，與佇列裡有多少元素無關，所以都是 O(1)。

完整走一遍（MAX = 6）

從空佇列 front = rear = 0 開始，依序執行下列操作。注意第 8 步 rear 從 5 繞回 0：

第 9 步之後再 enqueue 就會失敗，雖然陣列在 front = 2 的位置還有一格，但那是犧牲格。用個數公式驗算：(1 − 2 + 6) % 6 = 5，和表格一致。

看程式碼：enqueue / dequeue（犧牲一格）
enqueue / dequeue（犧牲一格）
#define MAX 8                                  /* 陣列大小；最多只能放 MAX - 1 個 */
int queue[MAX];
int front = 0, rear = 0;                       /* front 指向第一個元素的前一格 */

int isEmpty(void) { return front == rear; }
int isFull(void)  { return (rear + 1) % MAX == front; }

void enqueue(int x) {
  if (isFull()) { printf("Queue Full\n"); exit(1); }
  rear = (rear + 1) % MAX;                     /* rear 先往前一格 */
  queue[rear] = x;
}

int dequeue(void) {
  if (isEmpty()) { printf("Queue Empty\n"); exit(1); }
  front = (front + 1) % MAX;                   /* front 先往前一格 */
  return queue[front];
}

int size(void) { return (rear - front + MAX) % MAX; }

下面的動畫把 MAX = 8 的陣列畫成一個環，灰色那一格就是 front 指的犧牲格。可以自己輸入數值 enqueue、dequeue，按「放到滿」觀察第幾個會滿；也可以切換成「多記 count」的做法比較。

其他做法：count 與 tag

如果不想浪費那一格，就要多記一些資訊。最清楚的做法是用 head 直接指向第一個元素，再用 count 記錄目前有幾個：

  • 空：count == 0；滿：count == MAX，MAX 格全部用得到。
  • 新元素放在最後一個元素的下一格：(head + count) % MAX，所以連 rear 都不用記。
  • dequeue 先取 cq[head]，再讓 head = (head + 1) % MAX，count 減 1。
看程式碼：enqueue / dequeue（多記 count）
enqueueCount / dequeueCount（多記 count）
int cq[MAX];
int head = 0, count = 0;                       /* head：第一個元素；count：目前個數 */

void enqueueCount(int x) {
  if (count == MAX) { printf("Queue Full\n"); exit(1); }
  cq[(head + count) % MAX] = x;                /* 最後一個元素的下一格 */
  count++;
}

int dequeueCount(void) {
  if (count == 0) { printf("Queue Empty\n"); exit(1); }
  int x = cq[head];
  head = (head + 1) % MAX;
  count--;
  return x;
}

tag 做法則保留 front、rear 原本的意義，另外用一個布林值記錄最後一次操作：enqueue 後設 tag = 1、dequeue 後設 tag = 0。front == rear 時，tag = 1 代表剛放滿、tag = 0 代表剛取空。它也能用滿 MAX 格，但多了一次判斷與賦值。

做法額外變數容量空的條件滿的條件

tagtag（1 bit）MAXfront == rear && tag == 0front == rear && tag == 1

三種做法的操作都是 O(1)，差別只在「省一格空間」和「多維護一個變數」之間的取捨。考題常問「如果不想浪費空間要怎麼改」，答案就是 count 或 tag。另外要特別小心：不同題目對 front、rear 的定義可能不同（例如 front 指向第一個元素、rear 指向最後一個元素的下一格），作答前一定要先看清楚題目的定義，公式要跟著調整。

效能與應用

環狀佇列的 enqueue、dequeue、判斷空滿、計算個數全部是 O(1)，空間固定是 MAX 格，不需要動態配置記憶體，也不會有假性溢位。缺點是容量在一開始就固定，放滿了就不能再放；如果事先不知道最多會有多少資料，可以改用鏈結串列實作的佇列，代價是每個節點多一個指標、而且每次都要 malloc。

它的應用幾乎都和「先來先處理、空間固定」有關：

  • CPU 排程：Round-Robin 排程把等待的行程排成一個環，輪流分配時間片段。
  • 緩衝區：鍵盤輸入、網路封包、音訊串流常用 Ring Buffer（環狀緩衝區），生產者從 rear 寫、消費者從 front 讀，兩邊速度不同也能順利交接。
  • 圖的 BFS：廣度優先搜尋用佇列記錄「下一批要拜訪的點」，節點數量已知時常直接用環狀佇列。

易錯點

  • 元素個數 = rear − front → rear 可能比 front 小（已經繞回），要寫 (rear − front + MAX) % MAX 例題
  • 大小 MAX 的環狀佇列可以放 MAX 個 → 犧牲一格的做法只能放 MAX − 1 個；要放滿 MAX 個得多記 count 或 tag 例題
  • front == rear 就代表空 → 不犧牲一格時，全滿也是 front == rear，兩種狀態分不出來 例題
  • rear 到了 MAX − 1 就不能再放 → 那是線性佇列；環狀佇列會用 (rear + 1) % MAX 繞回 [0] 例題
  • 公式背一套就好 → front 指「第一個元素」或「前一格」、rear 指「最後一個」或「下一個空位」，公式都不同，先看題目定義 例題
