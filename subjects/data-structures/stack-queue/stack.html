Stack（堆疊）最後放進去的，最先拿出來

Ch3 Stacks and Queues 難度 ★★☆ LIFO infix postfix

什麼是 Stack

想像餐廳裡疊在一起的盤子：洗好的盤子一個一個疊上去，要用的時候也只能從最上面拿。你不會、也拿不到壓在最底下的那一個。Stack（堆疊）就是把這個規則搬到資料上的結構：資料只能從同一端放進去、從同一端拿出來，那一端叫做 top（頂端），另一端叫做 bottom（底端）。

因為只能從頂端進出，所以「最後放進去的，一定最先被拿出來」。這個性質叫做 LIFO（Last In, First Out，後進先出）。反過來說，最早放進去的元素會一直被壓在下面，要等上面的全部拿走才輪得到它。

為什麼需要這種「限制很多」的結構？因為很多問題天生就是後進先出的：函式 A 呼叫 B、B 再呼叫 C，一定是 C 先結束、再回到 B、最後回到 A；寫程式時最後打開的括號，一定要最先被關掉；編輯器按「復原」時，最後做的動作最先被撤銷。把資料放進 Stack，程式自然就會照這個順序處理，不需要額外記錄「現在該處理誰」。

💡 只要題目出現「反轉順序」「配對」「回到上一步」，例如括號配對、函式呼叫、遞迴、undo，第一個想到的就是 Stack。

Stack 的基本操作（ADT）

描述一個資料結構時，我們先不管它用什麼實作，只定義「它能做哪些事、每件事的效果是什麼」，這叫做 Abstract Data Type（ADT，抽象資料型態）。Stack 的 ADT 很精簡：

  • push(x)（推入）：把 x 放到最上面，x 成為新的 top。
  • pop()（彈出）：把最上面的元素拿走並回傳，原本第二個元素變成新的 top。
  • peek() / top()（查看頂端）：回傳最上面的元素，但不拿走，Stack 內容不變。
  • isEmpty()：是否為空。對空的 Stack 做 pop 或 peek 是錯誤，稱為 Stack Underflow（堆疊下溢）。
  • isFull()：是否已滿。只有用固定大小的陣列實作時才有意義，滿了還 push 稱為 Stack Overflow（堆疊溢位）。

注意這些操作全部只碰 top，完全不需要走訪其他元素。所以不管 Stack 裡有 10 個還是 100 萬個元素，每個操作都是 O(1)。這是 Stack 好用的根本原因。

用陣列實作

最常見的實作是一個大小為 MAX 的陣列，加上一個整數 top 記錄「最上面那個元素的索引」。陣列的第 0 格是 bottom，往索引大的方向長高。

  1. 初始化：top = -1。−1 表示「連第 0 格都還沒有東西」，也就是空堆疊。
  2. push(x)：先檢查 top == MAX - 1（最後一格已經用掉了）就是滿的；沒滿就先把 top 加 1，再把 x 放進 stack[top]。合在一起寫成 stack[++top] = x，++ 寫在前面表示「先加再用」。
  3. pop()：先檢查 top == -1 就是空的；不空就回傳 stack[top]，再把 top 減 1，寫成 return stack[top--]，-- 寫在後面表示「先用再減」。

pop 之後，陣列裡那一格的值其實還在，只是 top 已經往下移，它就被視為「不存在」，下次 push 會直接覆蓋過去。所以 pop 不需要真的去清除資料。

陣列實作的缺點是大小固定：開太小會溢位，開太大會浪費空間。下面的動畫可以自己 push、pop，觀察 top 怎麼移動，也可以故意塞滿或清空，看看 overflow、underflow 怎麼發生。

用鏈結串列實作

如果事先不知道要放多少資料，可以改用 Linked List（鏈結串列）：每個節點存一筆資料和一個指向「下一個（也就是下面那個）節點」的指標，top 指標永遠指向最上面的節點。

  • push(x)：配置一個新節點，讓它的 next 指向目前的 top，再把 top 改成指向新節點。
  • pop()：記下 top 節點的資料，把 top 移到 top->next，再釋放原本的節點。
  • 空堆疊：top == NULL。只要記憶體還夠就能一直 push，不會有「陣列滿了」的問題。

Stack 的應用

① 括號配對

檢查 { [ ( ) ] } 這類括號是否正確配對：由左往右掃，遇到左括號就 push；遇到右括號就 pop 一個出來，看看是不是同一種。如果種類不同、或想 pop 時 Stack 已經空了，就是錯誤；掃完之後 Stack 還有剩，也是錯誤（有左括號沒被關掉）。例如 ( [ ) ]：讀到 ) 時 pop 出來的是 [，種類不符，所以不合法。Stack 能做這件事，正是因為「最後打開的括號要最先關」是 LIFO。

② 函式呼叫與遞迴

程式執行時，系統用一個 call stack（呼叫堆疊）記錄每一層函式的區域變數和返回位置。每呼叫一次函式就 push 一層，函式結束就 pop 掉那一層、回到下面那層繼續執行。遞迴太深導致的「stack overflow」錯誤，指的就是這個 call stack 被塞爆。也因為如此，任何遞迴都能改寫成「自己用一個 Stack 模擬」的迴圈版本。

③ 其他常見應用

  • 運算式轉換與求值：中序轉後序、後序求值（下面兩節詳細說明）。
  • Depth-First Search（深度優先搜尋）：走到底再回頭，回頭的順序就是 LIFO。
  • Undo（復原）、瀏覽器的上一頁：最近的動作最先被撤銷。
  • 迷宮問題、回溯法（backtracking）：走錯路時退回上一個岔路口。

合法的輸出序列

考研很愛考這一題：把 1, 2, …, n 依序 push 進 Stack，過程中可以在任何時候 pop，問「哪些輸出順序是可能的」。關鍵在於：一旦某個數被 pop 出來，所有比它小、但還留在 Stack 裡的數，一定是由大到小排在裡面，之後也只能由大到小地被 pop。

以 n = 3 為例，6 種排列中只有 5 種做得到：

  • 1 2 3：每 push 一個就馬上 pop。
  • 1 3 2：push 1、pop；push 2、push 3、pop、pop。
  • 2 1 3：push 1、push 2、pop、pop；push 3、pop。
  • 2 3 1：push 1、push 2、pop；push 3、pop；pop。
  • 3 2 1：全部 push 完再全部 pop。
  • 3 1 2 ✗：要先輸出 3，表示 1、2 都已經在 Stack 裡，而且 2 壓在 1 上面。下一個只能 pop 出 2，不可能先輸出 1。

一般化的判斷法：輸出序列中只要出現「某個大數 k 先出來，後面跟著兩個比它小的 i、j，且 i < j、i 又排在 j 前面」（也就是 …k…i…j… 且 i < j < k），這個序列就不可能。所有合法序列的數量是 Catalan number（卡塔蘭數）：

C(n) = (2n)! / ((n+1)! · n!)      C(1)=1, C(2)=2, C(3)=5, C(4)=14, C(5)=42

也就是 n = 4 時，24 種排列裡只有 14 種是 Stack 做得出來的，超過四成的排列都不可能。Catalan number 之後在「n 個節點能組成幾種二元樹」也會再出現。

運算式轉換：中序轉後序

我們平常寫的 a + b * c 叫做 infix（中序式）：運算子夾在兩個運算元中間。中序式對人很直覺，但電腦處理起來很麻煩：必須知道 * 比 + 優先，遇到括號還要特別處理。

如果把運算子放到兩個運算元後面，就變成 postfix（後序式，又稱逆波蘭表示法）：a b c * +。後序式有兩個大優點：不需要括號，而且不需要考慮優先權，從左到右掃一遍、用一個 Stack 就能算出結果。所以編譯器常先把中序式轉成後序式，再拿去求值。

轉換的想法

從左到右讀中序式：運算元出現的順序在中序和後序裡完全一樣，所以讀到就直接輸出；運算子則要「等一下」，因為它後面可能還有優先權更高、應該先算的運算子。等待中的運算子就放在 Stack 裡。

讀到一個新的運算子時，要先看 Stack 頂端的運算子：如果頂端那個應該先算（優先權較高，或同級且左結合），就把它 pop 出來輸出，一直重複到不用再 pop 為止，再把新運算子 push 進去。輸入讀完後，把 Stack 剩下的全部 pop 出來。

為什麼要分 isp 和 icp

麻煩的是左括號 (：它剛讀進來時要「無條件 push」（優先權要最高），可是一旦進了 Stack，又要擋住外面的運算子、不能被 pop 掉（優先權要最低）。同一個符號需要兩種優先權，所以給每個符號兩個數字：in-stack precedence（isp，在堆疊裡的優先權）和 incoming precedence（icp，剛讀入時的優先權）。規則只剩一條：只要 isp[top] ≥ icp[token]，就 pop。右括號 ) 則是特例：一路 pop 到遇見 ( 為止，兩個括號都丟掉。

後序式求值

有了後序式，求值就非常單純：從左到右掃，遇到運算元就 push；遇到運算子就 pop 兩個數出來計算，再把結果 push 回去。全部掃完時，Stack 裡唯一剩下的數就是答案。

唯一要小心的是順序：先 pop 出來的是右運算元，後 pop 的才是左運算元。加法、乘法順序錯了沒差，但減法和除法就會算錯。

讀入動作Stack（底 → 頂）
6 2 3依序 push6 2 3
+pop 3、pop 2，算 2 + 3 = 5，push6 5
-pop 5、pop 6，算 6 − 5 = 1，push1
3 8 2依序 push1 3 8 2
/pop 2、pop 8，算 8 / 2 = 4，push1 3 4
+pop 4、pop 3，算 3 + 4 = 7，push1 7
*pop 7、pop 1，算 1 × 7 = 7，push7

程式碼

#define MAX 6
int stack[MAX], top = -1;

void push(int x) {
  if (top == MAX - 1) { overflow(); return; }
  stack[++top] = x;
}

int pop(void) {
  if (top == -1) { underflow(); return -1; }
  return stack[top--];
}

int peek(void) { return stack[top]; }

/* 中序轉後序（isp / icp 寫法） */
void postfix(void) {
  stack[0] = eos; top = 0;           /* 堆疊底放 eos，isp[eos] = 0 */
  for (token = getToken(); token != eos; token = getToken()) {
    if (token == operand) printf("%c", symbol);
    else if (token == rparen) {
      while (stack[top] != lparen) printToken(pop());
      pop();                           /* 丟掉 '(' */
    } else {
      while (isp[stack[top]] >= icp[token]) printToken(pop());
      push(token);
    }
  }
  while ((token = pop()) != eos) printToken(token);
}

/* 後序式求值：遇到運算子時，先 pop 出來的是「右」運算元 */
int evalPostfix(char *tokens[], int n) {
  for (int i = 0; i < n; i++) {
    if (isNumber(tokens[i])) push(atoi(tokens[i]));
    else {
      int b = pop(), a = pop();      /* 注意順序！ */
      push(apply(tokens[i][0], a, b));   /* a op b */
    }
  }
  return pop();
}

考研重點

追蹤把中序式轉成後序（或前序），並寫出每一步的 stack 內容。

解題方向：照 isp / icp 表逐 token 列表（token / stack / output 三欄），每次比較都寫出 isp 和 icp 的數字。也常考「請填出 isp、icp 表並說明為什麼 ( 的 isp 和 icp 不同」。快速驗算法：依優先權加滿括號，再把每個運算子移到它所屬的右括號位置（前序則移到左括號）。

計算給一個後序式求值，例如 6 2 3 + - 3 8 2 / + *。

解題方向：遇到運算子就 pop 兩個數，後 pop 的在左邊。這題：6−(2+3)=1，3+(8/2)=7，1×7=7。

判斷輸入序列 1, 2, …, n 依序 push（中間可任意 pop），哪些輸出序列不可能出現？共有幾種可能？

解題方向：不可能的樣式是「出現 …k…i…j… 且 i < j < k」，例如 1,2,3 無法輸出 3,1,2。合法序列數是 Catalan number（卡塔蘭數） C(n) = (2n)! / ((n+1)! n!)，n=3 時 5 種、n=4 時 14 種。

實作在一個大小為 n 的陣列中放兩個 stack，要求空間不浪費。

解題方向：一個從索引 0 往右長、一個從 n−1 往左長，兩個 top 相鄰（top1 + 1 == top2）時才算滿。

易錯點

  • ❌ 後序求值時 a = pop(), b = pop() 再算 a − b → ✅ 先 pop 的是右運算元 b，要算 a − b，減法與除法順序錯就全錯
  • ❌ ( 只有一個優先權 → ✅ ( 的 icp = 20（讀入時最大，一定 push），isp = 0（在堆疊裡最小，誰都不會把它 pop 掉）。這就是要分成 isp / icp 兩張表的原因
  • ❌ ^ 和 + - 一樣，同優先權就 pop → ✅ ^ 是右結合，同級時不 pop（isp 14 < icp 15），2^3^2 轉成 2 3 2 ^ ^
  • ❌ 前序式 = 把後序式整個反過來 → ✅ 不對。a-b 後序是 a b -，反過來是 - b a，但前序應為 - a b
  • ❌ top 一定從 −1 開始 → ✅ 也有教科書讓 top 指向「下一個空位」、從 0 開始，這時 push 寫成 stack[top++] = x。作答前先看題目的定義

自我測驗

a + b * c - d 的後序式是什麼？

a b c * + d -。讀到 - 時，堆疊中的 * 和 + 優先權都 ≥ -，所以先依序 pop 出來。

(A + B) * (C - D) 的後序式是什麼？

A B + C D - *。可以把它貼到上面的動畫驗證。

1, 2, 3 依序 push（中間可 pop），能不能輸出 3, 1, 2？

不能。要先輸出 3，必須 1、2 都已經在堆疊中，且 2 壓在 1 上面，所以下一個只能 pop 出 2，不可能是 1。

1～4 依序進堆疊，共有幾種合法的輸出順序？

14 種，也就是 Catalan number C(4) = 8! / (5!·4!) = 14。

為什麼遞迴可以改寫成用 Stack 的迴圈？

因為函式呼叫本身就是靠系統的 call stack 保存區域變數與返回位置。自己用 Stack 存同樣的資訊，就能模擬遞迴。
