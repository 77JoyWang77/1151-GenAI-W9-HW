Minimum Cost Spanning Tree 最小成本生成樹邊由小到大挑、從一點往外長，貪婪也能拿到最佳解

Ch6 Graphs 難度 MST Kruskal Prim union-find cut property

為什麼需要最小生成樹

假設學校要用光纖把 7 棟大樓連起來，每兩棟之間能不能拉線、拉一條要花多少錢都估好了。要求很單純：任兩棟大樓之間都要通（可以經過別棟轉接），而且總花費越少越好。把大樓當頂點、可以拉的線當邊、花費當邊的權重，這就是一張 Weighted Graph（加權圖），問題變成：從這張圖挑出一些邊，讓所有頂點連通，而且挑出的邊權重總和最小。

先想想答案長什麼樣子。如果挑出來的邊裡有環，環上隨便拿掉一條邊，所有頂點還是連通（環的另一半路還在），花費卻變少了。所以最省的答案一定沒有環，又要連通所有頂點，那它就是一棵樹。在 BFS & DFS 那一頁已經看過：包含圖上所有頂點、而且只用圖上的邊的樹，叫做 Spanning Tree（生成樹）。BFS、DFS 隨便走一遍就能得到一棵，但那時候邊沒有權重，任何一棵都一樣好；現在邊有成本了，我們要的是成本最低的那一棵，叫做 Minimum Cost Spanning Tree（MST，最小成本生成樹）。

生成樹的數量通常非常多：4 個頂點的完全圖就有 16 棵，n 個頂點的完全圖有 nn−2 棵（Cayley 公式），10 個頂點就是一億棵。一棵一棵列出來比較是不可能的，所以需要聰明的演算法。好消息是 MST 可以用 Greedy Algorithm（貪婪演算法）解：每一步都挑目前看起來最便宜、又不違反規則的邊，最後得到的就是全域最佳解。這一頁要講三種挑法（Kruskal、Prim、Sollin），以及最重要的問題：為什麼這樣貪心不會出錯。

MST 的應用很直接：網路佈線、電路板走線、道路與水管規劃，都是「全部連起來、總長度最短」。它也是很多問題的子程序，例如分群（把 MST 最重的 k − 1 條邊拿掉，剩下 k 群），以及旅行推銷員問題的近似解。

定義與生成樹的基本性質

設 G = (V, E) 是連通、無向的加權圖，n = |V|、e = |E|，每條邊 (u, v) 有權重 w(u, v)。G 的生成樹 T 是一個子圖 (V, T)：T ⊆ E、包含全部 n 個頂點、連通且沒有環。T 的成本是 T 中所有邊的權重和；成本最小的生成樹就是 MST。

生成樹的四個性質（後面的證明全靠它們）

  • 邊數固定是 n − 1。不管哪一棵生成樹、不管是最小還是最大，邊數都一樣；所以「MST 有幾條邊」永遠是 n − 1，範例圖 7 個頂點就是 6 條。
  • 加一條非樹邊，恰好形成一個環。T 上任兩點之間本來就有唯一一條路，再加一條邊 (u, v)，就和 T 上 u 到 v 的那條路圍成一個環，而且只有這一個。
  • 拿掉一條樹邊，樹剛好斷成兩塊。兩塊之間原本只靠這條邊相連。
  • 換邊之後還是生成樹：加入非樹邊 e 形成環，再拿掉環上任何一條其他的邊 f，得到的 T + e − f 仍是生成樹。這個「換邊」動作是所有 MST 證明的基本工具。

容易忽略的細節

  • 圖要連通。不連通的圖沒有生成樹，每個連通元件各自的 MST 合起來叫 Minimum Spanning Forest（最小生成樹林），k 個元件時邊數是 n − k。
  • 權重可以是負的。MST 只比較邊的大小，不像最短路徑那樣要把權重沿著路徑累加，所以負權重完全沒問題；把所有權重都加上同一個常數 c，每棵生成樹的成本都多 (n − 1)c，誰最小不會變。
  • MST 不一定唯一。有相同權重的邊時，可能有好幾棵成本一樣的 MST（後面唯一性一節會講什麼時候一定唯一）。題目問的「MST 的成本」一定唯一，但「MST 的邊」不一定。
  • 只談無向圖。有向圖的對應問題叫 minimum arborescence，要用別的演算法，考研的 MST 題一律是無向圖。

圖可以用相鄰矩陣或相鄰串列存（在 BFS & DFS 介紹過）；下面的程式兩種都用到：Kruskal 和 Sollin 只需要一個「邊的陣列」，Prim 的 O(V²) 版用相鄰矩陣 cost[u][v]，heap 版用相鄰串列。

看程式碼：邊的結構與排序用的比較函式
Edge 與 cmpEdge()
typedef struct {
  int u, v, w;                           /* 無向邊 (u, v)，權重 w */
} Edge;

/* 權重小的在前；權重相同時依 (u, v) 由小到大，讓結果固定 */
int cmpEdge(const void *x, const void *y) {
  const Edge *a = x, *b = y;
  if (a->w != b->w) return (a->w > b->w) - (a->w < b->w);
  if (a->u != b->u) return a->u - b->u;
  return a->v - b->v;
}

為什麼貪婪是對的：cut property 與 cycle property

貪婪演算法很容易寫，難的是確定它不會因為「眼前最便宜」而錯過全域最佳。MST 的所有演算法都靠兩個性質撐腰，考研的觀念題也幾乎都在考它們的正確敘述與反例。

Cut 與 light edge

把頂點分成兩堆 S 和 V − S，叫做一個 Cut（切割）。一端在 S、另一端在 V − S 的邊叫做跨越這個 cut；跨越的邊裡權重最小的叫 Light Edge（輕邊）。

Cut property：對任何一個 cut，跨越它的最輕邊一定屬於某一棵 MST；如果這條最輕邊是唯一的（沒有別的跨越邊和它一樣輕），它就屬於每一棵 MST。

證明（換邊法）：設 e = (u, v) 是跨越 cut (S, V − S) 的最輕邊，T 是一棵不含 e 的 MST。把 e 加進 T，會形成一個環；這個環從 u 出發、繞到 v 再回來，一定有另一條邊 f 也跨越同一個 cut（從 S 走到 V − S 再走回來，至少要跨兩次）。因為 e 是最輕的跨越邊，w(e) ≤ w(f)，所以 T + e − f 是一棵成本 ≤ T 的生成樹，它也是 MST，而且包含 e。若 e 是唯一最輕，w(e) < w(f)，T + e − f 就比 T 更便宜，和 T 是 MST 矛盾，所以每棵 MST 都一定含 e。

Cycle property：圖上任何一個環，環上唯一最重的邊不屬於任何 MST；如果最重的邊有好幾條並列，至少存在一棵 MST 不用其中某一條。

證明：設 f 是環 C 上唯一最重的邊，假設某棵 MST T 含 f。拿掉 f，T 斷成兩塊；C 是一個環，所以 C 上除了 f 之外一定還有別的邊 e 連接這兩塊，而且 w(e) < w(f)。T − f + e 是更便宜的生成樹，矛盾。

常考的推論與反例

敘述對錯理由
全圖最輕的邊一定在某棵 MST對它是任何「把它的兩端分開的 cut」的最輕邊；Kruskal 第一條就收它
第二輕的邊一定在某棵 MST對簡單圖中兩條邊不可能成環，Kruskal 一定也收
第三輕的邊一定在某棵 MST錯可能和前兩條圍成三角形，例如三角形權重 1、2、3，邊 3 不在 MST
全圖唯一最重的邊一定不在 MST錯它可能是 bridge（拿掉就不連通），例如一個頂點只靠這條邊接上，每棵生成樹都要用它
某個環上唯一最輕的邊一定在 MST錯它在別的環上可能是最重的；cycle property 只講「最重的不在」
在某棵 MST 裡的邊，一定是某個 cut 的 light edge對把它從 MST 拿掉形成的 cut，它就是最輕的跨越邊，否則可以換成更輕的

通用的貪婪框架

把兩個性質合起來，就得到所有 MST 演算法的共同骨架：維護一個邊集合 A，保證 A 一直「包含在某棵 MST 裡」。每一步找一個不切到 A 的 cut（A 的邊都不跨越它），把跨越它的最輕邊加進 A，依 cut property，A 仍然包含在某棵 MST 裡；做 n − 1 次就完成了。這樣的邊叫做 A 的 Safe Edge（安全邊）。三種演算法的差別只在「怎麼挑 cut」：

  • Kruskal：A 是一片森林。下一條要看的邊 (u, v) 如果連接兩棵不同的樹，就用「u 所在的那棵樹 | 其餘頂點」當 cut，(u, v) 是目前沒看過的邊裡最輕的，所以一定是最輕的跨越邊。
  • Prim：A 永遠是一棵包含起點的樹 X，cut 固定是 X | V − X。
  • Sollin：每一棵樹各自當一個 cut，同時挑邊。

Kruskal：邊由小到大，不成環就收

Kruskal's Algorithm（Kruskal 演算法）的想法最直覺：把所有邊照權重由小到大排好，從最便宜的開始一條一條看，加進來不會形成環就收，會形成環就丟掉，收滿 n − 1 條就結束。過程中收下的邊不一定連在一起，是一片慢慢合併的森林。

  1. 把 e 條邊依權重排序。
  2. 一開始每個頂點自己是一棵樹（n 棵）。
  3. 依序取下一條邊 (u, v)：如果 u、v 在不同的樹上，收下它並把兩棵樹合併；如果已在同一棵樹上，丟掉（樹上已經有一條 u 到 v 的路，加進來就成環）。
  4. 收滿 n − 1 條就停；邊看完了還不滿，代表圖不連通。

為什麼丟掉的邊不可惜？它是在「比它輕的邊都看過之後」才發現兩端已經連通，所以它和樹上那條路形成的環中，它是最重的，cycle property 保證它不在 MST。為什麼收下的邊安全？它是目前沒看過的邊裡最輕的，又跨越「u 所在的樹 | 其他」這個 cut，cut property 保證它安全。

判斷會不會成環：union-find

「u、v 在不在同一棵樹上」要能快速判斷。把每棵樹當成一個集合，就是 Union-Find（聯集-搜尋，又叫 disjoint set）的兩個操作：find(x) 找出 x 所在集合的代表（root），兩端 root 相同就是同一棵樹；收下一條邊時用 union 把兩個集合合併。加上「小集合掛到大集合下面」與「路徑壓縮」，每次操作的均攤成本是 α(n)，α 是成長極慢的反阿克曼函數，實務上 ≤ 4，可以當成常數。union-find 的細節會在「Set Representation (Union-Find) 集合表示法」（籌備中）一頁講，這裡會用就好。

看程式碼：union-find（路徑壓縮＋依大小合併）
initSets() / find() / unionSets()
int parent[MAXV], setSize[MAXV];

void initSets(void) {
  for (int i = 0; i < n; i++) {
    parent[i] = i;                       /* 一開始每個頂點自己一棵樹 */
    setSize[i] = 1;
  }
}

int find(int x) {                        /* 找 x 所在集合的代表（root），順便壓縮路徑 */
  if (parent[x] != x) parent[x] = find(parent[x]);
  return parent[x];
}

void unionSets(int a, int b) {           /* a、b 都是 root：小的集合掛到大的下面 */
  if (setSize[a] < setSize[b]) { int t = a; a = b; b = t; }
  parent[b] = a;
  setSize[a] += setSize[b];
}

看程式碼：kruskal()
kruskal()：排序＋union-find
int kruskal(Edge t[]) {
  int k = 0, total = 0;
  qsort(e, m, sizeof(Edge), cmpEdge);    /* 所有邊依權重排序：O(E log E) */
  initSets();
  for (int i = 0; i < m && k < n - 1; i++) {
    int ru = find(e[i].u), rv = find(e[i].v);
    if (ru == rv) {                      /* 兩端已在同一棵樹：加進來會形成環 */
      printf("  略過 (%d,%d) %d：形成環\n", e[i].u, e[i].v, e[i].w);
      continue;
    }
    unionSets(ru, rv);                   /* 兩棵樹合併成一棵 */
    t[k++] = e[i];
    total += e[i].w;
  }
  if (k < n - 1) return -1;              /* 收不滿 n-1 條：圖不連通，只得到生成樹林 */
  return total;
}

時間複雜度：O(E log E) = O(E log V)

排序 e 條邊要 O(e log e)；之後最多 e 次 find、n − 1 次 union，每次接近 O(1)，總共 O(e α(n))，比排序小。所以 Kruskal 的瓶頸是排序，總時間 O(e log e)。因為簡單圖的 e ≤ n(n − 1)/2 < n²，log e < 2 log n，所以 O(e log e) 和 O(e log n) 是同一個等級，兩種寫法都對。如果邊權是小範圍整數可以用 counting sort 排，Kruskal 就接近 O(e α(n))。另一種寫法是不排序，把邊建成 min-heap 每次取最小，好處是收滿 n − 1 條就能提早停，最差情況一樣是 O(e log e)。

改成求最大成本生成樹也很簡單：邊由大到小排，其他完全不變（等於把所有權重取負號再求 MST）。

Prim：從一個點往外長

Prim's Algorithm（Prim 演算法）換一個角度：從任選的起點 s 開始，手上永遠只有一棵樹 X。每一步看所有「一端在 X、另一端在 X 外」的邊，也就是跨越 cut (X, V − X) 的邊，挑最輕的那條，把它和另一端的頂點加進 X。重複 n − 1 次，X 長滿所有頂點。依 cut property，每次挑的都是安全邊。

要快速找「最輕的跨越邊」，替每個樹外頂點 v 記兩個值：key[v] 是「v 用一條邊接到 X，最便宜要多少」，from[v] 是那條邊在樹上的另一端。每一步：

  1. 在樹外的頂點中，選 key 最小的 u，把邊 (from[u], u) 收進 MST，u 加入 X。
  2. u 進來之後，u 的鄰居 v 多了一條接到樹的路：如果 w(u, v) < key[v]，就更新 key[v] = w(u, v)、from[v] = u。

這個更新規則和 Dijkstra 最短路徑幾乎一模一樣，唯一的差別是 Dijkstra 比較的是 dist[u] + w(u, v)（從起點一路累加的距離），Prim 比較的只是 w(u, v) 這一條邊。考題常把兩者的更新式放在一起考（例題）。

兩種實作：O(V²) 與 O(E log V)

  • 相鄰矩陣＋key 陣列（預設頁籤）：每一步掃一遍 n 個頂點找最小 key，O(n)；更新時掃 u 的那一列，也是 O(n)。做 n 步，總共 O(n²)，和邊數無關。
  • binary heap＋相鄰串列：把候選邊放進 min-heap，每次 pop 最輕的；pop 出來的邊另一端如果已經在樹上，是過期的候選，直接丟掉。每條邊最多被 push 一次（一端先進樹時 push，另一端進樹時它已過期、不會再 push），每次 push、pop 都是 O(log e)，總共 O(e log e) = O(e log n)。另一種寫法是 heap 裡放頂點、用 decrease-key 更新 key，同樣 O((n + e) log n)。
  • Fibonacci heap：decrease-key 均攤 O(1)、extract-min O(log n)，總共 O(e + n log n)，是理論上最快的 Prim。
看程式碼：prim()（相鄰矩陣版／heap 版）
prim()：key 陣列，O(V²)
int prim(int s, Edge t[]) {
  int key[MAXV], from[MAXV], inTree[MAXV], total = 0;
  for (int v = 0; v < n; v++) {
    key[v] = INF;                        /* key[v]：v 連到樹上最便宜的邊權 */
    from[v] = -1;                        /* from[v]：那條邊的另一端（樹上的頂點） */
    inTree[v] = 0;
  }
  key[s] = 0;
  for (int k = 0; k < n; k++) {
    int u = -1;
    for (int v = 0; v < n; v++)          /* 在樹外找 key 最小的頂點：O(V) */
      if (!inTree[v] && (u == -1 || key[v] < key[u])) u = v;
    if (key[u] == INF) return -1;        /* 剩下的頂點都接不上：圖不連通 */
    inTree[u] = 1;                       /* 邊 (from[u], u) 是跨越 cut 最輕的邊 */
    total += key[u];
    if (from[u] != -1) t[k - 1] = (Edge){from[u], u, key[u]};
    for (int v = 0; v < n; v++)          /* 用 u 的邊更新樹外頂點的 key */
      if (!inTree[v] && cost[u][v] < key[v]) {
        key[v] = cost[u][v];
        from[v] = u;
      }
  }
  return total;
}
primHeap()：min-heap 放候選邊，O(E log V)
int primHeap(int s, Edge t[]) {
  int inTree[MAXV] = {0}, k = 0, total = 0;
  hsize = 0;
  inTree[s] = 1;
  for (int i = head[s]; i != -1; i = nxt[i]) heapPush((Edge){s, to[i], wt[i]});
  while (hsize > 0 && k < n - 1) {
    Edge x = heapPop();                  /* heap 裡最便宜的候選邊 */
    if (inTree[x.v]) continue;           /* 另一端也已在樹上：過期的候選，丟掉 */
    inTree[x.v] = 1;
    t[k++] = x;
    total += x.w;
    for (int i = head[x.v]; i != -1; i = nxt[i])
      if (!inTree[to[i]]) heapPush((Edge){x.v, to[i], wt[i]});
  }
  return k == n - 1 ? total : -1;
}

heap 版用到的 heapPush、heapPop 就是一般的 min-heap 插入與刪除最小值（上浮、下沉），做法和 Heap 堆積那一頁的 max-heap 相同，只是比較方向相反；排序依據是邊的權重。

動手操作

在第一個輸入框用「頂點-頂點:權重」輸入無向邊（空白隔開，頂點 0～9、最多 16 條邊、權重 −99～999），第二個輸入框是 Prim 的起點。按 Kruskal 看右側排好序的邊一條一條被考慮：藍色是正在看的邊，綠色收下，紅色虛線因為兩端 find 到同一個 root（會成環）而略過，下方是 union-find 目前的集合。按 Prim 看樹從起點長出去：綠色是樹上的頂點與邊，藍色是跨越 cut 的邊（實線是每個樹外頂點目前 key 所對應的邊，虛線是其他較貴的跨越邊），樹外頂點下方標著 key。「同權重」範例可以看到同權重時依 (u, v) 決定順序；「不連通」範例可以看到收不滿 n − 1 條邊的情況。

複雜度比較：稀疏圖與稠密圖

演算法關鍵資料結構時間適合
Kruskal排序＋union-findO(E log E) = O(E log V)稀疏圖、邊已經排好或用邊表給的題目
Prim（相鄰矩陣）key 陣列O(V²)稠密圖（E 接近 V²）
Prim（binary heap）min-heap＋相鄰串列O(E log V)稀疏圖
Prim（Fibonacci heap）Fibonacci heapO(E + V log V)理論最佳，稠密圖時等於 O(V²)
Sollin（Borůvka）union-findO(E log V)平行計算

拿數字感受一下，V = 1000：

  • 稀疏圖 E = 3000：Kruskal 約 3000 × log₂3000 ≈ 3000 × 11.6 ≈ 35,000 次比較；heap 版 Prim 約 3000 × log₂1000 ≈ 30,000；矩陣版 Prim 卻要 1000² = 1,000,000，慢了約 30 倍，因為它不管邊多邊少都要掃完整個矩陣。
  • 稠密圖 E ≈ V²/2 = 500,000：Kruskal 約 500,000 × 18.9 ≈ 9,500,000；heap 版 Prim 約 500,000 × 10 = 5,000,000；矩陣版 Prim 只要 1,000,000，反而最快，比 Kruskal 少了約 9 倍。

一句話記：Kruskal 看邊、Prim 看點。Kruskal 的成本跟著邊數走（要排序所有邊），Prim 矩陣版的成本跟著點數走（V²），所以邊很多的稠密圖用 Prim，邊很少的稀疏圖用 Kruskal 或 heap 版 Prim。

工具也不要記反：union-find 是 Kruskal 的（判斷兩端是否已連通），Prim 只維護一棵樹，用 inTree[] 就知道誰在樹上，不需要 union-find；heap（以及 Fibonacci heap 的 O(1) decrease-key）是 Prim 的，Kruskal 的瓶頸在排序，換成 Fibonacci heap 也不會變快。

Sollin（Borůvka）：每棵樹同時挑邊

第三種做法叫 Sollin's Algorithm（Sollin 演算法，也叫 Borůvka 演算法），它把 Kruskal 的「森林」和 Prim 的「往外長」結合起來：一開始每個頂點自己一棵樹；每一回合，每一棵樹各自挑出「連到別棵樹最便宜的邊」，把這些邊全部加進來（兩棵樹選到同一條邊時只加一次），樹就兩兩合併。重複到只剩一棵樹。

每一棵樹挑的都是「這棵樹 | 其他」這個 cut 的最輕邊，所以都是安全邊。每回合每棵樹至少和另一棵合併，樹的數量至少減半，所以最多 ⌈log₂ n⌉ 回合；每回合掃一遍所有邊 O(e)，總共 O(e log n)。各棵樹挑邊互不干擾，很適合平行處理。

有一個陷阱：如果權重有相同的，兩棵樹可能各挑一條同權重但不同的邊，三棵以上的樹就可能被連成環。所以權重相同時要有固定的比較規則（例如再比 (u, v)），程式裡的 cmpEdge 就是做這件事。

看程式碼：sollin()
sollin()：每回合每棵樹挑一條最便宜的外連邊
int sollin(Edge t[]) {
  int k = 0, total = 0, trees = n, cheap[MAXV];
  initSets();
  while (trees > 1) {
    for (int i = 0; i < n; i++) cheap[i] = -1;
    for (int i = 0; i < m; i++) {        /* 每棵樹找出連到外面最便宜的邊 */
      int a = find(e[i].u), b = find(e[i].v);
      if (a == b) continue;
      if (cheap[a] == -1 || cmpEdge(&e[i], &e[cheap[a]]) < 0) cheap[a] = i;
      if (cheap[b] == -1 || cmpEdge(&e[i], &e[cheap[b]]) < 0) cheap[b] = i;
    }
    int added = 0;
    for (int i = 0; i < n; i++) {
      if (cheap[i] == -1) continue;
      Edge x = e[cheap[i]];
      int a = find(x.u), b = find(x.v);
      if (a == b) continue;              /* 兩棵樹選中同一條邊：只加一次 */
      unionSets(a, b);
      t[k++] = x;
      total += x.w;
      trees--;
      added = 1;
    }
    if (!added) return -1;               /* 沒有樹找得到外連邊：圖不連通 */
    printf("  一回合後剩 %d 棵樹\n", trees);
  }
  return total;
}

MST 唯一性與常見變形

權重互不相同 → MST 唯一

證明：假設 T₁ ≠ T₂ 都是 MST，取兩者「不共有的邊」中權重最小的一條 e，不妨設 e 在 T₁ 不在 T₂。把 e 加進 T₂ 形成環，環上一定有一條 f 不在 T₁（否則整個環都在 T₁ 裡，T₁ 就有環了）。f 也是不共有的邊，而 e 是不共有邊中最小的，權重又互不相同，所以 w(e) < w(f)。T₂ + e − f 比 T₂ 便宜，和 T₂ 是 MST 矛盾。

反過來不成立：有相同權重的邊，MST 仍可能唯一。例如一條路徑 a–b–c，兩條邊都是 1，圖本身就是唯一的生成樹。判斷唯一性的實用方法：對每一條非樹邊 e，看它加進 MST 形成的環上，有沒有和它一樣重的樹邊；有就可以互換，MST 不唯一；全部都沒有，MST 就唯一。

同權重時：合法的收邊順序不只一種

Kruskal 遇到同權重的邊，誰先看都可以，所以可能有好幾種合法的選邊序列，甚至選出不同的樹。判斷「哪個序列不可能是 Kruskal 的」時檢查三件事：權重有沒有由小到大（同權重之間可以任意順序）、有沒有收到會成環的邊、有沒有漏掉一定要收的邊。以「同權重」範例（正方形四條邊都是 1，對角線 (0,2) 是 2）來說，四條權重 1 的邊任選 3 條都是 MST，一共 4 棵，成本都是 3；對角線 2 是任何環上最重的，永遠不收。

邊權改變之後

改變原本的 MST T怎麼修正
樹邊變輕還是 MSTT 的成本變小，其他樹最多也只變小同樣的量
非樹邊變重還是 MST本來就沒用它
非樹邊 e 變輕可能不是e 加進 T 形成環，環上最重的樹邊若比 e 重，換掉它
樹邊 f 變重可能不是拿掉 f 把 T 分成兩塊，找跨越這個 cut 最輕的邊，若比 f 輕就換上
所有邊加常數 c、或乘正數還是 MST邊的大小順序沒變，Kruskal 的排序也不變

以範例圖為例：如果把非樹邊 (4,5) 從 12 降成 7，它和樹上 4-3-5 形成環，環上最重的樹邊是 (3,4) 8 > 7，換掉之後成本變成 28 − 8 + 7 = 27。如果只降成 9，9 > 8，不用換，MST 不變。

最大生成樹、第二小生成樹

  • 最大成本生成樹：Kruskal 改成由大到小排；Prim 改成每次挑最重的跨越邊。cut、cycle property 也跟著反過來（跨越 cut 最重的邊安全、環上最輕的邊不要）。
  • 第二小生成樹（成本嚴格大於 MST 的最小生成樹）：一定可以由 MST 只換一條邊得到。對每一條非樹邊 e，加進 MST、拿掉它形成的環上最重的樹邊，成本增加 w(e) − (環上最大樹邊)；取增加量最小的那一個。範例圖中，把 (0,4) 9 加進來、拿掉環 0-1-3-4 上最重的 (3,4) 8，只多 1，所以第二小生成樹的成本是 29（已用程式窮舉 176 棵生成樹驗證）。

MST 與旅行推銷員

邊權非負時，MST 的成本一定 ≤ 任何一條 TSP Tour（旅行推銷員迴路）的成本：迴路拿掉任一條邊會變成一條經過所有頂點的路徑，路徑也是一棵生成樹，成本 ≥ MST，再把拿掉的那條（非負）邊加回去只會更大。這是 TSP 近似演算法的出發點。

MST 和最短路徑樹不一樣

從起點 s 做 Dijkstra，記下每個頂點最後一次被更新時的前一個頂點，也會得到一棵生成樹，叫 Shortest-Path Tree（最短路徑樹）。它和 MST 長得很像、程式也很像，但目標完全不同：

  • MST：讓所有邊的總和最小，不在乎任兩點之間的路有多長。
  • 最短路徑樹：讓從 s 到每個頂點的距離各自最小，不在乎總和。

所以「MST 上兩點之間的路徑就是最短路徑」是錯的，「從任一點做 Dijkstra 得到的樹就是 MST」也是錯的。MST 路徑真正保證的是另一個性質：MST 上 u 到 v 的路徑，使「路徑上最重的那條邊」在所有 u 到 v 的路徑中最小，也就是 Minimax Path（瓶頸最小的路徑）。Dijkstra 的細節會在「Shortest Path 最短路徑」（籌備中）一頁講。

易錯點

  • Kruskal 第 k 條收入的邊就是第 k 小的邊 → 中間會成環的邊被略過，不算數；要一條一條檢查 例題
  • Prim 收邊的順序也是權重由小到大 → Prim 每次只看跨出目前這棵樹的邊，很輕的邊可能要等兩端靠近樹才輪到 例題
  • 某個環上最輕的邊一定在 MST；全圖最重的邊一定不在 MST → 正確的是「cut 上最輕的邊安全」「環上唯一最重的邊不在」；最重的邊若是 bridge 一定要用 例題
  • MST 一定唯一；有同權重的邊就一定不唯一 → 權重互不相同保證唯一；有同權重時要實際檢查，仍可能唯一 例題
  • Prim 換起點，MST 成本可能不同；有負權重就不能用 → 起點只影響收邊順序，成本一定相同；MST 只比大小，負權重沒問題 例題
  • union-find 加速 Prim、Fibonacci heap 加速 Kruskal → 剛好相反：union-find 給 Kruskal 判斷成環，Fibonacci heap 的 decrease-key 給 Prim 例題
  • 降低一條非樹邊的權重，MST 不會變 → 降到比它所在環上最重的樹邊還輕，就要換掉；不會變的是「非樹邊變重」 例題
  • MST 上兩點的路徑是最短路徑；Dijkstra 得到的樹就是 MST → MST 讓總和最小，最短路徑樹讓每個距離最小，兩者不同 例題
