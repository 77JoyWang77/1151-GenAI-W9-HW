Euler and Hamilton Paths Euler 與 Hamilton 路徑Euler 管邊、Hamilton 管點

Ch7 Graphs 難度 Euler circuit Hamilton circuit degree Hierholzer

從七橋問題開始

十八世紀的 Königsberg 有一條河穿過市區，河中有兩座島，島和兩岸之間共有 7 座橋。當地人想知道：能不能從某個地方出發，每座橋剛好走過一次，最後回到原點？大家試了很久都做不到，但「試不出來」不等於「不可能」。Euler 把問題抽象化：陸地變成頂點、橋變成邊，問題就變成「能不能沿著圖走一圈，每條邊剛好用一次」。

Euler 的關鍵觀察只看度數（degree，連到這個頂點的邊數）：路線每經過一個中間的頂點，都是「走進來一次、走出去一次」，用掉兩條邊。所以除了起點和終點，每個頂點的邊都必須成對使用，度數一定是偶數。七橋的四個頂點全是奇數度，答案就是不可能，完全不用試。

這類「每條邊走一次」的問題在生活中很常見：郵差要走過每條街送信、掃街車要掃過每條路、畫圖時想「一筆畫完」。另一類看起來很像、其實完全不同的問題是「每個頂點剛好經過一次」，例如業務員要拜訪每個城市一次再回公司。前者叫 Euler，後者叫 Hamilton，這一頁會把兩者講清楚並比較。

定義：走邊還是走點

先釐清幾個名詞。在圖上從一個頂點沿著邊移動到另一個頂點，經過的序列叫 Walk（走法）；如果邊不重複叫 Trail（行跡），頂點也不重複叫 Path（路徑）；起點等於終點的稱為「迴路」或「環」。不同教材對 path、circuit 的用詞略有差異，考試時以題目的定義為準，但下面四個名詞的意思是固定的：

名詞要求回到起點？
Euler Circuit（Euler 迴路）每條邊剛好經過一次是
Euler Path（Euler 路徑）每條邊剛好經過一次不一定（通常指不回到起點）
Hamilton Circuit（Hamilton 迴路）每個頂點剛好經過一次是
Hamilton Path（Hamilton 路徑）每個頂點剛好經過一次不一定

記法：Euler 管邊、Hamilton 管點。Euler 可以重複經過頂點（只要邊不重複），Hamilton 可以有很多邊沒用到（只要每個點剛好一次）。

注意 Euler 允許重複經過頂點：七橋問題裡島 A 有 5 座橋，一定會被經過好幾次。反過來，Hamilton 迴路在 n 個頂點的圖上剛好用 n 條邊，其他邊都不用走。這兩個問題長得像，難度卻天差地遠：Euler 有一行就能判斷的定理，Hamilton 至今沒有有效率的判斷方法。

Euler 定理：數奇點就知道

對連通的無向圖（允許重邊；孤立點不影響，可以忽略）：

有 Euler 迴路 ⇔ 每個頂點的度數都是偶數。
有 Euler 路徑（但沒有迴路） ⇔ 恰好 2 個頂點是奇數度，而且路徑一定從其中一個奇點出發、在另一個奇點結束。
奇數度頂點有 4 個以上 ⇒ 都沒有。

為什麼「必要」？沿著 Euler 迴路走，每次經過一個頂點都是進來一條、出去一條，邊兩兩成對；起點也一樣，出發用掉一條、最後回來用掉一條。所以每個頂點的度數都是偶數。如果只是路徑，起點多出去一次、終點多進來一次，這兩點變成奇數度，其他點仍然是偶數。

為什麼「充分」？從任一點出發隨便走，因為每個點都是偶數度，走進一個不是起點的點時，一定還有一條沒走過的邊可以出去，所以只會在起點卡住，得到一個小迴路。如果還有邊沒走到，因為圖是連通的，這些邊一定和已走的迴路共用某個頂點，從那個頂點再繞一個小圈接進去就好。不斷重複，所有的邊都會被接進同一條迴路，這也就是下一節 Hierholzer 演算法的做法。

另外有一個基本事實：任何圖的奇數度頂點個數一定是偶數。因為每條邊替兩個端點各貢獻 1 度，度數總和 = 2 × 邊數，一定是偶數；偶數度頂點的度數和是偶數，所以奇數度頂點的度數和也必須是偶數，奇數個奇數加起來是奇數，因此奇點個數只能是偶數。這叫 Handshaking Lemma（握手定理），也說明了「恰好 1 個奇點」不可能出現。

一筆畫要幾筆？如果連通圖有 2k 個奇點（k ≥ 1），最少要 k 筆才能把所有邊畫完：每一筆最多「消化」兩個奇點（當起點和終點）。七橋有 4 個奇點，至少要 2 筆，也就是至少要有一座橋走兩次，或在兩個奇點之間多蓋一座橋。

有向圖的版本也很常考：有向圖有 Euler 迴路 ⇔ 連通（忽略方向後）且每個頂點的入度 = 出度；有 Euler 路徑 ⇔ 恰有一個頂點出度比入度多 1（起點）、一個頂點入度比出度多 1（終點），其餘入度 = 出度。

看程式碼：判斷有沒有 Euler 迴路／路徑
eulerType()：數奇點
int eulerType(int *start) {
  int odd = 0;
  *start = 0;
  if (!connected()) return 0;
  for (int v = n - 1; v >= 0; v--)             /* 倒著找，start 會是編號最小的奇點 */
    if (degree(v) % 2 == 1) { odd++; *start = v; }
  if (odd == 0) return 2;                      /* 全部偶點：Euler 迴路，從哪裡出發都行 */
  if (odd == 2) return 1;                      /* 恰好兩個奇點：從其中一個奇點出發 */
  return 0;                                    /* 奇點有 4 個以上：不存在 */
}
degree() 與 connected()：度數與連通性
#define N 8
int g[N][N];                                   /* g[u][v]：u、v 之間的邊數（允許重邊） */
int n;                                         /* 頂點數，編號 0..n-1 */

int degree(int v) {
  int d = 0;
  for (int u = 0; u < n; u++) d += g[v][u];
  return d;
}

int seen[N];
void dfs(int v) {
  seen[v] = 1;
  for (int u = 0; u < n; u++)
    if (g[v][u] && !seen[u]) dfs(u);
}

int connected(void) {
  int s = -1;
  memset(seen, 0, sizeof seen);
  for (int v = 0; v < n; v++) if (degree(v) > 0) { s = v; break; }
  if (s == -1) return 1;                       /* 沒有邊：當作連通 */
  dfs(s);
  for (int v = 0; v < n; v++)
    if (degree(v) > 0 && !seen[v]) return 0;   /* 有邊的頂點沒被走到 */
  return 1;
}

找出 Euler 迴路：Hierholzer 演算法

知道「有」之後，怎麼把路線實際找出來？Hierholzer's Algorithm（Hierholzer 演算法）把上一節的證明直接變成程式，用一個 Stack 記住「走過來的路」：

  1. 把起點放進 stack（有 2 個奇點時，起點一定要選奇點）。
  2. 看 stack 頂端的頂點 v：如果 v 還有沒走過的邊 v–u，就走過去，把這條邊標成已用，u 放進 stack。
  3. 如果 v 的邊都用完了（卡住了），就把 v 從 stack pop 出來，放進答案序列。
  4. stack 空了就結束，答案序列倒過來就是 Euler 迴路（路徑）。

卡住時退回上一個點，正是「從已走的迴路上找一個還有邊的頂點，繞一個小圈接進去」：退回到 v 之後，如果 v 還有邊，就會從 v 開始走出一個新的小圈，最後這個小圈會被接在答案裡 v 的位置。

例子：蝴蝶結（兩個三角形共用 C）

邊是 AB、AC、BC、CD、CE、DE，度數 A、B、D、E 都是 2，C 是 4，全部偶數，所以有 Euler 迴路。從 A 出發，每次挑字母最小的鄰居：

步驟動作stack（底 → 頂）答案（依放入順序）
1A 走到 BA B
2B 走到 CA B C
3C 的鄰居中 A 最小，走到 AA B C A
4A 的兩條邊都用完，卡住，pop AA B CA
5退回 C，C 還有 CD、CE，走到 DA B C DA
6D 走到 EA B C D EA
7E 走到 CA B C D E CA
8～13所有邊都用完，依序 pop C、E、D、C、B、A（空）A C E D C B A

答案倒過來是 A → B → C → D → E → C → A，6 條邊各走一次。第 4 步就是關鍵：一開始的 A–B–C–A 只是一個小圈，退回 C 之後補上右邊的小圈 C–D–E–C，兩個圈在 C 接在一起。

效能：每條邊只會被「走過去」一次，每個頂點被 push、pop 的次數和邊數同級，所以用相鄰串列實作時是 O(|V| + |E|)。下面的程式為了簡單用相鄰矩陣，每次找鄰居要掃 n 格，是 O(n · |E|)。另一個常見做法 Fleury's Algorithm（Fleury 演算法）是「能不走橋就不走橋」，每一步都要檢查某條邊是不是橋，比較慢，約 O(|E|²)，但手算時很直覺。

看程式碼：hierholzer()：用 stack 找 Euler 路徑
hierholzer()：用 stack 找 Euler 路徑
int adj[N][N];                                 /* 還沒走過的邊（g 的副本） */
int stack[64], path[64];

int hierholzer(int start) {                    /* 回傳 path 的頂點數 */
  int top = 0, len = 0;
  memcpy(adj, g, sizeof g);
  stack[0] = start;
  while (top >= 0) {
    int v = stack[top], u = 0;
    while (u < n && adj[v][u] == 0) u++;       /* 找 v 的一條還沒走過的邊 */
    if (u < n) {                               /* 有：走過去，這條邊用掉 */
      adj[v][u]--; adj[u][v]--;
      stack[++top] = u;
    } else {                                   /* 沒路了：v 放進答案，退回上一個點 */
      path[len++] = stack[top--];
    }
  }
  return len;                                  /* path 倒過來讀就是 Euler 路徑 */
}

Hamilton 迴路：沒有簡單的判別法

把「每條邊一次」換成「每個頂點一次」，問題就從簡單變成困難。判斷一個圖有沒有 Hamilton 迴路是 NP-complete（NP 完全）問題：目前沒有已知的多項式時間演算法，一般只能用回溯法（backtracking）一個一個試，最差要試 (n − 1)! 種排列。所以考試不會要你「判斷任意圖」，而是考下面這些工具。

用來證明「沒有」的必要條件

  • 有度數為 1 的頂點 ⇒ 沒有 Hamilton 迴路（它只能進不能出）。
  • 度數為 2 的頂點，兩條邊都必須出現在 Hamilton 迴路裡。如果某個頂點因此被迫用到 3 條邊，或提早形成一個沒包含全部頂點的小圈，就矛盾。
  • 有 Cut Vertex（割點），也就是拿掉它圖就斷開的頂點 ⇒ 沒有 Hamilton 迴路，因為迴路必須兩次經過它才能往返兩邊。
  • 二分圖 Km,n 的迴路必須左右交替，所以 m ≠ n 時沒有 Hamilton 迴路。

用來證明「有」的充分條件（n ≥ 3）

  • Dirac's Theorem（Dirac 定理）：每個頂點的度數都 ≥ n / 2，就一定有 Hamilton 迴路。
  • Ore's Theorem（Ore 定理）：任兩個不相鄰的頂點 u、v 都滿足 deg(u) + deg(v) ≥ n，就一定有。Dirac 是 Ore 的特例。

要特別注意這兩個定理是充分但不必要：不滿足條件不代表沒有。例如 n 個頂點的環 Cn 每個點只有 2 度，遠小於 n / 2，卻明顯有 Hamilton 迴路。

看程式碼：hamilton()：回溯法
hamilton()：回溯法
int cyc[N], used[N];

int hamilton(int k) {                          /* cyc[0..k-1] 已經排好，現在決定第 k 個 */
  if (k == n) return g[cyc[n - 1]][cyc[0]] > 0;   /* 全部排完，最後一點要能回到起點 */
  for (int v = 1; v < n; v++)
    if (!used[v] && g[cyc[k - 1]][v]) {        /* 沒用過、而且和上一個點相鄰 */
      used[v] = 1; cyc[k] = v;
      if (hamilton(k + 1)) return 1;
      used[v] = 0;                             /* 這條路走不通：退回，試下一個 */
    }
  return 0;
}

int hasHamiltonCircuit(void) {
  memset(used, 0, sizeof used);
  cyc[0] = 0; used[0] = 1;                     /* 迴路會經過每個點，固定從 0 出發即可 */
  return hamilton(1);
}

動手操作

每個頂點下方會標出度數。按 Euler 會先數奇點判斷，再用 Hierholzer 演算法逐步找出路線，下方兩列是 stack 和答案序列；按 Hamilton 會用回溯法從 A 開始試，走不通的地方會變紅並退回。可以點範例圖（蝴蝶結、六邊形、房子、七橋、K5、K2,3），或自己輸入邊，例如 AB BC CA，同一組字母出現兩次代表兩條重邊。

常考的特殊圖

考題最喜歡問「哪些 n 讓某種圖有 Euler／Hamilton 迴路」。用度數判斷 Euler、用結構判斷 Hamilton，整理如下：

圖度數Euler 迴路Hamilton 迴路
完全圖 Kn（n ≥ 3）每點 n − 1n 為奇數一定有
環 Cn（n ≥ 3）每點 2一定有一定有（它本身就是）
完全二分圖 Km,n左邊 n、右邊 mm、n 都是偶數m = n ≥ 2
超立方體 Qn（n ≥ 2）每點 nn 為偶數一定有（Gray code）
輪圖 Wn（n ≥ 3）中心 n、外圈 3沒有（外圈都是奇數度）一定有

Km,n 的 Euler 路徑（不是迴路）也常考：需要恰好 2 個奇點，只有在「其中一邊恰好 2 個頂點、另一邊是奇數個」（例如 K2,3：右邊 3 點都是 2 度、左邊 2 點都是 3 度），或 K1,1、K1,2 這兩個小圖時成立。

Hamilton 迴路的計數

在 Kn 中，Hamilton 迴路就是把 n 個點排成一圈。固定起點後剩下 (n − 1)! 種順序，而同一個圈順時針、逆時針走被算了兩次，所以不同的 Hamilton 迴路共有：

K_n 的 Hamilton 迴路數 = (n − 1)! / 2      例：K_5 有 4! / 2 = 12 個，K_7 有 6! / 2 = 360 個

這也說明了暴力法的困難：只是 n = 15，(14)! / 2 就超過 435 億個。另一個經典結果：n 為奇數時，Kn 的 n(n − 1) / 2 條邊可以剛好分成 (n − 1) / 2 個邊不重複的 Hamilton 迴路，每個迴路用 n 條邊。

應用與比較

  • 中國郵差問題（Chinese Postman）：每條街至少走一次、總距離最短。有 Euler 迴路時答案就是總邊長；沒有時，要在奇點之間重複走一些邊，把奇點兩兩配成偶數度。
  • 旅行推銷員問題（TSP）：每個城市拜訪一次、總距離最短，就是在加權完全圖上找最短的 Hamilton 迴路，至今沒有有效率的精確解法。
  • Gray code：n 位元的二進位碼排成一圈，相鄰兩個只差一個位元，就是超立方體 Qn 的 Hamilton 迴路，用在旋轉編碼器避免讀值跳動。
  • DNA 定序、de Bruijn 序列：把短片段組成長序列，可以轉成有向圖上的 Euler 路徑問題，所以能有效率地解。

易錯點

  • 有 2 個奇點就有 Euler 迴路 → 只有 Euler 路徑，而且必須從一個奇點出發、在另一個奇點結束；迴路要全部偶數度 例題
  • Kn 都有 Euler 迴路 → Kn 每點 n − 1 度，只有 n 為奇數時才全是偶數度 例題
  • 不滿足 Dirac 條件就沒有 Hamilton 迴路 → Dirac、Ore 是充分條件，不是必要條件；Cn 每點只有 2 度也有 例題
  • 有 Euler 迴路的圖一定也有 Hamilton 迴路 → 兩者互不保證，蝴蝶結有 Euler 迴路但沒有 Hamilton 迴路 例題
  • Kn 的 Hamilton 迴路有 n! 個 → 起點不同、方向相反都算同一個圈，要除以 n 再除以 2，得到 (n − 1)! / 2 例題
  • Km,n 只要 m = n 就有 Euler 迴路 → m = n 是 Hamilton 的條件；Euler 要 m、n 都是偶數 例題
