Propositional Logic 命題邏輯蘊含只在 T → F 時為假

Ch1 Logic and Proofs 難度 truth table implication tautology De Morgan CNF/DNF

為什麼要學命題邏輯

寫程式時你天天在用邏輯：if (x > 0 && !done)、while (i < n || retry)。可是當條件一長，例如「不是（A 而且 B）」到底等不等於「不是 A 或不是 B」？「如果下雨就不出門」和「如果出門就沒下雨」是不是同一句話？靠直覺很容易搞錯，這時就需要一套可以機械式檢查的規則。

Propositional Logic（命題邏輯）就是這套規則的最基礎版本：把一句句「非真即假」的話當成變數，用少數幾個連接詞組合起來，然後用真值表或等價律判斷整句話什麼時候成立、兩句話是不是同一個意思。它是後面述詞邏輯、推論規則、證明方法的地基，也直接對應到計算機組織的邏輯電路和布林代數。

考研題目在這裡最常考三件事：(1) 蘊含 p → q 的真值與它的逆、否、逆否命題；(2) 用真值表或等價律判斷恆真式、矛盾式、兩式是否等價；(3) 把中文或英文句子翻成邏輯式（特別是「只有……才……」）。這一頁會把這些一次講清楚，並附上一個可以自己輸入公式的真值表動畫。

命題是什麼

Proposition（命題）是一個有明確真假的敘述句：要嘛為真（記作 T），要嘛為假（記作 F），不能兩者都是，也不能都不是。重點不在於「我們知不知道答案」，而在於「它本身有沒有確定的真假」。

句子是不是命題原因
7 是質數。是（T）有確定真假
台北在台南的南邊。是（F）假的也是命題
每個大於 2 的偶數都能寫成兩個質數的和。是真假目前沒人證明出來，但它本身一定有答案
今天會不會下雨？不是問句沒有真假
把作業交上來。不是命令句沒有真假
x + 3 = 5不是x 沒給值，真假不確定（這是下一個主題「述詞」）

不能再拆的命題叫 Atomic Proposition（原子命題），我們用小寫字母 p、q、r、s 代表它們，叫做命題變數。用連接詞把原子命題組起來，就得到 Compound Proposition（複合命題），例如「p 而且非 q」。複合命題的真假完全由它的原子命題決定，這正是真值表能運作的原因：n 個變數只有 2n 種真假組合，全部列出來就能看清楚整句話的行為。

六個連接詞

命題邏輯常用的連接詞有六個。下表左邊是數學寫法，右邊是本頁動畫和 C 程式用的 ASCII 寫法：

名稱符號ASCII讀法什麼時候為真
Negation（否定）¬p~p非 pp 為假時
Conjunction（合取）p ∧ qp & qp 且 q兩個都為真
Disjunction（析取）p ∨ qp | qp 或 q至少一個為真
Exclusive Or（互斥或）p ⊕ qp ^ qp 或 q 但不同時剛好一個為真
Conditional（條件句／蘊含）p → qp -> q若 p 則 q除了「p 真 q 假」以外都為真
Biconditional（雙條件）p ↔ qp <-> qp 若且唯若 qp、q 真值相同

有兩個地方特別容易和日常用語混淆：

  • 「或」預設是可兼的：數學裡 p ∨ q 在兩個都真時也是真。日常說「飲料可以選紅茶或綠茶」通常是二選一，那其實是 ⊕。題目沒特別說明時，「或」一律當 ∨。
  • ⊕ 和 ↔ 互為否定：⊕ 是「真值不同才真」，↔ 是「真值相同才真」，所以 p ⊕ q ≡ ¬(p ↔ q)。在電路裡 ⊕ 就是 XOR 閘，↔ 是 XNOR 閘。

在程式裡，每個連接詞都只是一行運算：∧ 是 &&、∨ 是 ||、⊕ 可以寫成「兩邊不相等」，→ 用下一節會講的 ¬p ∨ q，↔ 是「兩邊相等」。下面的 eval() 用遞迴算出一個公式在某一組變數值下的真值，row 的二進位每一位代表一個變數（1 = T）：

看程式碼：eval()：遞迴求出公式的真值
eval()：遞迴求出公式的真值
int eval(int k, int row) {
  Node *t = &node[k];
  switch (t->op) {
  case VAR:   return (row >> (nvar - 1 - pos[t->var])) & 1;
  case CONST: return t->var;
  case NOT:   return !eval(t->l, row);
  case AND:   return eval(t->l, row) && eval(t->r, row);
  case XOR:   return eval(t->l, row) != eval(t->r, row);   /* 剛好一個為真 */
  case OR:    return eval(t->l, row) || eval(t->r, row);
  case IMP:   return !eval(t->l, row) || eval(t->r, row);  /* 前提假就為真 */
  case IFF:   return eval(t->l, row) == eval(t->r, row);   /* 真值相同才為真 */
  }
  return 0;
}
Node：公式存成語法樹

enum { CONTRADICTION, CONTINGENT, TAUTOLOGY };

  int l, r;        /* 左右子樹在 node[] 裡的位置（NOT 只用 l） */

蘊含：前提假就為真

p → q 是整個命題邏輯最違反直覺的地方。p 叫 Hypothesis（前提），q 叫 Conclusion（結論）。它的真值表只有一列是 F：前提為真、結論為假。很多人卡在「p 是假的，為什麼 p → q 還是真？」

把 p → q 想成一個承諾最好懂。學長說：「如果你期中考 90 分以上，我就請你喝飲料。」什麼情況下學長算是「說謊」？

你考 90 以上（p）學長請客（q）學長有沒有食言p → q
TT說到做到T
TF食言了，承諾被打破F
FT你沒考到，他還是請了，大方而已，沒違反承諾T
FF你沒考到，他也沒請，沒違反承諾T

承諾只規定了「p 發生時要怎樣」，p 沒發生時完全沒有約束，所以不能說它是假的。在二值邏輯裡「不是假」就是真，這種前提為假而成立的情況叫 Vacuous Truth（空虛的真）。也因此 p → q 和 ¬p ∨ q 真值完全一樣：「要嘛前提不成立，要嘛結論成立」。這條 蘊含消去 是化簡時最常用的一條，等於是把 → 換成 ∨ 的公式。

記法：p → q 只在「T → F」時為假。看到 → 就想 ¬p ∨ q。

p → q 的各種說法

翻譯句子是必考題，特別是 only if（只有……才……）和 unless（除非）：

說法邏輯式理解方式
若 p 則 q；p implies qp → q標準形式
p 是 q 的充分條件p → q有 p 就足以保證 q
q 是 p 的必要條件p → q沒有 q 就不可能有 p
p only if q；只有 q 才 pp → qp 發生的前提是 q 必須成立
p if q；q 的話就 pq → pif 後面的才是前提
p unless q；除非 q，否則 p¬q → p（≡ p ∨ q）q 不成立時一定是 p
p if and only if q；p 若且唯若 qp ↔ q(p → q) ∧ (q → p)

舉例：「只有繳了學費，才能選課」。令 p = 能選課、q = 繳了學費，「能選課」的必要條件是「繳學費」，所以是 p → q，不是 q → p：繳了學費不保證能選課（可能還有擋修），但能選課的人一定繳了學費。

逆、否、逆否命題

從 p → q 出發，把前後對調、或兩邊都加上否定，可以得到三個相關的條件句：

名稱形式和 p → q 等價嗎
Converse（逆命題）q → p不等價
Inverse（否命題）¬p → ¬q不等價
Contrapositive（逆否命題）¬q → ¬p等價

為什麼逆否等價？用蘊含消去：¬q → ¬p ≡ ¬(¬q) ∨ ¬p ≡ q ∨ ¬p ≡ ¬p ∨ q ≡ p → q。直覺上也很合理：「下雨 → 地濕」等於「地沒濕 → 沒下雨」。逆命題卻不同：「地濕 → 下雨」不成立，地濕可能是有人灑水。用真值表看，p = T、q = F 那一列 p → q 為 F，但 q → p 為 T，這一列就是反例。

否命題 ¬p → ¬q 則是逆命題的逆否，所以它和逆命題等價，和原命題不等價。考試常把這四個混在一起出選擇題，記住「對角線等價」就不會錯。逆否等價也是「Proof by Contraposition（逆否證法）」的基礎：要證 p → q 很難時，可以改證 ¬q → ¬p。

運算優先順序與真值表

p ∨ q ∧ ¬r → s 要怎麼讀？跟算術的「先乘除後加減」一樣，連接詞也有優先順序，越高的越先結合：

優先順序連接詞備註
1（最高）¬只作用在緊接著的那一項：¬p ∧ q 是 (¬p) ∧ q
2∧
3⊕⊕ 的位置沒有統一規定，本頁跟 C 語言的 & ^ | 一樣放在 ∧ 和 ∨ 之間
4∨
5→連續的 → 從右邊結合：p → q → r 是 p → (q → r)
6（最低）↔

¬ > ∧ > ∨ > → > ↔ 這個順序是大多數教材的共識；但 ⊕ 的位置和 → 的結合方向各家寫法不一，考試作答時有疑慮就加括號，看到題目沒括號時也要先確認題目的約定。

怎麼畫真值表

  1. 列出變數：n 個變數有 2n 列。習慣從全 T 排到全 F，最左邊的變數每 2n−1 列換一次，最右邊的每列換一次，就像二進位倒著數。
  2. 拆子式：照語法樹由內往外，每個子式一欄，先算的放左邊。
  3. 逐欄計算：每一欄只用到它左邊已經算好的欄，套那個連接詞的真值表。
  4. 看最後一欄：整個公式的真值，用來判斷恆真、矛盾或可滿足。

例子：(p → q) ∧ ¬q → ¬p

這個公式說「如果 p 推得出 q，而 q 不成立，那 p 也不成立」。先看結構：→ 優先順序最低，所以整句是 [(p → q) ∧ ¬q] → ¬p。子式由內往外依序是 p → q、¬q、(p → q) ∧ ¬q、¬p、整個公式：

pqp → q¬q(p → q) ∧ ¬q¬p整個公式
TTTFFFT（前提 F）
TFFTFFT（前提 F）
FTTFFTT（前提 F）
FFTTTTT（T → T）

最後一欄 4 列全是 T，所以它是恆真式，這就是推論規則裡的 Modus Tollens（否定後件）。注意前三列都是靠「前提為 F 所以蘊含為 T」成立的，真正要檢查的只有第 4 列：前提 (p → q) ∧ ¬q 為真時，結論 ¬p 也真。

真值表的代價：每多一個變數，列數就翻倍。4 個變數 16 列還能手算，10 個變數就有 1024 列，30 個變數超過 10 億列。所以真值表適合變數少的題目，變數多時要改用下面的等價律化簡，或在考試中用「假設為假找矛盾」的方法（見練習題）。

下面的程式是一個完整的小型剖析器：用 Recursive Descent（遞迴下降）的方式，每一層優先順序寫一個函式，低優先的函式呼叫高優先的函式，所以高優先的運算子會先被組成子樹。

看程式碼：剖析公式、印出子式、產生真值表
parse()：遞迴下降剖析器（一層優先順序一個函式）
void skip(void) { while (src[at] == ' ') at++; }

int eat(const char *tok) {     /* 下一個符號是 tok 就吃掉它，回傳 1 */
  skip();
  int n = strlen(tok);
  if (strncmp(src + at, tok, n) == 0) { at += n; return 1; }
  return 0;
}

int fail(const char *msg) {
  if (!err) { err = msg; errAt = at; }   /* 只記第一個錯誤 */
  return -1;
}

int mk(int op, int var, int l, int r) {
  if (nn >= MAXN) return fail("公式太長");
  node[nn] = (Node){ op, var, l, r };
  return nn++;
}

int parseIff(void);

int parseAtom(void) {          /* 變數、常數、括號 */
  skip();
  char c = src[at];
  if (c >= 'p' && c <= 's') { at++; return mk(VAR, c - 'p', -1, -1); }
  if (c == 'T' || c == 'F') { at++; return mk(CONST, c == 'T', -1, -1); }
  if (c == '(') {
    at++;
    int k = parseIff();
    if (k < 0) return -1;
    if (!eat(")")) return fail("少了右括號 )");
    return k;
  }
  if (c == '\0') return fail("公式還沒結束，這裡需要一個變數或左括號");
  return fail("這裡需要變數 p q r s、常數 T F 或左括號");
}

int parseNot(void) {           /* ~ 只作用在緊接著的那一項 */
  if (eat("~")) {
    int k = parseNot();
    return k < 0 ? -1 : mk(NOT, 0, k, -1);
  }
  return parseAtom();
}

int parseAnd(void) {
  int k = parseNot();
  while (k >= 0 && eat("&")) { int r = parseNot(); k = r < 0 ? -1 : mk(AND, 0, k, r); }
  return k;
}

int parseXor(void) {
  int k = parseAnd();
  while (k >= 0 && eat("^")) { int r = parseAnd(); k = r < 0 ? -1 : mk(XOR, 0, k, r); }
  return k;
}

int parseOr(void) {
  int k = parseXor();
  while (k >= 0 && eat("|")) { int r = parseXor(); k = r < 0 ? -1 : mk(OR, 0, k, r); }
  return k;
}

int parseImp(void) {           /* p -> q -> r 讀成 p -> (q -> r) */
  int k = parseOr();
  if (k >= 0 && eat("->")) { int r = parseImp(); k = r < 0 ? -1 : mk(IMP, 0, k, r); }
  return k;
}

int parseIff(void) {
  int k = parseImp();
  while (k >= 0 && eat("<->")) { int r = parseImp(); k = r < 0 ? -1 : mk(IFF, 0, k, r); }
  return k;
}

int parse(const char *s) {     /* 成功回傳根節點，失敗回傳 -1（err、errAt 說明原因） */
  src = s; at = 0; err = NULL;
  int k = parseIff();
  skip();
  if (k >= 0 && src[at] != '\0')
    return fail(src[at] == ')' ? "多了一個右括號 )" : "這裡多出了無法辨識的符號");
  return k;
}
show()：依優先順序只加必要的括號
int prec(int op) {
  switch (op) {
  case IFF: return 1;
  case IMP: return 2;
  case OR:  return 3;
  case XOR: return 4;
  case AND: return 5;
  case NOT: return 6;
  }
  return 7;                                     /* 變數、常數 */
}

void show(int k, char *out) {                   /* 把子樹 k 接在 out 後面 */
  static const char *sym[] = { "", "", "~", " & ", " ^ ", " | ", " -> ", " <-> " };
  Node *t = &node[k];
  if (t->op == VAR) { char v[2] = { (char)('p' + t->var), '\0' }; strcat(out, v); return; }
  if (t->op == CONST) { strcat(out, t->var ? "T" : "F"); return; }
  int p = prec(t->op);
  if (t->op == NOT) {
    int paren = prec(node[t->l].op) < p;
    strcat(out, "~");
    if (paren) strcat(out, "(");
    show(t->l, out);
    if (paren) strcat(out, ")");
    return;
  }
  int pl = prec(node[t->l].op), pr = prec(node[t->r].op);
  int lp = pl < p || (pl == p && t->op == IMP);  /* -> 從右結合：左邊同級一定要括號 */
  int rp = pr <= p;                              /* 右邊同級也加括號，讀起來比較清楚 */
  if (lp) strcat(out, "(");
  show(t->l, out);
  if (lp) strcat(out, ")");
  strcat(out, sym[t->op]);
  if (rp) strcat(out, "(");
  show(t->r, out);
  if (rp) strcat(out, ")");
}
addCols() 與 truthTable()：依計算順序列出子式欄
/* 依「先算子式、再算整體」的順序列出要算的欄位（後序，重複的子式只列一次） */
int cols[MAXN], ncol;
char colText[MAXN][160];

void addCols(int k) {
  if (node[k].op == VAR || node[k].op == CONST) return;
  addCols(node[k].l);
  if (node[k].r >= 0) addCols(node[k].r);
  char buf[160] = "";
  show(k, buf);
  for (int i = 0; i < ncol; i++) if (strcmp(colText[i], buf) == 0) return;
  strcpy(colText[ncol], buf);
  cols[ncol++] = k;
}

void truthTable(int root) {
  ncol = 0;
  addCols(root);
  for (int v = 0; v < 4; v++) if (pos[v] >= 0) printf("%c ", 'p' + v);
  for (int i = 0; i < ncol; i++) printf("| %s ", colText[i]);
  printf("\n");
  for (int row = (1 << nvar) - 1; row >= 0; row--) {
    for (int i = 0; i < nvar; i++) printf("%c ", (row >> (nvar - 1 - i)) & 1 ? 'T' : 'F');
    for (int i = 0; i < ncol; i++) {
      int w = strlen(colText[i]);
      printf("| %*c ", w, eval(cols[i], row) ? 'T' : 'F');
    }
    printf("\n");
  }
}

恆真式、矛盾式與可滿足

看真值表的最後一欄，可以把公式分成三類：

分類最後一欄例子
Tautology（恆真式）每一列都是 Tp ∨ ¬p、(p ∧ q) → p
Contradiction（矛盾式）每一列都是 Fp ∧ ¬p、p ⊕ p
Contingency（可能式）有 T 也有 Fp → q（4 列中 3 列為真）

另一個常用的詞是 Satisfiable（可滿足）：至少有一列為 T，也就是存在一組變數值讓公式成立。所以「可滿足」包含恆真式和可能式，只有矛盾式是不可滿足的。三者的關係可以用否定互相轉換：

  • A 是恆真式 ⇔ ¬A 是矛盾式（每一列都反過來）。
  • A 可滿足 ⇔ A 不是矛盾式 ⇔ ¬A 不是恆真式。
  • A 是可能式 ⇔ ¬A 也是可能式。

程式只要數最後一欄有幾個 T：等於 2n 是恆真、等於 0 是矛盾，其他是可能式。這需要把 2n 列全部算完，每列求值和公式長度 m 成正比，總共 O(2n · m)。

看程式碼：classify()：數有幾列為真
classify()：數有幾列為真
int classify(int root) {
  int t = 0, rows = 1 << nvar;
  for (int row = rows - 1; row >= 0; row--)     /* 由全 T 到全 F，共 2^n 列 */
    t += eval(root, row);                       /* 數有幾列為真 */
  if (t == rows) return TAUTOLOGY;              /* 每一列都真 */
  if (t == 0) return CONTRADICTION;             /* 每一列都假 */
  return CONTINGENT;                            /* 有真有假：可滿足但不是恆真 */
}

動手操作

在第一格輸入公式 A，按「填真值表」：動畫會先決定列數，然後每一列先代入變數值（橘色），再照優先順序一欄一欄算子式（藍色是正在算的子式和它用到的欄，紫色是剛算出的值），最後判斷恆真、矛盾或可滿足。第二格輸入公式 B 時，會多一欄「相同？」逐列比較兩式，紅色的列就是反例。右側程式碼會跟著亮起 eval() 裡對應的那一行。

邏輯等價與常用等價律

兩個公式 A、B 如果在每一組變數值下真值都相同，就說它們 Logically Equivalent（邏輯等價），記作 A ≡ B。換個角度：A ≡ B ⇔ A ↔ B 是恆真式。判斷方法有兩種：畫出兩者的真值表逐列比較（只要有一列不同就不等價，那一列就是反例），或用已知的等價律一步步改寫。

注意 ≡ 不是連接詞，它是在描述「兩個公式之間的關係」；↔ 才是公式裡的連接詞。p ↔ q 本身可能真可能假，但 p → q ≡ ¬p ∨ q 是一個永遠成立的事實。

和代數不同的是，∨ 對 ∧ 也可以分配（第二條分配律），這在一般數的加法和乘法是不成立的：a + bc ≠ (a + b)(a + c)。De Morgan 定律口訣是「否定進括號，且或互換」，也就是把 ¬ 分配進去時 ∧、∨ 要對調。

對偶：把一條只含 ¬、∧、∨ 的等價式中所有 ∧ 和 ∨ 互換、T 和 F 互換，得到的式子仍然成立。上表大部分的等價律都是兩兩成對，就是這個原因。

equivalent()：逐列比較找反例
int equivalent(int a, int b) {                  /* 回傳反例那一列；-1 表示等價 */
  for (int row = (1 << nvar) - 1; row >= 0; row--)
    if (eval(a, row) != eval(b, row)) return row;   /* 這一列兩式真值不同 */
  return -1;                                    /* 每一列都相同：a ≡ b */
}

用等價律化簡與證明

真值表很可靠但很長；等價律則像代數化簡，一步一步改寫，每一步都要能說出用了哪一條律。常見的套路是：先用蘊含消去把 → 、↔ 換掉，再用 De Morgan 把 ¬ 推到變數旁邊，最後用分配律、吸收律、否定律收尾。

例 1：化簡 ¬(p → q) ∨ (p ∧ q)

步驟式子理由
0¬(p → q) ∨ (p ∧ q)原式
1¬(¬p ∨ q) ∨ (p ∧ q)蘊含消去
2(¬¬p ∧ ¬q) ∨ (p ∧ q)De Morgan
3(p ∧ ¬q) ∨ (p ∧ q)雙重否定
4p ∧ (¬q ∨ q)分配律（反向，提出 p）
5p ∧ T否定律
6p恆等律

所以 ¬(p → q) ∨ (p ∧ q) ≡ p：看起來有兩個變數，其實結果和 q 完全無關。直覺上也通：第一項是「p 真且 q 假」、第二項是「p 真且 q 真」，合起來就是「p 真」。

例 2：證明 (p → r) ∧ (q → r) ≡ (p ∨ q) → r

步驟式子理由
0(p → r) ∧ (q → r)左式
1(¬p ∨ r) ∧ (¬q ∨ r)蘊含消去（兩次）
2(¬p ∧ ¬q) ∨ r分配律（反向，∨ 對 ∧ 的版本提出 r）
3¬(p ∨ q) ∨ rDe Morgan
4(p ∨ q) → r蘊含消去（反向）

這條的意思是「p 會導致 r、q 也會導致 r」等於「p 或 q 任一個發生就會導致 r」，是分情況證明的依據。小心不要和 (p → q) ∨ (p → r) 搞混，後者等價於 p → (q ∨ r)。

證明恆真式

要證 A 是恆真式，可以把 A 化簡到 T。例如 [p ∧ (p → q)] → q：先換成 ¬[p ∧ (¬p ∨ q)] ∨ q，分配律得 p ∧ (¬p ∨ q) ≡ (p ∧ ¬p) ∨ (p ∧ q) ≡ p ∧ q，所以整式 ≡ ¬(p ∧ q) ∨ q ≡ ¬p ∨ ¬q ∨ q ≡ ¬p ∨ T ≡ T。另一個更快的方法是假設它為假找矛盾：→ 為假只有「前提 T、結論 F」一種可能，所以 q = F，且 p ∧ (p → q) = T，即 p = T 且 p → q = T；但 p = T、q = F 時 p → q = F，矛盾，所以它不可能為假。

DNF 與 CNF

任何公式都能改寫成兩種標準形式，方便比較、化簡和交給電腦處理。先定義 literal（文字）：一個變數或它的否定，例如 p、¬q。

  • Disjunctive Normal Form（析取範式，DNF）：好幾個「literal 的 ∧」用 ∨ 接起來，例如 (p ∧ ¬q) ∨ (¬p ∧ q ∧ r)。
  • Conjunctive Normal Form（合取範式，CNF）：好幾個「literal 的 ∨」用 ∧ 接起來，例如 (p ∨ q) ∧ (¬p ∨ r)。

從真值表直接寫出來：DNF 看最後一欄為 T 的列，每一列寫一個 ∧ 項（變數為 T 寫原樣、F 寫否定），再全部用 ∨ 接起來；CNF 看為 F 的列，每一列寫一個 ∨ 項（變數為 F 寫原樣、T 寫否定，讓那一列的這一項變成 F），再全部用 ∧ 接起來。以 p ↔ q 為例：

pqp ↔ qDNF 用的項CNF 用的項
TTTp ∧ q
TFF¬p ∨ q
FTFp ∨ ¬q
FFT¬p ∧ ¬q

得到 DNF：(p ∧ q) ∨ (¬p ∧ ¬q)，CNF：(¬p ∨ q) ∧ (p ∨ ¬q)，兩者都和 p ↔ q 等價（程式已逐列驗證）。這個構造方法也證明了一件重要的事：只用 ¬、∧、∨ 就能表示任何真值表，這叫 Functionally Complete（功能完備）。再用 De Morgan 把 ∨ 換成 ¬ 和 ∧，可知 {¬, ∧} 本身就完備；單獨一個 NAND（¬(p ∧ q)）也完備，所以晶片可以只用 NAND 閘做出所有電路。

n 個變數的真值表有 2n 列，每列可以自由填 T 或 F，所以互不等價的公式總共有 22n 種：2 個變數有 24 = 16 種，3 個變數就有 256 種。DNF、CNF 最差也要 2n 項，更精簡的化簡方法（卡諾圖）在布林代數那一章。

應用與比較

  • 邏輯電路：每個連接詞就是一個邏輯閘，T / F 對應高 / 低電位。化簡公式等於減少閘的數量，電路更便宜、更快。
  • 程式條件與搜尋條件：if (!(a && b)) 可以用 De Morgan 改成 if (!a || !b)；資料庫查詢 WHERE NOT (age >= 18 AND member = 1)、搜尋引擎的 AND / OR / NOT 也都是命題邏輯。C 的 &&、|| 還有「短路」：左邊已能決定結果就不算右邊，和本頁 eval() 的寫法一樣。
  • SAT 問題：給一個 CNF 公式，問它是否可滿足。這是第一個被證明為 NP-complete 的問題（Cook–Levin 定理），目前沒有已知的多項式時間演算法，真值表法要 2n 列。但實務上的 SAT solver 用大量剪枝技巧，能處理上百萬個變數的工業問題，用在硬體驗證、排程、軟體測試。

易錯點

  • p 為假時，p → q 也為假 → 前提為假時蘊含一律為真；p → q 只在 p 真 q 假時為假 例題
  • p → q 和它的逆命題 q → p 等價 → 和 p → q 等價的是逆否命題 ¬q → ¬p；逆命題和否命題彼此等價 例題
  • 「p only if q」翻成 q → p → only if 引出的是必要條件，是 p → q；「p if q」才是 q → p 例題
  • ¬(p ∧ q) ≡ ¬p ∧ ¬q → De Morgan 要把 ∧ 換成 ∨：¬(p ∧ q) ≡ ¬p ∨ ¬q 例題
  • → 有結合律，(p → q) → r ≡ p → (q → r) → → 沒有結合律；p → (q → r) ≡ (p ∧ q) → r，和 (p → q) → r 不等價 例題
  • p ∨ q ∧ r 從左算到右，讀成 (p ∨ q) ∧ r → ∧ 比 ∨ 優先，是 p ∨ (q ∧ r)；→ 的優先順序最低 例題
  • 可滿足就是恆真 → 可滿足只要至少一列為真；恆真要每一列都真 例題
