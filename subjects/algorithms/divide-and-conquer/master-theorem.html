Master Theorem 主定理比較樹根的 f(n) 和葉子的 n^(log_b a)，誰大誰決定答案

Ch2 Divide and Conquer 難度 master theorem recurrence recursion tree divide and conquer

分治遞迴式從哪裡來

Divide and Conquer（分治法）的演算法都長得很像：把大小 n 的問題切成 a 個小問題，每個小問題的大小是 n/b，遞迴解完之後再合併。把「切」和「合」花的時間記成 f(n)，執行時間就寫成一條 Recurrence（遞迴式）：

T(n) = a · T(n/b) + f(n)
        ↑     ↑         ↑
   子問題個數  每個子問題的大小  這一層自己做的事（分割 + 合併）

先看幾個一定會遇到的例子，每一個都可以直接讀出 a、b、f(n)：

演算法怎麼分遞迴式abf(n)
Merge sort切成左右兩半各自排序，再花線性時間合併T(n) = 2T(n/2) + Θ(n)22Θ(n)
Binary search和中間比一次，只往其中一半找T(n) = T(n/2) + Θ(1)12Θ(1)
分塊矩陣乘法n×n 矩陣切成 4 塊，要做 8 次 (n/2)×(n/2) 的乘法，再做矩陣加法T(n) = 8T(n/2) + Θ(n²)82Θ(n²)
Strassen同樣切 4 塊，但用巧妙的組合只做 7 次乘法，多做一些加減法T(n) = 7T(n/2) + Θ(n²)72Θ(n²)

注意 a 和 b 是兩件不同的事：a 是「遞迴呼叫幾次」，b 是「每次呼叫的問題縮小幾倍」。Binary search 雖然把陣列切成兩半，但只往其中一半走，所以 a = 1、b = 2；Merge sort 兩半都要排，所以 a = 2。很多人看到「切兩半」就寫 2T(n/2)，是第一個常見錯誤。

有了遞迴式之後，問題就變成「T(n) 到底是多少」。最一般的方法是 Substitution Method（代入法）：先猜答案，再用數學歸納法證明；或是畫 Recursion Tree（遞迴樹）把每一層的成本加起來。這兩種方法都要動手算，而考試最常見的分治遞迴式其實都長成 aT(n/b) + f(n) 這個固定形狀，所以有人把遞迴樹的加總「一次做完」，整理成可以直接套的結論，這就是 Master Theorem（主定理）。它的價值在於：只要比較兩個函數的大小，幾秒鐘就能寫出答案。

例如 Strassen 的答案是 Θ(nlog₂7) ≈ Θ(n2.807)，分塊乘法是 Θ(n³)。指數只差 0.193 看起來不多，但 n = 220（大約一百萬）時 n³ / n2.807 = 220 × 0.193 ≈ 14，也就是少做了一個數量級的工作；而這個差距完全來自「8 次乘法變 7 次」，也就是 a 從 8 變成 7。主定理會讓你一眼看出 a 才是關鍵。

遞迴樹：每層成本與葉子數

要理解主定理，先把 T(n) = aT(n/b) + f(n) 展開成一棵樹。樹根代表原問題，它自己花 f(n)；它有 a 個孩子，每個是大小 n/b 的子問題，各自花 f(n/b)；每個孩子又有 a 個孩子……一直到子問題大小變成常數為止。

三個關鍵數字

  • 第 i 層有 ai 個節點，每個子問題的大小是 n/bi，所以第 i 層的總成本是 ai · f(n/bi)。
  • 樹高是 logb n：大小每層除以 b，除到 1 要除 logb n 次。
  • 葉子數是 nlogb a：最底層是第 logb n 層，有 alogb n 片葉子。用換底公式 alogb n = nlogb a（兩邊取 logb 都等於 logb a · logb n），每片葉子成本是常數，所以葉子層總共 Θ(nlogb a)。

把所有層加起來就是 T(n)：

T(n) = Θ(n^(log_b a))  +  Σ (i = 0 到 log_b n − 1)  a^i · f(n / b^i)
       └─ 葉子層 ─┘        └──────── 內部節點每一層的成本 ────────┘

nlogb a 這個量很重要，我們把它的指數 e = logb a 叫做 臨界指數。它代表「如果每個節點都只花常數時間，光是葉子就有這麼多工作」。主定理整件事就是在問：樹根那層的 f(n) 和葉子那層的 ne，誰比較大、大多少。

三種形狀一目了然：

  • Merge sort：每層都是 32 = n，一共 6 = lg 32 + 1 層，總和 192 = n(lg n + 1)。每層一樣大，答案就是「每層成本 × 層數」= Θ(n lg n)。
  • Strassen：每層是上一層的 1.75 倍，越往下越重。光是葉子層 16807 就佔了總和 37851 的 44%，最底下兩層加起來佔 70%。總和由葉子決定：Θ(nlog₂7)。
  • 2T(n/2) + n²：每層只剩上一層的一半，越往下越輕。樹根的 1024 就佔了總和 2016 的 51%。總和由樹根決定：Θ(n²)。

相鄰兩層的比值為什麼是 a / bk？當 f(n) = nk，第 i 層成本是 ai (n/bi)k = nk (a/bk)i，是一個公比 r = a/bk 的等比數列。r > 1、r = 1、r < 1 恰好對應 k < e、k = e、k > e（因為 a = be），也就是主定理的三個 case。

看程式碼：逐層加總遞迴樹與直接遞迴
recursionTree()：n = b^L 時逐層印出每層成本
double f(double n, double k, int p) {
  return pow(n, k) * pow(log2(n), p);
}

double recursionTree(int a, int b, double k, int p, int L) {
  double n = pow(b, L), total = 0;
  for (int i = 0; i < L; i++) {
    double nodes = pow(a, i);              /* 第 i 層的節點數 */
    double size = n / pow(b, i);           /* 每個子問題的大小 */
    double level = nodes * f(size, k, p);  /* 這一層的總成本 */
    printf("  第 %d 層：%g 個 × f(%g) = %g\n", i, nodes, size, level);
    total += level;
  }
  double leaves = pow(a, L);               /* a^L = n^(log_b a) 片葉子，每片 T(1) = 1 */
  printf("  葉子：%g 個 × T(1) = %g\n", leaves, leaves);
  return total + leaves;
}
T()：照遞迴式直接算 T(n)
double T(double n, int a, int b, double k, int p) {
  if (n < b) return 1;                     /* T(1) = 1 */
  return a * T(n / b, a, b, k, p) + f(n, k, p);
}
Tsplit()：真的遞迴 a 次並數呼叫次數
long calls;
double Tsplit(long n, int a, int b, double k, int p) {
  calls++;
  if (n < b) return 1;
  double cost = f(n, k, p);                /* 這一層自己的分割、合併成本 */
  for (int j = 0; j < a; j++) cost += Tsplit(n / b, a, b, k, p);
  return cost;
}

三種寫法算出的 T(n) 完全一樣（程式裡逐一比對過）。Tsplit() 真的把問題分成 a 份去遞迴，順便數呼叫次數：merge sort 在 n = 65536 時呼叫 131071 次（= 2n − 1，就是遞迴樹的節點總數）；binary search 只呼叫 17 次（= lg n + 1，樹只有一條路徑）；Strassen 在 n = 256 時呼叫 6,725,601 次，等於 (79 − 1)/6，也就是 9 層、每層 7 倍的等比級數總和。

主定理的三種情況

設 a ≥ 1、b > 1 是常數，f(n) 是漸近為正的函數，T(n) = aT(n/b) + f(n)（n/b 取上高斯或下高斯都可以，不影響答案）。令 e = logb a：

case 1：若 f(n) = O(n^(e − ε))，某個常數 ε > 0          → T(n) = Θ(n^e)
case 2：若 f(n) = Θ(n^e)                                → T(n) = Θ(n^e · lg n)
case 3：若 f(n) = Ω(n^(e + ε))，某個常數 ε > 0
        而且 a·f(n/b) ≤ c·f(n)，某個常數 c < 1，n 夠大  → T(n) = Θ(f(n))

case 1：葉子主導

f(n) 比 ne 小了一個多項式倍 nε。每層成本越往下越大，是遞增的等比級數，總和是最後一項（葉子層）的常數倍，所以 T(n) = Θ(ne)。例：9T(n/3) + n，e = log₃9 = 2，f = n = O(n2 − 1)，ε = 1，答案 Θ(n²)。程式驗算 T(n)/n² 從 n = 81 的 1.494 收斂到 1.500，比值固定，表示真的是 Θ(n²)。

case 2：每層一樣大

f(n) 和 ne 同階。每層成本都是 Θ(ne)，共有 logb n + 1 層，答案就是 ne 再乘一個 lg n。Merge sort（e = 1、f = n）得 Θ(n lg n)；binary search（e = log₂1 = 0、f = 1 = n⁰）得 Θ(lg n)。程式驗算 binary search 的 T(220) = 21 = lg n + 1，正是層數。

case 3：樹根主導

f(n) 比 ne 大了一個多項式倍。每層越往下越小，是遞減的等比級數，總和是第一項（樹根）的常數倍，所以 T(n) = Θ(f(n))。例：2T(n/2) + n²，e = 1，f = n² = Ω(n1+1)，答案 Θ(n²)；程式算出 T(n)/n² 收斂到 2，就是等比級數 1 + 1/2 + 1/4 + … 的和。

正則條件：case 3 多出來的那一句

case 3 除了「f 夠大」，還要求 Regularity Condition（正則條件）：a·f(n/b) ≤ c·f(n)，c 是小於 1 的常數。翻成遞迴樹的語言，a·f(n/b) 是第 1 層的總成本、f(n) 是第 0 層，這條件就是在說「下一層一定比這一層小一個固定比例」，這樣每層成本才會像等比級數一樣衰減，總和才會被樹根壓住。光有 f = Ω(ne+ε) 只保證樹根比葉子大，不保證中間每一層都乖乖變小；如果 f 忽大忽小（在某些 n 特別大、某些 n 特別小），中間的層可能反而比較重，就不能說總和是 Θ(f(n))。

好消息是：對考試常見的 f(n) = nk lgp n，只要 k > e，正則條件一定成立。因為 a·f(n/b) = a(n/b)k lgp(n/b) = (a/bk) · nk lgp(n/b)，而 k > e 代表 bk > be = a，所以 a/bk < 1。p ≥ 0 時 lgp(n/b) ≤ lgp n，直接取 c = a/bk；p < 0 時 lgp(n/b) / lgp n 會隨 n 變大趨近 1，取一個介於 a/bk 和 1 之間的 c 即可。考試要求「驗證正則條件」時，就把 c 寫出來。

例：3T(n/4) + n lg n。e = log₄3 ≈ 0.792，f = n lg n = Ω(n0.792 + 0.2)，ε 取 0.2 就好。正則條件：3 · (n/4) lg(n/4) ≤ (3/4) n lg n，c = 3/4 < 1，成立。所以 T(n) = Θ(n lg n)。

一句話記憶：比 f(n) 和 nlogb a。葉子大取葉子、樹根大取樹根、一樣大多乘一個 lg n；「大」一定要大一個多項式 nε，樹根大時再檢查正則條件。

看程式碼：計算臨界指數並判斷 case
critExp()、masterCase()：f(n) = n^k lg^p n 時判斷落在哪個 case
#define EPS 1e-9

double critExp(int a, int b) {
  return log(a) / log(b);
}

int masterCase(int a, int b, double k, int p) {
  double e = critExp(a, b);
  if (k < e - EPS) {                       /* f 比 n^e 小了一個多項式倍：葉子主導 */
    printf("case 1：T(n) = Θ(n^%.3f)\n", e);
    return 1;
  }
  if (k > e + EPS) {                       /* f 比 n^e 大了一個多項式倍：樹根主導 */
    double c = a / pow(b, k);              /* 正則條件：a·f(n/b) ≤ c·f(n)，c = a / b^k < 1 */
    printf("case 3（c = %.3f < 1）：T(n) = Θ(n^%g lg^%d n)\n", c, k, p);
    return 3;
  }
  if (p >= 0) {                            /* 同階：每層差不多一樣大，再乘上層數 lg n */
    printf("case 2：T(n) = Θ(n^%.3f lg^%d n)\n", e, p + 1);
    return 2;
  }
  printf("不能套用：f = n^%.3f / lg^%d n 落在 case 1 和 case 2 之間\n", e, -p);
  return 0;
}

程式裡比較 k 和 e 時用 EPS = 10−9 容許浮點誤差：log₂4 用浮點數算可能是 1.9999999999，直接用 == 比會誤判成 case 1。

動手操作

輸入 a、b 和 f(n) = nk lgp n 的 k、p（例如 merge sort 是 a = 2、b = 2、k = 1、p = 0；p = −1 代表 n / lg n），動畫會取 n = b⁵，一層一層畫出遞迴樹：框內是子問題大小，中間是「節點數 × 每個成本」，右邊長條是這一層的總成本，長條的長短變化就是三種 case 的形狀。最後比較 k 和 logb a，判斷落在哪個 case、寫出答案；落在空隙時會說明為什麼不能套用。某一層節點太多畫不下時，整層用一個長框代表，框內寫出節點數和子問題大小。

用程式驗證：T(n) / 答案 會趨近常數

Θ 的意思是「T(n) 和答案只差常數倍」。所以驗證方法很直接：把 T(n) 實際算出來，除以主定理給的答案 g(n)，看 n 變大時比值是否穩定在某個常數。下表是程式（T(1) = 1）算出的 T(n)/g(n)：

遞迴式g(n)n = 2⁸n = 2¹⁶n = 2²⁴收斂到
2T(n/2) + nn lg n1.1251.0631.0421（多出來的是葉子層的 n，佔 1/lg n）
7T(n/2) + n²nlog₂72.3182.3332.3337/3（等比級數 Σ(4/7)j = 7/3）
2T(n/2) + n²n²1.9962.0002.0002（等比級數 Σ(1/2)i = 2）

比值穩定，就代表答案的「階」是對的。如果把 Strassen 誤答成 Θ(n³)，比值會是 2.333 / n0.193，n 每大 2⁸ 倍就縮小約 2.9 倍，一路趨近 0，馬上就看得出錯。

看程式碼：主定理的答案 g(n)
answer()：主定理給的 g(n)，用來算 T(n)/g(n)
double answer(int a, int b, double k, int p, double n) {
  double e = critExp(a, b), lg = log2(n);
  if (k < e - EPS) return pow(n, e);
  if (k > e + EPS) return f(n, k, p);
  if (p >= 0) return pow(n, e) * pow(lg, p + 1);
  if (p == -1) return pow(n, e) * log2(lg);  /* 空隙裡的 n^e / lg n：Θ(n^e lg lg n) */
  return pow(n, e);                          /* p < -1：每層成本加起來收斂，Θ(n^e) */
}

延伸的 case 2：多了 lg 的次方

三個 case 的標準版本有一個明顯的漏洞：2T(n/2) + n lg n。這裡 e = 1，f = n lg n 比 n 大，但只大了 lg n 倍，不是多項式倍（對任何 ε > 0，lg n 最後都比 nε 小），所以不符合 case 3；它也不是 Θ(n)，不符合 case 2。這類 f 很常見，所以 case 2 有一個一般化的版本：

延伸 case 2：若 f(n) = Θ(n^e · lg^p n)，p ≥ 0   → T(n) = Θ(n^e · lg^(p+1) n)

p = 0 就是原本的 case 2。為什麼多乘一個 lg n？看遞迴樹的第 i 層：ai · (n/bi)e · lgp(n/bi) = ne · lgp(n/bi)，因為 ai = (bi)e 剛好抵掉。lg(n/bi) 從最上面的 lg n 一層一層變小到常數，令 j = logb(n/bi)，總和大約是：

n^e · Σ (j = 1 到 log_b n) (j · lg b)^p  ≈  n^e · (lg b)^p · (log_b n)^(p+1) / (p + 1)  =  Θ(n^e · lg^(p+1) n)

所以 2T(n/2) + n lg n = Θ(n lg² n)，4T(n/2) + n² lg n = Θ(n² lg² n)。程式驗算這兩個的 T(n) / (ne lg² n) 都從 0.578（n = 2⁸）降到 0.523（n = 2²⁴），往 1/2 收斂，正好是上式的 1/(p + 1)。

p 是負數呢？

同樣的加總在 p < 0 時也算得出來，只是答案的形狀不一樣，這兩種不在延伸 case 2 的範圍內，要自己用遞迴樹算：

f(n)每層成本加總結果程式驗算

ne / lg n（p = −1）Σ 1/j 是調和級數 ≈ ln(log n)Θ(ne lg lg n)2T(n/2) + n/lg n 對 n lg lg n 的比值 1.24 → 1.04（n = 2⁸ → 2²⁴），慢慢穩定

直覺上：p 越負，f 越小，越靠近 case 1。p < −1 時 f 已經小到每層加起來不會比葉子多，答案和 case 1 一樣是 Θ(ne)；p = −1 剛好卡在邊界，多出一個長得極慢的 lg lg n（n = 232，大約 43 億，lg lg n 也才 5）。

主定理不能用的情況

主定理只是「aT(n/b) + f(n) 這個形狀的遞迴樹」的整理結果，條件不符時直接套會得到錯的答案。考試很喜歡出「下列哪個不能用主定理」，常見的有下面幾類。

1. f(n) 落在空隙裡

最經典的是 T(n) = 2T(n/2) + n / lg n。e = 1，f = n/lg n 比 n 小，看起來像 case 1，但 case 1 要求 f = O(n1−ε)，也就是小一個多項式倍 nε；n/lg n 只比 n 小 lg n 倍，而 lg n 比任何 nε 都長得慢，所以不成立。它也不是 Θ(n)。這時用遞迴樹：第 i 層成本 2i · (n/2i) / lg(n/2i) = n / (lg n − i)，加總得到 n · (1/lg n + 1/(lg n − 1) + … + 1/1) = n · Hlg n，調和數 Hm ≈ ln m，所以 T(n) = Θ(n lg lg n)。

同理，在只有三個標準 case 的版本裡，2T(n/2) + n lg n 落在 case 2 和 case 3 之間的空隙，要靠上一節的延伸 case 2 才能處理。題目若說「用主定理（三種情況）」，遇到它要回答不能直接套用，再用延伸版或遞迴樹算出 Θ(n lg² n)。

2. 形狀不是 aT(n/b) + f(n)

遞迴式不能套的原因改用的方法與答案
T(n) = T(n/3) + T(2n/3) + n子問題大小不一樣，沒有單一的 b遞迴樹：每層總成本 ≤ n，最長路徑 log3/2 n 層，最短 log₃ n 層 → Θ(n lg n)
T(n) = n · T(n/2) + na = n 不是常數不能套，要另外展開分析
T(n) = 0.5 · T(n/2) + na < 1，「半個子問題」沒有意義不符合前提
T(n) = T(n − 1) + n是「減掉常數」不是「除以 b」展開：n + (n−1) + … + 1 → Θ(n²)
T(n) = 2T(n − 1) + 1同上每層節點數加倍，共 n 層 → Θ(2n)
T(n) = 2T(√n) + lg n不是除以常數 b變數代換 m = lg n，S(m) = T(2m) 滿足 S(m) = 2S(m/2) + m，S(m) = Θ(m lg m)，所以 T(n) = Θ(lg n · lg lg n)

反過來也要注意：f(n) 不是多項式不代表不能用。例如 T(n) = 2T(n/2) + 2n，f = 2n 遠大於 n1+ε，正則條件 2 · 2n/2 ≤ c · 2n 在 n 夠大時對 c = 1/2 成立，所以是 case 3，T(n) = Θ(2n)。判斷能不能用，看的是三個條件，不是 f 長得像不像多項式。

3. 不必擔心的事：取整數

實際的 merge sort 是 T(⌈n/2⌉) + T(⌊n/2⌋) + Θ(n)，兩個子問題差 1。這種上下高斯的差異不影響漸近結果，主定理照樣適用，答案還是 Θ(n lg n)。

和代入法、遞迴樹的關係

三種解遞迴式的方法不是互相取代，而是分工合作：

方法做什麼優點缺點
主定理比較 f(n) 和 nlogb a，直接讀答案最快，幾秒鐘寫出答案只適用 aT(n/b) + f(n)，有空隙
遞迴樹畫出每層成本再加總任何形狀都能畫，直覺清楚，常用來「猜」答案加總不嚴謹時只能當猜測
代入法猜一個答案，用數學歸納法證明最嚴謹，可以證明任何猜對的答案要先猜得到；歸納時常數要處理好

主定理其實就是預先算好的遞迴樹：三個 case 對應等比級數遞增、每項相等、遞減三種加總結果，正則條件就是保證「遞減」的那一句。所以忘記公式時，畫遞迴樹重推一遍一定推得出來，這也是本頁動畫的設計方式。

考題若要求「證明」或「用代入法」，就要把主定理得到的答案拿去做歸納。例如證明 2T(n/2) + n = O(n lg n)：假設對比 n 小的值 T(m) ≤ c·m lg m 都成立，則

T(n) ≤ 2 · c(n/2) lg(n/2) + n
     = c·n lg n − c·n + n
     ≤ c·n lg n          （只要 c ≥ 1）

最後一步要寫出「−cn + n ≤ 0」才算完整，這正是代入法最常被扣分的地方：歸納的結論必須和假設的形式完全一樣（c·n lg n），寫成 c·n lg n + n 就不能說證完了。基底情況則選 n = 2、3 這種 lg n > 0 的小值，用常數 c 夠大蓋過去。

遞迴樹與代入法的完整寫法會在「Substitution and Recursion-Tree Methods 代入法與遞迴樹」這個主題頁詳細說明（籌備中）。

易錯點

  • Binary search 切兩半，所以是 2T(n/2) + 1 → a 是遞迴呼叫的次數；binary search 只往一半走，是 T(n/2) + 1 = Θ(lg n) 例題
  • f(n) = n² 比較大，所以 4T(n/2) + n 的答案是 Θ(n) → 要比的是 f 和 nlogb a，不是 f 和 n；log₂4 = 2，葉子 n² 主導，答案 Θ(n²) 例題
  • case 2 的答案是 Θ(f(n)) → 每層一樣大、共 log n 層，要多乘一個 lg n：Θ(ne lg n) 例題
  • case 3 只要 f 比 ne 大就好 → 要大一個多項式倍，而且要驗證正則條件 a·f(n/b) ≤ c·f(n)、c < 1 例題
  • n/lg n 比 n 小，所以 2T(n/2) + n/lg n 是 case 1 → 只小了 lg n 倍不是多項式倍，落在空隙；用遞迴樹得 Θ(n lg lg n) 例題
  • T(n/3) + T(2n/3) + n 也能套主定理 → 子問題大小不同就沒有單一的 b，要用遞迴樹（或代入法） 例題
  • T(√n) 型的遞迴式沒辦法處理 → 令 m = lg n 做變數代換，就變回 aS(m/b) + g(m) 的形狀 例題
