P, NP, and NP-Completeness P、NP 與 NP 完備好驗證的問題，是不是都好解？

Ch12 NP-Completeness 難度 P NP NP-complete reduction co-NP

為什麼要分類問題：決策問題與輸入大小

前面學的排序、最短路徑、LCS 都有多項式時間的演算法，n 變大時時間只是 n²、n³ 這樣慢慢長。但有一大群問題，例如「排一條經過每個城市恰好一次的最短路線」「把一堆數字分成總和相等的兩堆」，幾十年來沒有人找到多項式時間的解法，也沒有人證明它們一定沒有。NP 完備理論做的事，就是把這些問題分類：哪些已知簡單、哪些「一樣難」、哪些只要解掉一個其他全部跟著解掉。考研的這一章幾乎都是是非判斷題，觀念一錯就整串推論都錯，所以下面每個定義都要記準。

決策問題 vs 最佳化問題

複雜度類別（P、NP……）只收 Decision Problem（決策問題）：答案只有 yes 或 no 的問題。我們平常遇到的多半是 Optimization Problem（最佳化問題），要先把它改寫成「有沒有一個解，好到某個門檻 k」：

最佳化版本決策版本
求圖 G 最小的點覆蓋G 有沒有大小 ≤ k 的點覆蓋？
求 s 到 t 的最短路徑長s 到 t 有沒有長度 ≤ k 的路徑？
求最短的旅行推銷員路線有沒有總長 ≤ k、經過每個城市一次的迴路？
0/1 背包的最大價值能不能在重量 ≤ W 下讓價值 ≥ k？

兩個版本的難度關係：

  • 決策版本不會比較難：會解最佳化，就算出最佳值再跟 k 比一次。所以「最佳化版本有多項式解」⇒「決策版本有多項式解」。
  • 反過來通常也行：最佳值通常介於 0 和一個多項式位元數的上限之間，對 k 做二分搜尋，呼叫決策版本 O(log 上限) 次就能找出最佳值。所以對這些常見問題來說，兩個版本「同時在 P 或同時不在」。
  • 差別在分類：最佳化版本不是 yes/no 問題，不屬於 NP，最多只能說它是 NP-hard。這是「NP-hard 不一定在 NP 裡」最常見的例子。

多項式要對「輸入長度」算

「多項式時間」裡的 n 是輸入編碼的長度（多少個位元或符號），不是題目裡某個數字的大小。一張圖的輸入長度和點數、邊數同階；但一個整數 W 只要 ⌈log₂(W + 1)⌉ 個位元就寫得下。這一點會直接決定「背包問題的 O(nW) 算不算多項式」，最後一節再細講。

P：多項式時間可以解

P（Polynomial time）：存在一個確定性演算法，對任何長度 n 的輸入都能在 O(nc) 時間（c 是常數）內正確回答 yes 或 no 的決策問題所成的集合。

為什麼用「多項式」當作「有效率」的分界線？

  • 成長速度差太多：n = 50 時，n³ 是 125,000；2n 已經超過 1015，每秒算 10 億次也要 13 天左右。n 再加 10，n³ 只多了不到一倍，2n 卻變成 1024 倍。
  • 對組合封閉：多項式加、乘、代入多項式還是多項式。一個多項式演算法呼叫另一個多項式副程式多項式次，整體仍是多項式；這讓「歸約」可以一層一層串下去。
  • 和機器模型無關：RAM、圖靈機、各種合理的程式語言互相模擬只差多項式倍，所以「在不在 P」不會因為換一台電腦而改變。

P 裡的經典例子：排序、最短路徑（Dijkstra、Bellman-Ford）、最小生成樹、最大流與最小割、二分圖匹配、2-SAT、判斷質數（2002 年證明在 P）、線性規劃。注意 P 只收決策問題，嚴格說是「最短路徑的決策版本 ∈ P」，但考題常常直接說「shortest path is in P」，意思一樣。

有一個常被問的性質：P 對補集封閉。如果 A ∈ P，把演算法的 yes、no 對調，就得到解「A 的補集」的多項式演算法，所以 A 的補集也在 P。下一節會看到 NP 沒有這麼漂亮的性質。

NP：答案是 yes 時好驗證

NP（Nondeterministic Polynomial time）：決策問題 A ∈ NP，若存在一個多項式時間的確定性驗證器 V 和多項式 p，使得：輸入 x 的答案是 yes ⇔ 存在一個長度 ≤ p(|x|) 的 Certificate（證據、證書） y，讓 V(x, y) 接受。

白話：答案是 yes 的時候，有人可以拿出一個不太長的證據，你只要花多項式時間檢查它就能被說服。至於證據怎麼找出來，定義完全不管。以 SAT（Satisfiability，布林可滿足性問題）為例：給一個 CNF 公式，問有沒有一組 T/F 指派讓它為真。certificate 就是那組指派，驗證器把每個子句檢查一遍，時間和公式長度成正比。

定義裡有兩個容易漏掉的細節：

  • 不對稱：只有 yes 的時候需要有證據。答案是 no 時，任何 certificate 都必須被拒絕；但你手上某一個 certificate 被拒絕，不代表答案是 no，只代表那一個不對。
  • 證據要短：certificate 的長度必須是輸入長度的多項式，驗證器的時間也是。如果允許指數長的證據，什麼問題都能「驗證」，定義就沒意義了。

另一種說法：非確定性演算法

NP 名字裡的 N 是 nondeterministic，不是 non-。另一個等價的定義是：A 可以被一個多項式時間的非確定性演算法解。非確定性演算法分兩階段：

  1. choosing phase（猜）：每一步用 choice() 從幾個選項中「挑一個」，而且假設它總是挑到會成功的那一個（只要有的話）。挑出來的東西就是 certificate。
  2. checking phase（檢查）：確定性地檢查挑出來的東西是不是解，是就 SUCCESS，否則 FAILURE。

兩階段都在多項式時間內完成，問題就在 NP。寫成虛擬碼證明某問題 ∈ NP 時，要清楚寫出輸入、輸出、兩個階段，並分析時間。以「有沒有大小 k 的 clique」為例：choosing phase 對每個點 choice({放, 不放})，共 O(n)；checking phase 檢查選了 k 個點、而且每一對都相鄰，O(k²) ⊆ O(n²)，所以 CLIQUE ∈ NP。

P ⊆ NP

如果 A ∈ P，驗證器可以完全不看 certificate，直接用多項式演算法把答案算出來。所以 P ⊆ NP。真正沒解決的是另一個方向：NP ⊆ P 嗎？也就是「好驗證的問題，是不是都好解」？這就是 P vs NP 問題，目前沒有人證明 P = NP，也沒有人證明 P ≠ NP。大多數人相信 P ≠ NP，但考題問「已經被證明」的時候，這件事兩邊都不能選。

看程式碼：verifySAT() 驗證器
verifySAT()：照 certificate 逐子句檢查
int litValue(int l, const int x[]) {
  return l > 0 ? x[l] : !x[-l];
}

int verifySAT(const CNF *f, const int x[]) {
  for (int j = 0; j < f->m; j++) {
    int sat = 0;
    for (int k = 0; k < f->len[j] && !sat; k++) {
      steps++;
      if (litValue(f->lit[j][k], x)) sat = 1;   /* 有一個字面為真，這個子句就滿足 */
    }
    if (!sat) return 0;                           /* 有一個子句全假：這組指派不行 */
  }
  return 1;                                       /* 每個子句都滿足：接受 */
}

動手操作：驗證 vs 暴力求解

驗證和求解差多少，自己跑一次最清楚。下面的動畫對同一個公式做兩件事：先拿 certificate 交給 verifySAT() 逐子句檢查，再用 bruteSAT() 從 00…0 開始把 2n 組指派一組一組試，每組都要整個再驗證一次。下方會累計兩者「看過的字面數」，這是兩個做法共同的基本動作，拿來比較最公平。

公式的寫法：每個子句用括號包起來，字面寫 x1～x4，否定在前面加 !（或 ¬），子句內用 |（或 ∨）隔開，例如 (x1|!x2)(!x1|x3)；最多 4 個變數、6 個子句，每個子句最多 3 個字面。certificate 依序寫 x1、x2、… 的值（1 是 T、0 是 F）；留白就只跑暴力法。按「certificate 給錯」可以看到：驗證器拒絕了，暴力法卻還是找得到解；按「不可滿足」則會看到暴力法非得試完全部 8 組才能說 no。

看程式碼：bruteSAT() 暴力枚舉
bruteSAT()：試遍 2^n 組指派
int bruteSAT(const CNF *f, int x[]) {
  for (long mask = 0; mask < (1L << f->n); mask++) {
    for (int i = 1; i <= f->n; i++)
      x[i] = (mask >> (f->n - i)) & 1;
    if (verifySAT(f, x)) return 1;                /* 找到一組可以滿足的指派 */
  }
  return 0;                                       /* 2^n 組全部失敗：不可滿足 */
}

co-NP：答案是 no 時好驗證

把決策問題 A 的 yes、no 對調，得到它的補集 Ā。co-NP（NP 的補集類別） = { A : Ā ∈ NP }，也就是「答案是 no 的時候有簡短證據」的問題。

問題yes 時有沒有短證據no 時有沒有短證據已知類別
SAT：公式可滿足嗎？有：一組指派不知道NP（NP-complete）
UNSAT：公式不可滿足嗎？不知道有：一組讓它為真的指派co-NP
TAUTOLOGY：公式永遠為真嗎？不知道有：一組讓它為假的指派co-NP
COMPOSITE：n 是合數嗎？有：一個因數有：質數證明P（因此也在 NP ∩ co-NP）

要記的關係：

  • P ⊆ NP ∩ co-NP：A ∈ P ⇒ Ā ∈ P ⊆ NP，所以 A ∈ co-NP。
  • NP = co-NP 嗎？未知。大家相信不相等。若 P = NP，因為 P 對補集封閉，會推出 NP = co-NP；但反過來不成立，NP = co-NP 不能推出 P = NP。
  • 若某個 NP-complete 問題在 co-NP 裡，則 NP = co-NP。理由：任何 B ∈ NP 都能歸約到它，而 co-NP 對多項式歸約封閉（B ≤p C 且 C ∈ co-NP ⇒ B ∈ co-NP），所以 NP ⊆ co-NP，兩邊取補集又得 co-NP ⊆ NP。因此「有一個 NPC 問題的補集也是 NPC」目前不能說是對的。

多項式時間歸約：比較兩個問題誰比較難

Polynomial-time Reduction（多項式時間歸約） A ≤p B：存在一個多項式時間可計算的函數 f，把 A 的每個輸入 x 轉成 B 的輸入 f(x)，而且 x 是 A 的 yes ⇔ f(x) 是 B 的 yes。

讀法：「A 歸約到 B」「A 可以化成 B」，意思是A 不比 B 難（最多差一個多項式的轉換成本）。記方向最好的方法是想「≤」：A 在小的那邊。從定義直接得到下面幾條推論，有的對、有的是常見的陷阱：

已知 A ≤p B成立嗎理由
B ∈ P ⇒ A ∈ P成立算 f(x)（多項式），再用 B 的演算法；f(x) 的長度也是多項式，代進多項式還是多項式
A 是 NP-hard ⇒ B 是 NP-hard成立任何 NP 問題 ≤p A ≤p B，歸約可以串接
A ∈ P ⇒ B ∈ P不成立簡單的問題可以歸約到很難的問題，例如任何 P 問題都能歸約到 SAT
B 是 NP-hard ⇒ A 是 NP-hard不成立同上，A 可能很簡單
B ∈ NP ⇒ A ∈ NP成立A 的驗證器：先算 f(x)，再用 B 的驗證器檢查

遞移性：A ≤p B、B ≤p C ⇒ A ≤p C，因為兩個多項式函數合成還是多項式。考題常給一串 A ≤p B ≤p C ≤p D 加上幾個已知條件，要你推出誰是 NP-hard、誰在 NP；做法就是「難度往箭頭方向傳、容易往箭頭反方向傳」。

另外有一種比較寬的歸約（Turing／Cook 歸約）：「可以用解 B 的多項式演算法當副程式，在多項式時間內解 A」。有的考卷就用這種定義。對「在不在 P」的推論，兩種定義結論一樣；只是它允許呼叫很多次、也允許把答案反過來，所以碰到 NP 和 co-NP 的區別時要用上面那種（Karp）定義。

簡單例子：Independent Set ≤p Vertex Cover

在無向圖 G = (V, E) 中，Independent Set（獨立集） S 是一組兩兩不相鄰的點；Vertex Cover（點覆蓋） C 是一組點，讓每條邊都至少有一個端點在 C 裡。關鍵觀察：S 是獨立集 ⇔ V − S 是點覆蓋。因為「每條邊最多一個端點在 S」和「每條邊至少一個端點不在 S」是同一句話。

所以歸約函數 f 只要把 (G, k) 變成 (G, n − k)：「G 有大小 k 的獨立集」⇔「G 有大小 n − k 的點覆蓋」。轉換只改一個數字，O(1) 時間。以圖 2 為例，n = 6：最大獨立集大小是 2（每個三角形最多選一點），所以最小點覆蓋大小是 6 − 2 = 4；想選 {a, d, e} 當獨立集就不行，因為 d、e 相鄰。程式把 5 個點的所有 1024 張圖、每個 k 都檢查了一遍，6,144 組答案完全一致。同樣的想法反過來也成立（VC ≤p IS），再加上「G 的獨立集 = 補圖的 clique」，三個問題其實是同一個問題的三種說法。更多的歸約技巧（3-SAT → CLIQUE、VC → HAM-CYCLE 這類需要「零件」的構造）放在 NP-Completeness Reductions 這一頁（籌備中）。

看程式碼：獨立集、點覆蓋的檢查與歸約
reduceISToVC()：只改門檻
void reduceISToVC(const Graph *g, int k, Graph *h, int *k2) {
  *h = *g;          /* 圖完全不用改 */
  *k2 = g->n - k;   /* 只改門檻：O(1)，當然是多項式時間 */
}
isIndependentSet() / isVertexCover()
int isIndependentSet(const Graph *g, const int in[]) {
  for (int u = 0; u < g->n; u++)
    for (int v = u + 1; v < g->n; v++)
      if (g->adj[u][v] && in[u] && in[v]) return 0;   /* 這條邊的兩端都在 S 裡 */
  return 1;
}

int isVertexCover(const Graph *g, const int in[]) {
  for (int u = 0; u < g->n; u++)
    for (int v = u + 1; v < g->n; v++)
      if (g->adj[u][v] && !in[u] && !in[v]) return 0; /* 這條邊兩端都不在 C 裡 */
  return 1;
}

NP-hard 與 NP-complete

NP-hard（NP 難）：每一個 NP 問題都 ≤p X。
NP-complete（NP 完備，NPC）：X ∈ NP 而且 X 是 NP-hard。

NP-hard 只說「至少和 NP 裡最難的一樣難」，沒有要求 X 在 NP 裡。X 甚至可以不是決策問題（例如 TSP 的最佳化版本），或根本不可判定（例如停機問題：任何 NP 問題都能歸約到它，但它不在 NP，所以是 NP-hard 不是 NPC）。NPC 是 NP 和 NP-hard 的交集，是 NP 裡「最難的那一群」。

NPC 的核心性質

  • 任何 NPC 問題都能歸約到任何 NPC 問題：X 是 NPC 所以 X ∈ NP；Y 是 NPC 所以每個 NP 問題（包括 X）都 ≤p Y。所有 NPC 問題在多項式歸約下「一樣難」。
  • 只要一個 NPC 問題在 P，就 P = NP：任何 NP 問題 ≤p 那個 NPC 問題 ∈ P，所以都在 P。反過來，只要一個 NPC 問題被證明不在 P，就 P ≠ NP，而且這時所有 NPC 問題都不在 P。
  • 若 P ≠ NP，P 和 NPC 不相交：P 裡的問題不會是 NP-hard，否則所有 NP 問題都能多項式解。所以「已知在 P 的問題」不能再勾 NP-hard 或 NPC。
  • 若 P ≠ NP，NP 裡還有既不在 P、也不是 NPC 的問題（這是一個已證明的定理）；整數分解、圖同構常被當作候選，但它們到底屬於哪一類目前未知。

怎麼證明一個問題 X 是 NP-complete

  1. 證明 X ∈ NP：說明 certificate 是什麼、驗證器怎麼在多項式時間檢查（或寫出多項式時間的非確定性演算法）。
  2. 挑一個已知的 NPC 問題 Y，證明 Y ≤p X：給出轉換 f，證明 f 是多項式時間，並證明「y 是 yes ⇔ f(y) 是 yes」兩個方向。

第 2 步方向最容易寫反：是把已知很難的化成新問題，代表新問題至少一樣難。如果寫成 X ≤p Y，只說明 X 不比 Y 難，什麼都證明不了（連排序都能 ≤p SAT）。另外，只做第 2 步得到的是 NP-hard；少了第 1 步就不能說 NPC。

和近似演算法的關係（簡述）

歸約保留的是 yes/no 的答案，不保留近似的好壞。所以同樣是 NPC 的決策版本，最佳化時可能差很多：點覆蓋有簡單的 2 倍近似；一般（不滿足三角不等式的）TSP 若 P ≠ NP 就沒有任何常數倍近似；背包問題甚至可以近似到任意接近 1。細節在 Vertex Cover Approximation 這一頁（籌備中）。

Cook–Levin 定理與常見的 NP-complete 問題

用「已知的 NPC 問題 ≤p X」來證明，需要有第一個 NPC 問題。Cook–Levin Theorem（Cook–Levin 定理）就是這個起點：SAT 是 NP-complete。它的證明直接從 NP 的定義下手，把「非確定性機器在多項式步內接受 x」的整個計算過程寫成一個多項式大小的布林公式，公式可滿足 ⇔ 機器接受，因此每個 NP 問題都 ≤p SAT。考研只要知道它的陳述和意義，不會要求證明。

之後的 NPC 證明都是一條歸約鏈：SAT ≤p 3-SAT ≤p CLIQUE ≤p VERTEX-COVER ≤p HAM-CYCLE ≤p TSP，3-SAT ≤p SUBSET-SUM 等等。下表是考題最常出現的 NPC 問題，旁邊放了長得很像、但在 P 裡的版本，因為判斷題最愛拿這些對照組出題：

NP-complete（決策版本）相近但在 P 的版本差在哪裡

還有一個陷阱：「u 到 v 有沒有長度 k 的路徑」要看路徑能不能重複走點。要求簡單路徑時，k = n − 1 就是 Hamiltonian path，是 NPC；如果允許重複點（walk），可以用 DP 或鄰接矩陣的次方在多項式時間判斷。

判斷題口訣：先問「它是決策問題嗎」，再問「已知在 P 嗎」，最後問「有沒有已知 NPC 問題能歸約到它」。已知在 P 的，在 P、NP、co-NP，不是 NP-hard（假設 P ≠ NP）；NPC 的，在 NP、是 NP-hard，不知道在不在 co-NP。

偽多項式時間：背包的 O(nW) 不算多項式

0/1 背包和 SUBSET-SUM 是 NPC，可是動態規劃可以在 O(nW)（或 O(nT)，T 是目標總和）時間解出來。這不是證明了 P = NP 嗎？不是，因為W 不是輸入長度。W 用二進位只要 b = ⌈log₂(W + 1)⌉ 個位元，所以 O(nW) = O(n · 2b)，對輸入長度來說是指數。這種「對數值大小是多項式、對位元數是指數」的時間叫 Pseudo-polynomial Time（偽多項式時間）。

以 SUBSET-SUM 的 DP 為例，can[s] 表示能不能湊出總和 s，每多考慮一個數就由大到小更新一次。集合 {5, 8, 13, 4, 7}、T = 20 時答案是 yes（13 + 7），總共更新 68 格，非常快。但如果 T 換成很大的數，輸入只多幾個位元，表格卻暴增：

T 的位元數 bT 最大約表格約 n × T 格（n = 5）意義
101,0235,120一瞬間
201,048,575約 524 萬輸入只多 10 個位元，表格大 1024 倍
30約 10.7 億約 54 億再多 10 個位元，又大 1024 倍

所以考題問「O(nW) 的 0/1 背包演算法是多項式時間演算法嗎」，答案是不是。反過來，如果題目保證 W ≤ n² 之類的條件，O(nW) 就真的是多項式了。這也把 NPC 問題分成兩種：背包、SUBSET-SUM 這種「數字小就好解」的叫 weakly NP-complete；TSP、3-COLOR、CLIQUE 這種就算數字都很小（甚至沒有數字）也還是 NPC 的叫 strongly NP-complete。背包問題本身的 DP 填表放在 0/1 Knapsack 這一頁（籌備中）。

看程式碼：subsetSum() 偽多項式時間的 DP
subsetSum()：O(nT) 填表
int subsetSum(const int a[], int n, int T, long *cells) {
  char *can = calloc(T + 1, 1);
  can[0] = 1;                                      /* 什麼都不選，總和 0 */
  for (int i = 0; i < n; i++)
    for (int s = T; s >= a[i]; s--) {              /* 由大到小，每個數只用一次 */
      if (can[s - a[i]]) can[s] = 1;
      (*cells)++;
    }
  int r = can[T];
  free(can);
  return r;
}

易錯點

  • NP 是 non-polynomial，NP 問題一定要指數時間 → NP 是 nondeterministic polynomial：yes 的答案可以多項式時間驗證；P ⊆ NP，所以 NP 裡也有很簡單的問題 例題
  • 要證明 X 是 NP-hard，就把 X 歸約到某個 NPC 問題 → 方向相反：要證明「已知 NPC ≤p X」；X ≤p NPC 只說明 X 不比它難 例題
  • A ≤p B 且 A ∈ P，所以 B ∈ P → 容易的性質只會往箭頭反方向傳：B ∈ P ⇒ A ∈ P；A 簡單時 B 可以任意難 例題
  • NP-hard 的問題一定在 NP 裡 → NP-hard 不要求 ∈ NP；停機問題、最佳化版本都是 NP-hard 但不是 NPC 例題
  • 已知 NPC 問題 A ≤p B，所以 B 是 NPC → 只能推出 B 是 NP-hard；還要 B ∈ NP 才是 NPC 例題
  • certificate 被驗證器拒絕，答案就是 no → 只代表這一個 certificate 不對；答案是 no 要所有 certificate 都被拒絕 例題
  • 2-SAT、最短路徑、最小割也是 NPC，因為 3-SAT、最長路徑、最大割是 → 這些對照組都在 P；假設 P ≠ NP 時，在 P 的問題不是 NP-hard 例題
  • 0/1 背包有 O(nW) 的 DP，所以是多項式時間 → W 只占 log W 個位元，O(nW) 對輸入長度是指數，叫偽多項式時間 例題
  • 已經證明 NPC 問題沒有多項式演算法 → P vs NP 還沒解決；只能說「若 P ≠ NP 則沒有」 例題
