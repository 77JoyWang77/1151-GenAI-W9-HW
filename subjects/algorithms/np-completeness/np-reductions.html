NP-Completeness Reductions NP 完備歸約把已知的難題變成新問題：構造、證明兩個方向、算大小

Ch12 NP-Completeness 難度 reduction 3-SAT CLIQUE SUBSET-SUM HAM-CYCLE

從定義到證明：這一頁要學會什麼

P、NP、NP-hard、NP-complete 的定義和「A ≤p B 的方向」已經在 P、NP 與 NP 完備講過，這裡只用三句話複習：

  • 歸約 A ≤p B：一個多項式時間的轉換 f，使「x 是 A 的 yes ⇔ f(x) 是 B 的 yes」。意思是 B 至少和 A 一樣難（詳細定義）。
  • NP-complete = 在 NP 裡 ＋ NP-hard（定義與性質）。
  • 起點：Cook–Levin 定理說 SAT 是 NPC，之後的 NPC 問題都是從它一路歸約出來的（定理與常見 NPC 清單）。

那一頁回答的是「這些詞是什麼意思」；這一頁要回答考卷上更實際的問題：拿到一個新問題，怎麼證明它是 NP-complete？這需要兩種能力。第一是邏輯：看到「若 A ≤p B 則……」能立刻判斷對錯、知道該從哪個已知問題歸約過來。第二是構造：真的寫出轉換 f，再證明 yes 對 yes、no 對 no。考古題裡這兩類大約各占一半，構造題通常給 10～15 分，而且會要求「兩個方向都要證」。

下圖是這一頁會走過的歸約。每一條箭頭都是一個獨立的構造，學會之後，遇到新問題時可以從這張圖上挑一個「長得最像」的已知問題當起點。

證明 X 是 NP-complete 的固定格式：(1) X ∈ NP：說出 certificate 和多項式時間的驗證方法。(2) 挑一個已知 NPC 問題 Y，構造 f 使 Y ≤p X。(3) f 是多項式時間。(4) 正確性兩個方向：y 是 yes ⇒ f(y) 是 yes；f(y) 是 yes ⇒ y 是 yes。四項缺一不可。

推論題：A ≤p B 能推出什麼

選擇題最常給一串歸約加上幾個條件，問哪些敘述一定成立。只要記住一件事：歸約 A ≤p B 是「把 A 變成 B」，所以 B 會解 ⇒ A 就會解。由這一句可以推出所有規則：

已知 A ≤p B 和……可以推出推不出（常見陷阱）
A 是 NP-hardB 是 NP-hardB 是 NPC：還缺 B ∈ NP
A 是 NPCB 是 NP-hardB 是 NPC（B 可能是停機問題）
B ∈ P（或 NP、co-NP）A ∈ P（或 NP、co-NP）—
A ∈ P什麼都推不出B ∈ P：簡單的問題可以變成很難的問題
B 是 NP-hard什麼都推不出A 是 NP-hard：例如排序 ≤p SAT

一題走一遍

設 SAT ≤p X ≤p Y ≤p Z，而且 Y ∈ NP。逐一判斷：

  • 誰是 NP-hard：SAT 是 NP-hard，往右傳，X、Y、Z 都是。
  • 誰在 NP：Y ∈ NP，往左傳，X ∈ NP（SAT 本來就在）。Z 在箭頭右邊，不知道。
  • 誰是 NPC：X、Y 同時 ∈ NP 且 NP-hard，是 NPC；Z 只能說是 NP-hard。
  • 「若 Z ∈ P 則 P = NP」：成立。Z ∈ P 往左傳得 X ∈ P，X 是 NPC，所有 NP 問題都能多項式解。
  • 「若 X ∈ P 則 Z ∈ P」：不成立。X ∈ P 雖然推得 P = NP，但 Z 可能根本不在 NP（例如不可判定），P = NP 也救不了它。

三個進階細節

  • 歸約的速度也會傳過去：若 A 可以線性時間歸約到 B，B 有 O(N3) 演算法，那 A 也有 O(N3)，因為轉換後的輸入長度只有 O(N)，(cN)3 = O(N3)。但「B 沒有 O(N3) 演算法」推不出 P ≠ NP：B 可能只是比 NP 更難，A 也可能有 O(N4) 的解。
  • 不是每個 NPC 問題都能歸約到每個 NP 問題：NP 裡有兩個「平凡」的語言，∅（永遠答 no）和全部字串（永遠答 yes）。歸約必須把 yes 送到 yes，∅ 根本沒有 yes 可以送，所以 SAT 不可能歸約到 ∅。考題問「every NPC problem reduces to every problem in NP」時，答案是錯。
  • NP-hard 問題不一定能歸約到另一個 NP-hard 問題：停機問題是 NP-hard，但它不可判定，如果能歸約到 SAT（可判定），停機問題就能解了。NPC 之間可以互相歸約，是因為它們都在 NP 裡。

寫歸約證明的方法：先挑起點，再設計零件

格式在上面的 callout 裡，真正難的是第 (2) 步：要從哪個已知問題歸約過來？怎麼設計 f？常用的手法可以分成三類，難度由淺到深：

手法想法例子
Restriction（限制法）新問題 X 的某個特例就是已知的 NPC 問題，f 只要把 Y 的輸入「原封不動」或稍微改一下放進 XHAM-CYCLE → TSP（權重只有 1、2）；HAM-PATH → 長度 k 的簡單路徑（k = n − 1）；CLIQUE → HALF-CLIQUE（補點）
Local Replacement（局部替換）把 Y 的輸入的每個「小零件」換成一小塊等價的結構，各換各的SAT → 3-SAT（每個長子句換成一串短子句）；IS → VC（集合取補）
Gadget Design（零件設計）替變數、子句分別設計零件，讓「零件能不能拼起來」剛好對應「公式能不能滿足」3-SAT → CLIQUE、3-SAT → 3-COLOR、VC → SUBSET-SUM

怎麼挑起點：看新問題「長得像誰」。

  • 要從一堆東西裡挑一組、彼此有衝突限制（選點、選集合）：從 CLIQUE、INDEPENDENT-SET、VERTEX-COVER 來。
  • 要排一個順序、經過每個東西一次（路線、排程）：從 HAM-CYCLE、HAM-PATH 來。
  • 和數字加總有關（湊總和、分兩堆、背包）：從 SUBSET-SUM 來。
  • 其他都不像，或是限制條件很「邏輯」（真假、互斥、至少一個）：從 3-SAT 來，它結構最簡單，每個子句只有 3 個字面。

正確性證明的寫法也固定：(⇒) 從 Y 的一個解，具體構造出 f(y) 的一個解；(⇐) 從 f(y) 的任意一個解，反推出 Y 的一個解。(⇐) 比較難，因為你不能假設 f(y) 的解長成你想要的樣子，必須用構造的性質逼它就範（例如「同一個子句的點之間沒有邊，所以 clique 每個子句只能拿一個」）。只證 (⇒) 是最常被扣分的地方：這只說明 yes 送到 yes，沒有排除 no 也被送到 yes。

SAT → 3-SAT：把長子句拆開

Cook–Levin 給的是一般的 CNF（合取範式）公式（CNF 的寫法見命題邏輯），子句可以任意長。後面的構造都希望每個子句最多 3 個字面，零件才設計得出來，所以第一步先證明 3-SAT 也是 NPC。3-SAT ∈ NP 很明顯（certificate 是一組指派）；接下來用局部替換把 SAT 歸約到 3-SAT。

長度 ≤ 3 的子句不動。長度 k > 3 的子句 (l1 ∨ l2 ∨ … ∨ lk) 引入 k − 3 個新變數 y1, …, yk−3，換成一串 k − 2 個子句：

(l1 ∨ l2 ∨ y1)(¬y1 ∨ l3 ∨ y2)(¬y2 ∨ l4 ∨ y3) … (¬y(k−3) ∨ l(k−1) ∨ lk)

例如 6 個字面的子句變成 (x1 ∨ x2 ∨ y1)(¬y1 ∨ x3 ∨ y2)(¬y2 ∨ x4 ∨ y3)(¬y3 ∨ x5 ∨ x6)，4 個子句、3 個新變數。y 像一條「接力棒」：yi = T 表示「真的字面在更右邊，請後面負責」。

  • (⇒) 原子句被某個 li 滿足：li 左邊的 y 全設 T，右邊的 y 全設 F。左邊每個子句由結尾的 y 滿足，右邊每個子句由開頭的 ¬y 滿足，li 所在的子句由 li 自己滿足。
  • (⇐) 若原本的 l1…lk 全假：第一個子句逼 y1 = T，第二個子句因此逼 y2 = T……一路傳到最後一個子句 (¬yk−3 ∨ lk−1 ∨ lk) 全假。所以新的那串子句能被滿足，就代表原本的 l 至少一個為真。
  • 大小：每個長度 k 的子句變成 k − 2 個子句，新公式長度是原本的常數倍，線性時間。

如果題目要求「每個子句恰好 3 個字面」，短子句可以重複字面補齊（(x) 變成 (x ∨ x ∨ x)），或另外加兩個強迫為假的新變數。反過來要注意：2-SAT 在 P，同樣的拆法拆不成 2 個字面的子句，所以 3 是臨界點。

看程式碼：reduceSATTo3SAT()
reduceSATTo3SAT()：長子句換成一串 3 字面子句
void reduceSATTo3SAT(const CNF *f, CNF *g) {
  g->n = f->n; g->m = 0;
  for (int j = 0; j < f->m; j++) {
    const int *l = f->lit[j];
    int k = f->len[j];
    if (k <= 3) {                                   /* 本來就夠短，照抄 */
      g->len[g->m] = k;
      memcpy(g->lit[g->m++], l, sizeof(int) * k);
      continue;
    }
    int y = ++g->n;                                 /* 第一個新變數 y1 */
    int first[3] = { l[0], l[1], y };
    g->len[g->m] = 3; memcpy(g->lit[g->m++], first, sizeof first);
    for (int t = 2; t < k - 2; t++) {               /* 中間：(¬y ∨ l_t ∨ y') */
      int y2 = ++g->n;
      int mid[3] = { -y, l[t], y2 };
      g->len[g->m] = 3; memcpy(g->lit[g->m++], mid, sizeof mid);
      y = y2;
    }
    int last[3] = { -y, l[k - 2], l[k - 1] };       /* 最後：(¬y ∨ l_{k-1} ∨ l_k) */
    g->len[g->m] = 3; memcpy(g->lit[g->m++], last, sizeof last);
  }
}

3-SAT → CLIQUE：每個字面一個點

Clique（團）是一組兩兩相鄰的點。CLIQUE 問題：給圖 G 和 k，有沒有 k 個點的 clique？它在 NP（certificate 是 k 個點，檢查 O(k2) 對）。要證明 NP-hard，從 3-SAT 歸約。給有 m 個子句的 3-CNF 公式 φ：

  1. 點：每個子句的每個字面各畫一個點，點記得「我是哪個字面、在第幾個子句」。最多 3m 個點。
  2. 邊：兩個點相連 ⇔ 它們在不同子句，而且不互補（不是 xi 和 ¬xi）。
  3. 門檻：k = m。

直覺：一個 clique 就是「每個子句派一個代表，而且代表之間不吵架」。同一子句不連邊，所以最多每個子句一個代表；互補不連邊，所以代表們可以同時為真。

正確性的兩個方向

  • (⇒) φ 可滿足 ⇒ G 有 m-clique：取一組滿足指派，每個子句至少有一個字面為真，各挑一個，得到 m 個點。任兩個點在不同子句；兩者都為真，所以不可能一個是 x、一個是 ¬x。照連邊規則它們之間一定有邊，所以是 m-clique。
  • (⇐) G 有 m-clique ⇒ φ 可滿足：任取一個 m-clique。同一子句的點之間沒有邊，m 個點只能每個子句剛好一個；互補的點之間沒有邊，所以 clique 裡不會同時有 x 和 ¬x。把 clique 裡的字面全設為真（不會矛盾），沒出現的變數隨便設。每個子句都有一個真字面，φ 被滿足。

大小：N ≤ 3m 個點，檢查每一對點 O(N2) = O(m2)。圖 3 的公式有 9 個點、21 條邊：任兩個子句之間有 3 × 3 = 9 對，三對子句共 27 對，扣掉 6 對互補（例如 C1 的 x1 和 C2 的 ¬x1）。程式對 3000 個隨機公式（其中 580 個不可滿足）都確認「φ 可滿足 ⇔ G 有 m-clique」，也確認 (⇒)、(⇐) 兩個構造本身都正確。

換成獨立集只要把邊反過來

Independent Set（獨立集）是一組兩兩不相鄰的點。3-SAT → INDEPENDENT-SET 用同樣的點，連邊規則改成：同一子句的點兩兩相連（三角形，保證每個子句最多選一個）、互補的點相連（保證不會同時選 x 和 ¬x），k 一樣是 m。比較兩條規則會發現它們剛好是補集：「不同子句且不互補」的否定就是「同子句或互補」。所以這兩張圖互為補圖，圖 3 的公式在獨立集版本有 15 條邊，21 + 15 = 36 = C(9, 2)。

看程式碼：3-SAT → CLIQUE／獨立集
reduce3SATToClique()：不同子句、不互補才連
void literalVertices(const CNF *f, Graph *g, int lit[], int cls[]) {
  g->n = 0;
  for (int j = 0; j < f->m; j++)
    for (int t = 0; t < f->len[j]; t++) {
      lit[g->n] = f->lit[j][t];
      cls[g->n] = j;
      g->n++;
    }
}

void reduce3SATToClique(const CNF *f, Graph *g, int *k, int lit[], int cls[]) {
  literalVertices(f, g, lit, cls);
  for (int u = 0; u < g->n; u++)
    for (int v = 0; v < g->n; v++)
      g->adj[u][v] = u != v
                     && cls[u] != cls[v]            /* 不同子句才連 */
                     && lit[u] != -lit[v];          /* x 和 ¬x 不連 */
  *k = f->m;
}
reduce3SATToIS()：同子句或互補就連
void reduce3SATToIS(const CNF *f, Graph *g, int *k, int lit[], int cls[]) {
  literalVertices(f, g, lit, cls);
  for (int u = 0; u < g->n; u++)
    for (int v = 0; v < g->n; v++)
      g->adj[u][v] = u != v
                     && (cls[u] == cls[v]           /* 同一個子句：最多選一個 */
                         || lit[u] == -lit[v]);     /* x 和 ¬x：不能同時為真 */
  *k = f->m;
}
pickTrueLiterals()（⇒）／readAssignment()（⇐）
long pickTrueLiterals(const CNF *f, const Graph *g, const int x[], const int lit[], const int cls[]) {
  long s = 0;
  for (int j = 0; j < f->m; j++)
    for (int v = 0; v < g->n; v++)
      if (cls[v] == j && litValue(lit[v], x)) {
        s |= 1L << v;                               /* 子句 j 挑這個點 */
        break;                                      /* 每個子句只挑一個 */
      }
  return s;
}

void readAssignment(const CNF *f, const Graph *g, long s, const int lit[], int x[]) {
  for (int i = 1; i <= f->n; i++) x[i] = 0;         /* 沒被選到的變數：設成什麼都可以 */
  for (int v = 0; v < g->n; v++)
    if (s >> v & 1) x[abs(lit[v])] = lit[v] > 0;    /* x_i 為真設 1，¬x_i 為真設 0 */
}

動手操作：一步一步建出 CLIQUE 的圖

下面的動畫照上一節的規則建圖：先每個字面一個點，再一對一對子句地連邊，互補的點對會用紅色虛線標出來、然後不連。建完之後，動畫拿暴力法找到的滿足指派走一次 (⇒)：每個子句挑一個為真的字面，看它們兩兩相鄰；再拿暴力法找到的任意一個 m-clique 走一次 (⇐)，看怎麼讀回指派。

公式寫法：每個子句用括號包起來，字面寫 x1～x4，否定在前面加 !（或 ¬），子句內用 |（或 ∨）隔開，最多 4 個子句、每個子句 1～3 個字面。按「目標：Clique」可以切換成 3-SAT → 獨立集，比較兩張圖；按「不可滿足」可以看到圖上找不到大小 m 的 clique，最多只湊得到 m − 1 個點。

CLIQUE、獨立集、點覆蓋：同一個問題的三種說法

有了 CLIQUE 是 NPC，另外兩個圖問題可以用很短的歸約接上。P、NP 與 NP 完備已經證過 IS ≤p VC（S 是獨立集 ⇔ V − S 是 Vertex Cover（點覆蓋））；再加上 clique 和獨立集的補圖關係，三個問題就能互相轉換：

歸約圖怎麼改門檻怎麼改為什麼對
CLIQUE(G, k) → IS(Ḡ, k)換成補圖不變S 在 G 兩兩相鄰 ⇔ S 在 Ḡ 兩兩不相鄰
IS(G, k) → CLIQUE(Ḡ, k)換成補圖不變同上，反過來讀
IS(G, k) → VC(G, n − k)不變k → n − k每條邊最多 1 端在 S ⇔ 至少 1 端在 V − S
VC(G, k) → IS(G, n − k)不變k → n − k同上
CLIQUE(G, k) → VC(Ḡ, n − k)換成補圖k → n − k上面兩條串起來

記法：clique ↔ 獨立集換「圖」（補圖），獨立集 ↔ 點覆蓋換「點」（補集）。兩者別混在一起：點覆蓋和獨立集是在同一張圖上互補。用數字講：若 10 個點的 G 最大 clique 有 4 個點，則 Ḡ 的最大獨立集也是 4、Ḡ 的最小點覆蓋是 10 − 4 = 6，但 G 自己的最小點覆蓋和這些沒有直接關係。補圖要 O(n2) 時間，改門檻 O(1)，都是多項式。程式枚舉了 5 個點以內的全部圖、每個 k（共 6504 組），三個問題的答案完全一致。

這三個問題在特殊的圖上會變簡單，這是判斷題的常客：二分圖的最小點覆蓋 = 最大匹配（多項式時間）；區間圖的最大獨立集用活動選擇的 greedy 就能解。

看程式碼：補圖與兩個轉換
complementGraph() / reduceCliqueToIS() / reduceISToVC()
void complementGraph(const Graph *g, Graph *h) {
  h->n = g->n;
  for (int u = 0; u < g->n; u++)
    for (int v = 0; v < g->n; v++)
      h->adj[u][v] = u != v && !g->adj[u][v];
}

void reduceCliqueToIS(const Graph *g, int k, Graph *h, int *k2) {
  complementGraph(g, h);
  *k2 = k;
}

void reduceISToVC(const Graph *g, int k, Graph *h, int *k2) {
  *h = *g;
  *k2 = g->n - k;
}

VERTEX-COVER → SUBSET-SUM：用位數記帳

Subset Sum（子集合和）：給一組正整數 S 和目標 t，有沒有一個子集合加起來剛好是 t？它在 NP（certificate 是子集合）。數字問題要從圖問題歸約過來，關鍵技巧是把數字當成好幾個欄位：每一位數記一件事，只要保證加的時候不會進位，各位數就互不干擾，「總和等於 t」就變成「每一位都剛好等於 t 的那一位」。

給 VERTEX-COVER 的輸入 G（n 個點、m 條邊 e0…em−1）和 k，所有數字都寫成 m + 1 位的 4 進位數：最高位記「選了幾個點」，第 j 位記「邊 ej 被蓋到幾次」。

  • 點 vi → xi：最高位 1，vi 碰到的每條邊那一位放 1。xi = 4m + Σej 碰到 vi 4j。
  • 邊 ej → yj：只有第 j 位是 1，yj = 4j，用來「補一次」。
  • 目標：最高位放 k，每條邊那一位都放 2。t = k·4m + Σj 2·4j。

例子：三角形 v0v1v2 加一條尾巴 v2v3，邊 e0 = v0v1、e1 = v0v2、e2 = v1v2、e3 = v2v3，k = 2。最高位是 44 = 256：

y0～y30各自那一位是 11、4、16、64

點覆蓋 {v1, v2}：x1 + x2 = 613，各邊位是 (e3, e2, e1, e0) = (1, 2, 1, 1)；e2 兩端都選了已經是 2，其他三條只蓋到 1 次，補上 y0 + y1 + y3 = 69，總和 682 = t。程式窮舉 28 個子集，總和 682 的剛好 2 個，對應這張圖大小 2 的兩個點覆蓋 {v1, v2}、{v0, v2}；k 換成 0 或 1 時都找不到，和點覆蓋的答案一致。

正確性

  • 為什麼不會進位：每一位最多被三個數加到：邊的兩個端點各 1、加上 yj 的 1，合計 3 < 4。所以用 4 進位（或任何 ≥ 4 的基底）就能把每一位分開比較。
  • (⇒) 點覆蓋 C（|C| = k）：取所有 xi（vi ∈ C），最高位是 k；每條邊至少一端在 C，該位是 1 或 2，是 1 的再加 yj。總和 = t。
  • (⇐) 若某子集總和 = t：沒有進位，逐位比較。最高位 = k，所以剛好選了 k 個 x，對應 k 個點；第 j 位 = 2，而 yj 最多貢獻 1，所以至少有一個 x 在這一位是 1，也就是 ej 至少一個端點被選。這 k 個點是點覆蓋。
  • 大小：n + m 個數，每個 m + 1 位（4 進位），總位元數 O((n + m)·m)，多項式時間寫得出來。

注意最後一點：這些數字的值是 4m 級，指數大，但位數只有 O(m)，而歸約只要求「寫出輸出的時間」是多項式。這也說明了 SUBSET-SUM 的 O(n·t) 動態規劃為什麼救不了 NP（見偽多項式時間）：歸約造出來的 t 本來就是指數大。標準教材裡更常見的是 3-SAT → SUBSET-SUM，想法一樣，只是每個數字的欄位改成「變數位」和「子句位」，用 10 進位。題目若要求加上別的限制（例如只准選奇數個元素），通常是在這個構造上再加幾個「控制位數」強迫選法。

看程式碼：reduceVCToSubsetSum()
reduceVCToSubsetSum()：4 進位，每一位代表一條邊
int reduceVCToSubsetSum(int n, int m, const int eu[], const int ev[], int k,
                        long long S[], long long *t) {
  long long p[MAXE + 1];
  p[0] = 1;
  for (int j = 1; j <= m; j++) p[j] = p[j - 1] * 4;
  int c = 0;
  for (int i = 0; i < n; i++) {                     /* 每個點一個數 x_i */
    S[c] = p[m];
    for (int j = 0; j < m; j++)
      if (eu[j] == i || ev[j] == i) S[c] += p[j];   /* 碰到的邊那一位放 1 */
    c++;
  }
  for (int j = 0; j < m; j++) S[c++] = p[j];        /* 每條邊一個補位數 y_j */
  *t = k * p[m];
  for (int j = 0; j < m; j++) *t += 2 * p[j];       /* 每條邊那一位都要湊到 2 */
  return c;                                          /* 共 n + m 個數 */
}

HAM-CYCLE → TSP 與各種路徑問題

Hamiltonian Cycle（漢米爾頓迴路）是經過每個點恰好一次再回到起點的 cycle（和 Euler 迴路的比較見Euler 與 Hamilton）。HAM-CYCLE 是 NPC，通常由 VERTEX-COVER 用一個比較複雜的「每條邊一個 12 點零件」的構造證明，考研幾乎不會要你寫出那個零件，只要知道這條箭頭存在。真正常考的是從 HAM-CYCLE 往下歸約，這些幾乎都是限制法。

TSP 的決策版本

Traveling Salesman Problem（旅行推銷員問題）的決策版本：給完全圖和整數權重，有沒有總長 ≤ k 的巡迴？給 HAM-CYCLE 的輸入 G（n 個點），建一張 n 個點的完全圖：G 的邊權重 1，不是 G 的邊權重 2，k = n。

  • (⇒) G 有 HC：同一條路線在完全圖上全部走權重 1 的邊，長度 n ≤ k。
  • (⇐) 有長度 ≤ n 的巡迴：巡迴剛好 n 條邊、每條至少 1，總長 ≤ n 只能每條都是 1，也就是全部是 G 的邊，這就是 G 的 HC。
  • 大小：n2 個權重，每個 1 個位元，O(n2)。

如果 G 沒有 HC 但有 Hamiltonian path，最短巡迴會是 n + 1（path 的兩端用一條權重 2 的邊接起來）。程式對 600 張隨機圖（其中 242 張有 HC）確認「G 有 HC ⇔ 最短巡迴 ≤ n」；把圖 5 的邊 2-3 拿掉，點 3 只剩一條邊，最短巡迴就變成 5 > 4。

路徑與環的變形：先問能不能「放進」HAM

判斷題常見的一群問題，都可以把 Hamiltonian 問題直接當成特例：

問題歸約結論
u 到 v 有沒有長度 k 的簡單路徑HC：選一點 u，對每個鄰居 v 問「u 到 v 有沒有長度 n − 1 的簡單路徑」，最多問 n 次NPC
最長簡單路徑（權重都是 1）長度能到 n − 1 ⇔ 有 Hamiltonian pathNP-hard
最大的環長度能到 n ⇔ 有 HCNP-hard
有負環時的最短簡單路徑權重全部取負號，就是最長簡單路徑NP-hard
u 到 v 有沒有長度 k 的 walk（可重複點）放不進 HAM：可以繞圈湊長度P（DP 或鄰接矩陣次方）

第一列的歸約用的是「多次呼叫」的歸約（Turing 歸約），對「若它在 P 則 HC 在 P」的結論一樣成立；想要一次轉換的 Karp 歸約也可以，加一個新點複製 u 的鄰居即可。關鍵詞永遠是 simple：題目沒寫清楚時，作答先講明你採用哪一種解讀。

看程式碼：reduceHCToTSP()
reduceHCToTSP()：邊權重 1、非邊權重 2、k = n
void reduceHCToTSP(const Graph *g, int w[][MAXV], int *k) {
  for (int u = 0; u < g->n; u++)
    for (int v = 0; v < g->n; v++)
      w[u][v] = u == v ? 0 : (g->adj[u][v] ? 1 : 2);
  *k = g->n;
}

3-SAT → 3-COLOR：調色盤與 OR 零件

3-Coloring（三著色）：能不能用 3 種顏色替每個點著色，讓相鄰的點不同色？2 色就是判斷二分圖，用 BFS 線性時間就能解；3 色卻是 NPC。這是零件設計最典型的例子，三種零件各管一件事：

  1. 調色盤：三個點 T、F、B 連成三角形，三種顏色各占一個。之後就把「和 T 同色」叫做真、「和 F 同色」叫做假。
  2. 變數零件：每個變數兩個點 xi、¬xi，互相連邊，也都連到 B。它們不能是 B 色、又不能同色，所以一個是 T、一個是 F，正好是一組指派。
  3. OR 零件：輸入 a、b，加三個點 p、q、o，邊 a–p、b–q、p–q、p–o、q–o。性質：a、b 都是 F 時，p、q 都不能是 F 又互相不同，只能是 {T, B}，o 和兩者都相鄰，只剩 F；只要 a、b 有一個是 T，就有辦法讓 o 塗成 T。
  4. 子句零件：子句 (l1 ∨ l2 ∨ l3) 用兩個 OR 零件算出 o2 = OR(OR(l1, l2), l3)，再把 o2 連到 F 和 B，逼 o2 = T。

(⇒) 有滿足指派：照指派塗變數點，每個子句至少一個輸入是 T，OR 零件的內部點照性質塗，o2 塗 T，全部合法。(⇐) 圖能 3 著色：每個變數零件給出一組指派；若某個子句三個字面全是 F，兩個 OR 零件會逼 o2 = F，但 o2 和 F 相鄰，矛盾。所以每個子句都有真字面。大小：3 + 2n + 6m 個點、3 + 3n + 12m 條邊，線性。示範公式（n = 3、m = 3）造出 27 個點、48 條邊；程式對 300 個隨機公式（其中 21 個不可滿足）用回溯法著色，答案全部一致。

有了 3-COLOR，k ≥ 4 的 k-COLOR 也都是 NPC：每多一種顏色，就加一個和所有點相連的新點。

看程式碼：reduce3SATTo3Color()
reduce3SATTo3Color()：調色盤、變數、子句
void reduce3SATTo3Color(const CNF *f, Graph *g) {
  memset(g, 0, sizeof *g);
  g->n = 3 + 2 * f->n;
  addEdge(g, T, F); addEdge(g, F, B); addEdge(g, B, T);
  for (int i = 1; i <= f->n; i++) {
    addEdge(g, varNode(i), varNode(-i));
    addEdge(g, varNode(i), B); addEdge(g, varNode(-i), B);
  }
  for (int j = 0; j < f->m; j++) {
    const int *l = f->lit[j];
    int o1 = orGadget(g, varNode(l[0]), varNode(l[1]));
    int o2 = orGadget(g, o1, varNode(l[2]));
    addEdge(g, o2, F); addEdge(g, o2, B);           /* 子句的輸出只能是 T */
  }
}
orGadget()：兩個輸入都是 F 時輸出一定是 F
int varNode(int l) { return l > 0 ? 3 + 2 * (l - 1) : 4 + 2 * (-l - 1); }

void addEdge(Graph *g, int u, int v) { g->adj[u][v] = g->adj[v][u] = 1; }

int orGadget(Graph *g, int a, int b) {
  int p = g->n++, q = g->n++, o = g->n++;
  addEdge(g, a, p); addEdge(g, b, q); addEdge(g, p, q);
  addEdge(g, p, o); addEdge(g, q, o);
  return o;
}

用歸約判斷：在 P 還是 NP-hard

很多題目把一個 NP-hard 問題和它的「好解版本」混在一起，要你分類。常見的對照表在 P、NP 與 NP 完備已經列過；這裡補上判斷的方法：先問「能不能把一個已知 NPC 問題放進去」（能 ⇒ NP-hard），再問「有沒有已知的多項式演算法」。兩個都找不到時，題目通常會給提示。

問題分類理由
最小的環（girth，權重都是 1）P每個點做一次 BFS，O(V(V + E))
找一個負環PBellman-Ford 跑完 V − 1 輪後還能鬆弛
找一個正環P權重全部取負號，變成找負環
最大割 MAX-CUTNP-hard已知 NPC（由 3-SAT 系列歸約）
最小割 MIN-CUTPmax-flow min-cut 定理
2-SATP每個 2 字面子句寫成兩條蘊含邊，一個變數和它的否定落在同一個強連通分量 ⇔ 不可滿足

2-SAT 的線性時間演算法用的是 Strongly Connected Components 強連通元件（籌備中）；手算小題時，「(x ∨ y)(¬x ∨ y) 等於直接強迫 y = 1」這種化簡最快。另外記得：「NP-hard」和「在 P」要在 P ≠ NP 的前提下才互斥，題目通常會寫 Assume P ≠ NP。

歸約為什麼是多項式時間：一張表整理

證明裡的「f 是多項式時間」常常被寫成一句「顯然」，但閱卷老師要看的是：輸出有多大、每個部分花多少時間，而且要對輸入長度算。下表用 n 代表變數數或點數、m 代表子句數或邊數：

歸約輸出大小時間要注意的地方
SAT → 3-SAT長度 k 的子句 → k − 2 個子句O(公式長度)新變數 k − 3 個，不是 k 個
3-SAT → CLIQUE / IS≤ 3m 個點、O(m2) 條邊O(m2)k = m（子句數），不是變數數
CLIQUE ↔ IS ↔ VC同樣的點、O(n2) 條邊O(n2)補圖或 k → n − k
VC → SUBSET-SUMn + m 個數，每個 m + 1 位O((n + m)m)數值是指數大，但位數是多項式
HAM-CYCLE → TSPn2 個權重O(n2)權重只有 1、2
3-SAT → 3-COLOR3 + 2n + 6m 個點O(n + m)每個子句 6 個新點

兩個常見的錯誤：

  • 把數字寫成一進位或用數值當大小：例如「建一張有 t 個點的圖」，t 是 SUBSET-SUM 的目標，值可能是 2位元數，這個轉換就是指數時間。數字只能出現在輸出裡當成數字，不能拿來決定要畫幾個點。
  • 歸約裡偷偷解了原問題：例如 f 先暴力判斷 φ 可不可滿足，再輸出一個固定的 yes 或 no 實例。這樣對答案當然對，但轉換本身是指數時間，不算歸約。f 只能看輸入的「形狀」，不能去解它。

歸約與近似（簡述）

NPC 問題的最佳化版本沒辦法保證又快又準，退而求其次就是近似演算法。這一章只需要記住它和歸約的關係，演算法細節在 Vertex Cover and TSP Approximation 頂點覆蓋與 TSP 近似（籌備中）。

  • 點覆蓋有 2-近似：反覆挑一條還沒被蓋到的邊，把兩個端點都放進 C。挑出的邊彼此沒有共同端點，任何點覆蓋都要在每條挑出的邊上至少選一點，所以 |C| = 2 × 挑出的邊數 ≤ 2 × 最佳值。
  • 歸約不保留近似比：IS(G, k) ⇔ VC(G, n − k) 是同一個歸約，但點覆蓋有 2-近似，獨立集在 P ≠ NP 下卻沒有任何常數倍近似。原因是 k 小一點，n − k 只差一點點，「差幾倍」不會跟著轉換保持。
  • 一般 TSP 沒有常數倍近似：把 HAM-CYCLE → TSP 的非邊權重從 2 改成 ρn + 1，有 HC 時最佳值是 n，沒有 HC 時任何巡迴都 > ρn，於是 ρ-近似演算法能分辨兩種情況，等於在多項式時間解了 HC。只有滿足三角不等式的 metric TSP 才有 2-近似。
  • SUBSET-SUM 可以近似到任意好：對 DP 的候選總和做「修剪」（相差不到 (1 + δ) 倍的只留一個），得到 (1 − ε)-近似，時間是 n 和 1/ε 的多項式。同樣是 NPC，近似的難度可以差非常多。

易錯點

  • 要證明新問題 X 是 NPC，就證明 X ≤p 某個已知 NPC 問題 → 方向相反：已知 NPC ≤p X。X ≤p 3-SAT 只說明 X 不比 3-SAT 難（連排序都做得到） 例題

  • A ≤p B 且 A ∈ P，所以 B ∈ P → 「好解」只會逆著箭頭傳：B ∈ P ⇒ A ∈ P 例題
  • B 沒有 O(N³) 演算法，A 又線性歸約到 B，所以 P ≠ NP → 只有「B 有 O(N³) ⇒ A 有 O(N³)」這個方向；B 沒有快的解法，什麼都推不出 例題

  • 正確性只要證 (⇒)：原問題 yes 時新問題也是 yes → 還要證 (⇐)，否則 no 的實例可能也被送到 yes；要從新問題的任意解反推 例題
  • VC → SUBSET-SUM 的 t 就是點覆蓋那幾個 x 的總和 → 每條邊的位要湊到 2，只蓋到一次的邊要再加 y；t = k·4m + Σ 2·4j 例題
