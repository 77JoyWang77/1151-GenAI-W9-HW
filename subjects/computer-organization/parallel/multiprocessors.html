Multiprocessors and GPUs 多處理器與 GPU多核心、共享記憶體、快取一致性與 GPU：平行硬體怎麼合作

Ch6 Parallel Processors 難度 speedup cache coherence MSI/MESI GPU SIMT

為什麼要多處理器

單一處理器變快的老方法是提高時脈、把管線切深、一個 cycle 發更多指令。這幾招在 2000 年代中期碰到兩道牆：時脈越高功耗越大、散熱做不到（Power Wall and Multicore 功耗牆與多核心，籌備中）；一個程式裡能同時執行的獨立指令也有限，硬體再怎麼找 ILP 也找不出更多（Instruction-Level Parallelism 指令層級平行，籌備中）。業界的出路是：不再讓一顆核心更快，而是在同一顆晶片上放很多顆比較省電的核心。

  • Multiprocessor（多處理器）：有兩個以上處理器的電腦系統。
  • Multicore（多核心）：多個處理器（核心）做在同一顆晶片上，是現在最常見的多處理器。
  • Thread-Level Parallelism（執行緒層級平行，TLP）：把工作分成多個可以同時執行的執行緒，分給不同核心。和管線、多發這類在單一指令流裡找平行的 ILP 是不同層次的平行。

多核心不會自動讓程式變快

多處理器有兩種用法。第一種是同時跑很多個互不相干的程式（job-level parallelism），例如伺服器同時處理很多個請求：每個工作本身沒有變快，但每秒完成的工作變多，改善的是 throughput（見 CPU Time and CPI CPU 時間與 CPI 的 response time 與 throughput）。第二種是把一個程式改寫成 Parallel Processing Program（平行處理程式），讓它的 response time 變短，這才是困難的地方：

  • 切工作：要找到夠多可以同時做、彼此獨立的部分。
  • 負載平衡：每個核心分到的量要差不多，否則大家都在等最慢的那個。
  • 溝通與同步：核心之間要交換資料、要等彼此做完一個階段，這些都是單核心沒有的額外成本。
  • 序列部分：只要有一部分只能一個核心做，它就是上限。Amdahl's Law 說 speedup ≤ 1 ÷ (s + (1 − s) ÷ P)，s 是序列部分佔的時間比例。例如想用 100 顆處理器得到 90 倍，代入可得 s 最多只能約 0.11%；s = 5% 時只有約 16.8 倍。完整推導在 Amdahl's Law Amdahl 定律（籌備中），Threads and Multithreading Models 執行緒與多執行緒模型 也有一個例子。

平行硬體的分類

依「幾個指令流 × 幾個資料流」可以把電腦分成 SISD、SIMD、MISD、MIMD 四類（Flynn 分類），多核心是 MIMD（每顆核心跑自己的程式、處理自己的資料），向量處理器和 SIMD 指令是 SIMD（一條指令同時處理多筆資料），GPU 介於兩者之間。核心內部還可以用硬體多執行緒（fine-grained、coarse-grained、SMT）讓多個執行緒共用一顆核心的功能單元。這兩個主題在 Flynn's Taxonomy and Multithreading Flynn 分類與硬體多執行緒（籌備中）詳細介紹，這一頁專注在下面幾種架構：

架構平行的單位核心之間怎麼溝通這一頁的重點
共享記憶體多處理器（多核心 CPU）執行緒讀寫同一個位址空間同步、cache coherence
Cluster（叢集）行程，每個節點一台電腦網路上傳訊息message passing、互連網路

另一個方向是 Heterogeneous Multicore（異質多核心）：同一顆晶片放不同種類的核心。例如手機常用的 big.LITTLE，把高效能的大核（多發、亂序、高時脈）和省電的小核（簡單、淺管線、低時脈）放在一起，輕負載交給小核，重負載才叫醒大核，目的是能源效率。

加速比、強擴展與弱擴展

評估平行程式最基本的兩個數字：

speedup（加速比）  = T1 ÷ TP          T1：1 個處理器的時間，TP：P 個處理器的時間
efficiency（效率）= speedup ÷ P             1 = 100%，代表每個處理器都沒有閒著

例如 32 個處理器得到 20 倍，效率 = 20 ÷ 32 ≈ 63%，等於平均每個處理器有 37% 的時間沒在做有用的事（在等序列部分、等別人、在溝通）。

兩種「加處理器」的問法

  • Strong Scaling（強擴展）：總問題大小固定，增加處理器，看時間能縮短多少。問題大小為 S 時，每個處理器分到 S ÷ P。
  • Weak Scaling（弱擴展）：每個處理器分到的量固定，處理器變多時問題也跟著變大（總量 = 每核的量 × P），看時間能不能維持不變。

考題常故意寫反：「strong scaling 是每個處理器使用的記憶體大小維持 S」是錯的，那是 weak scaling。實務上 weak scaling 比較容易做到，因為很多問題變大時，可平行的部分（例如矩陣）長得比序列部分快。

程式先做 20 次只能序列執行的加法，再把 N × N 矩陣的元素加總，N2 次加法平均分給 P 個處理器。每次加法 1 個時間單位，先忽略溝通成本：TP = 20 + N2 ÷ P。

負載不平衡

上面假設每個處理器分到一樣多。如果 N = 32、P = 32 時，其中一個處理器分到 64 個加法（其他的都不超過 32 個），平行階段要等最慢的那個：TP = 20 + 64 = 84，speedup 從 20.08 掉到 1044 ÷ 84 ≈ 12.43，少了約 38%。只有一個處理器多做一倍，整體就慢將近四成，所以平行階段的時間 = 最忙的那個處理器的時間。

理想 speedup 的判斷

迴圈每次迭代彼此完全獨立（例如 A[i][j] = B[j][i] * 100 + 20，每個元素只由一個輸入算出）時，把迭代平均切給 P 個核心，理想 speedup 就是 P；雙核心就是 2 倍。處理器的字長（32 或 64 位元）和這件事無關；「一條指令同時做幾筆」是 SIMD 的事，在後面的「向量處理器與 SIMD」討論。

看程式碼：parallelTime()、imbalancedTime()、speedupOf()、efficiency()

/* 序列部分 serial 個時間單位，可平行的 work 個單位平均分給 p 個核心 */
double parallelTime(double serial, double work, int p) {
  return serial + work / p;
}

/* 負載不平衡：最忙的核心分到 maxShare 個單位，其他核心做完也要等它 */
double imbalancedTime(double serial, double maxShare) {
  return serial + maxShare;
}

double speedupOf(double t1, double tp) { return t1 / tp; }
double efficiency(double t1, double tp, int p) { return t1 / tp / p; }

共享記憶體：SMP、UMA 與 NUMA

Shared Memory Multiprocessor（共享記憶體多處理器，SMP）讓所有處理器共用同一個實體位址空間：任何核心用一般的 load / store 就能讀寫任何位址，執行緒之間交換資料只要讀寫同一個變數。多核心 CPU 都是這一類。依存取時間是否相同，再分兩種：

  • UMA（Uniform Memory Access，均勻記憶體存取）：不論存取哪個位址、由哪個核心存取，延遲大致相同。典型做法是所有核心透過一條 bus 接到同一組記憶體，簡單，但 bus 是共用的，核心一多就塞車，通常只做到幾十顆。
  • NUMA（Nonuniform Memory Access，非均勻記憶體存取）：記憶體分散在各個節點，每個節點的核心存取「本地」記憶體快，存取別的節點要經過互連網路，比較慢。可以擴展到更多處理器，代價是程式要注意資料放在哪裡（作業系統也會盡量把執行緒排在它的資料附近）。

共享位址空間讓程式好寫，但帶來兩個新問題，是這一頁接下來的重點：多個核心同時修改同一個變數要同步；每個核心都有自己的快取，同一個位址可能有好幾份副本，要維持 cache coherence。

例子：平行加總

要把 P × k 個數加總，最直接的做法分兩階段：每個處理器先把自己那 k 個加成一個部分和（完全平行），再把 P 個部分和合起來。第二階段若讓一個處理器全包要 P − 1 次加法；用樹狀歸約（reduction），每一輪讓一半的處理器把另一半的部分和加進來，只要 log2 P 輪。8 個處理器時：第 1 輪 4 個人同時加、第 2 輪 2 個、第 3 輪 1 個，3 輪就完成，序列做要 7 次。

每一輪都要等上一輪的所有加法做完才能開始，否則可能讀到還沒加好的部分和，這種「大家都到了才往下走」的同步叫 Barrier（屏障）。

看程式碼：treeSum()
treeSum()：每輪減半的樹狀加總
/* 樹狀加總：每一輪讓前一半的核心把後一半的部分和加進來 */
float treeSum(float part[], int p) {
  for (int half = p / 2; half >= 1; half /= 2)   /* 每輪參與的核心數減半 */
    for (int i = 0; i < half; i++)               /* 這一輪 i = 0..half-1 同時做 */
      part[i] = part[i] + part[i + half];        /* 真的平行時，每輪之間要 barrier */
  return part[0];
}

浮點數的加總順序會影響結果

平行化改變了加法的順序。整數加法有結合律，順序不影響結果；浮點數每加一次都會捨入，沒有結合律。用 float 加總 {108, 1, 1, 1, −108, 1, 1, 1}（真正的和是 6）：

  • 由左到右依序加：108 附近的 float 間距是 8，每次加 1 都被捨掉，加完前四個還是 108，減掉 108 變 0，最後只得到 3。
  • 樹狀加總：第一輪 108 先和 −108 配對抵消成 0，三個 1 + 1 = 2 都沒有損失，最後得到 6。

所以平行版和循序版的浮點結果可能不同，處理器數改變時結果也可能變；需要可重現結果的程式要固定加總順序。

同步：交錯、race 與原子操作

共享變數最常見的錯誤是 Race Condition（競爭情況）：結果取決於各核心指令的先後。x = x + 1 在機器層級是三條指令：load 到暫存器、在暫存器裡加 1、store 回記憶體。兩個核心的這三條可以任意交錯，如果兩邊都在對方 store 之前 load，就都拿到舊值，後寫的那個會蓋掉先寫的，這叫 Lost Update（遺失更新）。軟體層面怎麼用 mutex 保護，見 Threads and Multithreading Models 執行緒與多執行緒模型；這一節從硬體角度看：交錯到底會產生哪些結果、硬體提供什麼指令做出不可分割的操作。

x 初值 1，P0 執行 x = x + 1、P1 執行 x = x * 2，沒有加鎖。兩邊各 3 條指令，交錯方式有 C(6, 3) = 20 種，但結果只有三種：

情況例子（每格是哪個核心執行下一條）最後 x說明
P0 整個先做完P0 P0 P0 P1 P1 P14(1 + 1) × 2
P1 整個先做完P1 P1 P1 P0 P0 P031 × 2 + 1

解題步驟：(1) 先列出「一次做完一整個運算」的各種先後順序，這些結果一定可能；(2) 再找「某人讀到舊值、晚於別人寫回」的交錯，看會多出哪些值；(3) 題目若有多個變數或多個運算，就逐一檢查每個 load 可能讀到哪幾個版本。題目數字多的時候（三個核心、各好幾條），可以用下面的程式窮舉所有交錯驗算。

常見的陷阱：有 cache coherence 不代表沒有 race。coherence 保證所有核心看到同一個位址的寫入順序一致、最後的寫入一定會被看到，但它不會把「讀－改－寫」三條指令綁在一起，上表的 2 在有 coherence 的系統上照樣會出現。

看程式碼：step()、runOp() 與 explore()：窮舉所有交錯
一條一條執行、加鎖時一次做完一個運算、遞迴窮舉每一種交錯
void step(Core *c) {
  Inst in = c->prog[c->pc];
  switch (in.op) {
    case LOAD:   c->reg = mem[in.var]; break;      /* 讀共享記憶體到自己的暫存器 */
    case ADDI:   c->reg = c->reg + in.k; break;    /* 只改自己的暫存器 */
    case MULI:   c->reg = c->reg * in.k; break;
    case STORE:  mem[in.var] = c->reg; break;      /* 寫回共享記憶體，別人才看得到 */
    case STOREI: mem[in.var] = in.k; break;
  }
  c->pc++;
}

/* 加鎖（原子）時：一次把整個高階運算做完，中間不讓別人插隊 */
void runOp(Core *c) {
  do step(c); while (c->pc < c->len && !c->prog[c->pc].first);
}

/* 窮舉所有交錯：每次選一個還沒跑完的核心先走一步 */
void explore(Core cs[], int n) {
  int moved = 0;
  for (int i = 0; i < n; i++) {
    if (cs[i].pc == cs[i].len) continue;       /* 這個核心已經跑完 */
    Core saved = cs[i];
    int m0 = mem[0], m1 = mem[1];
    if (atomicOps) runOp(&cs[i]); else step(&cs[i]);
    explore(cs, n);
    cs[i] = saved; mem[0] = m0; mem[1] = m1;   /* 還原，換下一個核心先走 */
    moved = 1;
  }
  if (!moved) record(mem[0], mem[1]);          /* 全部跑完：記下一種結果 */
}

硬體提供的原子操作

要寫出鎖，需要一個硬體保證不可分割的「讀－改－寫」。只用一般的 load 和 store 做不到：讀到「鎖是空的」和寫入「我拿到了」之間，別人可能也讀到空的。常見的硬體原語：

  • Atomic Exchange（原子交換，swap）：一條指令把暫存器和記憶體的值互換。拿鎖時把 1 換進去，換回來的是 0 就代表拿到了，是 1 就代表別人拿著。
  • Test-and-set、fetch-and-add、compare-and-swap：同樣是一條指令完成讀與寫，差別在怎麼改。
  • ll / sc（MIPS、RISC-V、ARM 的做法）：拆成兩條指令。Load Linked（ll）讀出值並記下這個位址；Store Conditional（sc）只有在 ll 之後沒有人寫過這個位址時才真的寫入，並把暫存器設成 1（成功），否則不寫、設成 0（失敗），程式看到 0 就跳回去重來。

一條指令同時讀又寫，對管線很不友善（要在一條指令裡做兩次記憶體存取，還不能被打斷）；ll / sc 把它拆成兩條普通長相的指令，比較好實作，這是它的主要優點。ll / sc 的幾個重點：

  • ll 不會鎖住記憶體，別的核心照樣可以寫，只是寫了之後這邊的 sc 會失敗。
  • sc 失敗的原因不只有 context switch：其他核心在 ll 與 sc 之間寫入同一位址也會失敗。所以「沒有 context switch，sc 就一定成功」是錯的。
  • sc 的位址必須和 ll 相同，檢查成功與否要看 sc 寫回的那個暫存器。考題常給一段 sc 寫錯位址、或分支檢查錯暫存器的程式要你找 bug。
  • ll 和 sc 之間只放少量暫存器運算，越長越容易被別人插隊而失敗。競爭很激烈時 sc 可能一直失敗重試，不見得比 atomic swap 有效率。
  • unlock 只要用一般的 store 把 0 寫回，因為只有持有鎖的人會寫它。
看程式碼：用 ll / sc 做 atomic swap 與 spin lock（MIPS）
atomic swap 與 spin lock（MIPS 組合語言）
   用 ll / sc 做 atomic swap（交換 $s4 與 0($s1)）：
try:  add  $t0, $zero, $s4   # 要寫進去的值
      ll   $t1, 0($s1)       # load linked：讀舊值，並記下這個位址
      sc   $t0, 0($s1)       # store conditional：期間沒人寫過才成功，$t0 = 1
      beq  $t0, $zero, try   # 失敗（$t0 = 0）就整段重來
      add  $s4, $zero, $t1   # 把讀到的舊值放進 $s4

   用 ll / sc 做 spin lock（0($s1) 為 0 表示沒人拿，1 表示被占用）：
lock: ll   $t0, 0($s1)       # 讀鎖目前的值
      bne  $t0, $zero, lock  # 已經被占用就繼續轉（spin）
      addi $t0, $zero, 1
      sc   $t0, 0($s1)       # 試著把 1 寫進去
      beq  $t0, $zero, lock  # 被別人搶先寫了，sc 失敗，重來
      ...                    # critical section
      sw   $zero, 0($s1)     # unlock：寫回 0 就好，不用 ll / sc

鎖要滿足哪些條件、怎麼避免忙等浪費 CPU，在 The Critical-Section Problem 臨界區問題（籌備中）和 Mutex Locks and Semaphores 互斥鎖與號誌（籌備中）介紹。

動手操作

下方動畫可以自己寫每個核心要做的運算（a += 1、a -= 2、a *= 2、a = 5、a++，變數 a 或 b，用分號隔開，每核最多 3 個；P2 可以空白），以及執行順序：例如「0 1 0 1」表示下一條指令依序由 P0、P1、P0、P1 執行，沒寫完的部分依 P0、P1、P2 做完。

  • 加鎖打開後，每個數字代表一整個運算（三條指令一次做完，期間別人不能插隊）。
  • 列舉所有結果：窮舉所有交錯，列出所有可能的 (a, b) 和一個能得到它的順序；紅字是只有遺失更新才會出現的結果。
  • 快捷例子：「遺失更新」是上表第三種情況；「a++ ‖ a = 2」是 P0 做 a++、b++，P1 做 a = 2、b += 2；「三核心」三個核心交錯修改同一個 a，可能的結果多達二十幾種。

Cache Coherence：snooping 與 MSI / MESI

每顆核心都有自己的快取，同一個位址可能同時在好幾個快取裡。快取用 write-back（見 Cache Organization and Mapping 快取組織與映射）時問題最明顯：P0 和 P1 都讀過 X = 0，接著 P0 寫 X = 1，新值只在 P0 的快取裡，P1 再讀 X 還是從自己的快取讀到 0。這就是 Cache Coherence（快取一致性）問題。

一致的定義

  • 同一核心先寫後讀：P 寫了 X 之後自己讀 X（中間沒有別人寫），一定讀到自己寫的值。
  • 寫入會傳出去（write propagation）：P 寫了 X 後經過足夠時間，其他核心讀 X 一定讀到新值。
  • 寫入有一致的順序（write serialization）：兩個核心先後寫同一個 X，所有核心看到的順序都一樣，不會有人看到 1 再看到 2、另一人看到 2 再看到 1。

注意這些都只講同一個位址。不同位址之間的讀寫順序是另一個問題（memory consistency，下一節）。

兩種維持方法

  • Snooping（監聽式）：所有快取接在同一條 bus（或廣播網路）上，每個快取都監聽 bus 上的交易，看到別人要讀或寫自己也有的 block 就做出反應。簡單、反應快，但每次都要廣播，核心多時 bus 會成為瓶頸，適合 UMA。
  • Directory（目錄式）：在記憶體端為每個 block 記錄「哪些快取有副本、誰擁有最新值」，只對相關的快取發訊息，不必廣播，適合 NUMA 和大量核心。

收到別人寫入時，可以把自己的副本作廢（Write Invalidate（寫入作廢）），也可以把新值更新進來（write update）。現代處理器幾乎都用 write invalidate：同一個核心連續寫很多次時只要作廢別人一次，之後都是本地 write hit，比每次寫都廣播新值省頻寬。

MSI 協定

每個快取裡的每個 block 有三種狀態：

狀態意思記憶體是不是最新可以直接讀可以直接寫
M（Modified）只有我有，而且我改過否（最新值只在我這裡）是是
S（Shared）我有一份乾淨的副本，別人可能也有是是否，要先作廢別人
I（Invalid）沒有有效資料—否（miss）否（miss）

事件原狀態bus 交易新狀態其他快取的反應

自己寫IBusRdX（write miss：讀進來並要求獨占）M有副本的全部變 I；是 M 的先寫回

看懂這張表的關鍵：M 一定是唯一的副本（所以寫 M 不用通知任何人），S 可能有很多份（所以寫 S 一定要先作廢別人）。追蹤題的例子：三個核心依序 P0 讀、P1 讀、P2 讀、P0 寫、P1 寫、P2 寫，三次讀各一次 BusRd（都變 S）；P0 寫送 BusUpgr，作廢 P1、P2；P1 寫是 write miss，P0（M）先寫回再作廢；P2 寫同理。總共 6 次 bus 交易、4 次 invalidate、2 次寫回。

MESI：多一個 E

MSI 的浪費：一個核心讀了一個只有它在用的 block（S），之後要寫還得送一次 BusUpgr，但其實根本沒有別人可以作廢。MESI 多了 E（Exclusive）：read miss 時如果沒有其他快取有副本，就給 E（獨占、乾淨，記憶體也是最新的）。之後寫入可以不上 bus，直接 E → M。別人讀這個 block 時，E 降成 S，不用寫回（因為是乾淨的）。私有資料先讀後寫的情況非常多，E 能省下大量 bus 交易，所以多數處理器用 MESI 或它的變形（例如再加 O 狀態的 MOESI）。directory 協定、MOESI 等進一步的內容在 Cache Coherence 快取一致性（籌備中）。

看程式碼：access()：MSI / MESI 的請求端與監聽端
access()：一次讀或寫，順便更新其他快取的狀態
void access(int p, int isWrite) {
  int others = 0;                                    /* 其他快取有沒有副本 */
  for (int q = 0; q < nproc; q++) if (q != p && state[q] != I) others = 1;
  if (!isWrite) {                                    /* ---- 讀 ---- */
    if (state[p] != I) return;                       /* S、E、M 都是 read hit */
    busTx++; misses++;                               /* read miss：送出 BusRd */
    for (int q = 0; q < nproc; q++) {
      if (q == p) continue;
      if (state[q] == M) { flushes++; state[q] = S; } /* 有最新值的寫回，降成 S */
      else if (state[q] == E) state[q] = S;
    }
    state[p] = (useMESI && !others) ? E : S;         /* MESI：沒人有副本就拿 E */
    return;
  }
  /* ---- 寫 ---- */
  if (state[p] == M) return;                         /* write hit，不必通知別人 */
  if (state[p] == E) { state[p] = M; return; }       /* 獨占：悄悄升成 M，不上 bus */
  busTx++;                                           /* S：BusUpgr；I：BusRdX */
  if (state[p] == I) misses++;
  for (int q = 0; q < nproc; q++) {
    if (q == p || state[q] == I) continue;
    if (state[q] == M) flushes++;                    /* 最新值先寫回 */
    state[q] = I;                                    /* 其他副本全部作廢 */
    invals++;
  }
  state[p] = M;
}

動手操作

輸入一串存取，例如 P0 R X, P1 W Y（核心、R 讀或 W 寫、變數 X 或 Y，用逗號隔開，最多 11 個；變數省略就是 X）。X 和 Y 放在同一個 block 裡，所以存取 Y 也會影響 X 的副本。每一步會顯示請求端的狀態、bus 上的交易、其他快取監聽到之後的反應（作廢、寫回），以及記憶體是不是最新的。寫入時寫進一個遞增的新值，方便看出誰拿著最新的資料。

  • 協定按鈕切換 MSI 與 MESI；核心數可填 2～4。
  • 快捷例子：「教學例」是三核心的讀寫交錯；「MESI 的 E」是先讀後寫的私有資料，切換協定比較 bus 交易數；「false sharing」是 P0 只寫 X、P1 只寫 Y，卻每次都互相作廢（下一節）。

False Sharing 與記憶體一致性

False sharing

coherence 是以 block 為單位追蹤的，不知道你用的是 block 裡的哪個 word。兩個核心各自存取同一個 block 裡不同的變數，硬體仍然當成共享：P0 寫 x 會把 P1 整個 block 作廢，P1 寫 y 又把 P0 的作廢，block 在兩個快取之間來回搬。這叫 False Sharing（偽共享），相對於真的在用同一個變數的 true sharing。

量化一下：兩核心、MSI、64 B block，x 在 0x1000、y 在 0x1004（同一個 block），P0 寫 x、P1 寫 y 交替各 4 次。除了第一次，每次寫入都是 write miss、都要作廢對方、對方是 M 還要先寫回：8 次 bus 交易、7 次 invalidate、7 次寫回。把 y 移到 0x1040（下一個 block），只有各自第一次 miss，總共 2 次 bus 交易，其餘 6 次都是 write hit。

這也是 block 大小的取捨之一：block 越大，越能利用 spatial locality、減少 compulsory miss（見 Cache Performance 快取效能），但不相干的變數越容易擠在同一個 block，false sharing miss 變多。解法是在程式裡讓各執行緒常寫的資料依 block 大小對齊或補空間（padding），例如每個執行緒的計數器各佔 64 bytes。

Memory consistency：不同位址之間的順序

coherence 只管同一個位址。Memory Consistency Model（記憶體一致性模型）規定的是：一個核心對不同位址的讀寫，在別的核心眼中是什麼順序。最直覺的是 Sequential Consistency（循序一致性）：所有核心的存取像是排成一個總順序，而且每個核心自己的存取在其中保持程式順序。

但處理器為了效能，store 不會等寫進快取才繼續，而是先放進 Store Buffer（寫入緩衝區），後面的 load 就先執行了。x86 採用的 TSO（Total Store Order）就是正式允許這件事：store 之後對不同位址的 load 可以提早，其他順序（load→load、load→store、store→store）都保持。經典例子（A、B 初值 0）：

Proc0Proc1循序一致TSO
store 1 → A；load Bstore 1 → B；load A不可能兩個 load 都讀到 0可能都讀到 0：兩個 store 都還在各自的 store buffer 裡
store 1 → A；store 1 → Bload B；load A讀到 B = 1 就一定讀到 A = 1同左：store→store、load→load 都不會重排

需要更強的順序時，程式要插入 Fence（記憶體屏障）指令，強迫前面的存取完成才能做後面的。lock、unlock 的實作內部都包含這類屏障，所以用鎖保護好的程式不必自己煩惱一致性模型。

Message Passing、Cluster 與互連網路

另一種多處理器不共享位址空間：每個處理器（節點）有自己的私有記憶體，要拿別人的資料只能用 send 和 receive 明確地傳訊息，叫做 Message Passing（訊息傳遞）。最典型的是 Cluster（叢集）：一堆普通的電腦用網路接起來，每台跑自己的作業系統；把規模放大到數萬台，就是雲端服務的 warehouse-scale computer。

比較共享記憶體（SMP）Message passing（cluster）
位址空間一個，大家共用每個節點各自一個
交換資料load / store 同一個位址（隱式）send / receive（顯式）
同步lock、barrier收到訊息本身就是同步
硬體 coherence需要不需要（資料不共享）
擴展性受 bus／coherence 限制容易擴展到很多節點
缺點同步與 coherence 的成本溝通延遲大，程式要自己切資料與傳遞；每台各一份 OS 與記憶體，管理成本高

互連網路的拓撲

不論 NUMA、cluster 或多顆加速器，節點之間都要靠網路連接。評估一個拓撲常用兩個數字（以下都假設每條連線頻寬相同）：

  • Total network bandwidth：所有連線的頻寬總和 = 連線數 × 每條頻寬，是最好情況。
  • Bisection Bandwidth（二分頻寬）：把節點分成兩半（各一半節點），找讓「跨過切線的連線數」最少的切法，那個數 × 每條頻寬。這是最壞情況下兩半之間能同時傳的量。

看程式碼：countLinks() 與 bisection()：窮舉所有平分方式
連線數與 bisection（窮舉驗算）
int countLinks(int n) {
  int c = 0;
  for (int a = 0; a < n; a++) for (int b = a + 1; b < n; b++) c += adj[a][b];
  return c;
}

/* 窮舉所有把節點分成兩半的方法，找跨過切線的最少連線數 */
int bisection(int n) {
  int best = 1 << 30;
  for (int mask = 0; mask < (1 << n); mask++) {
    if (!(mask & 1) || __builtin_popcount(mask) != n / 2) continue;   /* 固定節點 0 在左半，避免重複 */
    int cut = 0;
    for (int a = 0; a < n; a++) for (int b = a + 1; b < n; b++)
      if (adj[a][b] && (((mask >> a) & 1) != ((mask >> b) & 1))) cut++;
    if (cut < best) best = cut;
  }
  return best;
}

GPU：SIMT、warp 與延遲隱藏

GPU 原本為繪圖設計：每個像素要做的計算都一樣、彼此獨立，數量又非常多。這種工作不在乎單一像素多快算完，只在乎每秒能算多少像素，所以 GPU 和 CPU 的設計方向剛好相反：

比較CPUGPU
目標單一執行緒的延遲越低越好整體吞吐量越高越好
晶片面積主要給大容量多層快取、分支預測、亂序執行大量 ALU 與很大的暫存器檔
怎麼對付記憶體延遲用快取讓資料就在旁邊，少去記憶體同時掛著上千個執行緒，一組在等記憶體就換另一組執行
記憶體DDR：容量大、延遲低GDDR 或 HBM：頻寬高出數倍，延遲較高
適合分支多、相依多、序列的工作大量資料做相同計算（資料層級平行）

硬體組織

  • 一顆 GPU 由幾十個 Streaming Multiprocessor（SM，串流多處理器）組成，每個 SM 本質上是一個多執行緒的 SIMD 處理器，有自己的指令排程、很多 ALU、暫存器檔與晶片內記憶體。
  • 程式設計師寫的是單一執行緒的程式（CUDA kernel），啟動時指定要幾千、幾萬個執行緒。執行緒分組成 thread block，一個 block 交給一個 SM。
  • 硬體把執行緒 32 個一組成為一個 Warp（執行緒束）。同一個 warp 的 32 個執行緒共用一個 PC，每個 cycle 執行同一條指令、處理各自的資料。這叫 SIMT（Single Instruction, Multiple Threads）：硬體用 SIMD 的方式執行，但程式寫起來像獨立的執行緒。

延遲隱藏：靠大量 warp，不是靠快取或深管線

GPU 的全域記憶體存取要幾百個 cycle。SM 同時掛著幾十個 warp，每個 warp 的暫存器都在暫存器檔裡各有一份，切換 warp 不必存回任何東西，幾乎零成本。warp 排程器每個 cycle 從「已經 ready」的 warp 裡挑一個發指令；一個 warp 發出 load 之後就去等，換別的 warp 上。這是一種細粒度的硬體多執行緒。考題說「GPU 靠很深的管線隱藏 DRAM 延遲」或「GPU 靠好幾百 MB 的 L3 cache 隱藏延遲」都是錯的。

需要幾個 warp？假設每個 warp 連續發 20 條指令（每條 1 cycle，最後一條是 load），load 要 400 cycles 才回來。一個 warp 等待的 400 cycles 要由其他 warp 補滿，每個補 20 cycles，需要 400 ÷ 20 = 20 個，加上它自己共 21 個。只有 10 個 warp 時，每 420 cycles 只有 10 × 20 = 200 cycles 有事做，使用率約 47.6%。這也說明 GPU 的弱點：要有非常多可以平行的執行緒，否則延遲藏不住。

Branch divergence

warp 只有一個 PC，如果裡面的執行緒在 if-else 走了不同路，硬體只能兩路依序都執行：先執行 if 那一路，把走 else 的執行緒 mask 掉（不寫入結果）；再執行 else 那一路，把走 if 的 mask 掉；兩路都走完後重新合流。

以 32 個執行緒的 warp 計算：8 個走 A、24 個走 B，花 30 cycles；有用的 lane-cycle 是 8 × 20 + 24 × 10 = 400，總共 32 × 30 = 960，效率只有約 41.7%。如果條件改成以 warp 為單位一致（例如 (tid / 32) % 4 == 0），同一個 warp 走同一路就不會分歧，4 個 warp 合計 20 + 3 × 10 = 50 cycles，原本是 4 × 30 = 120 cycles，快了 2.4 倍。divergence 只在 warp 內部有代價，不同 warp 走不同路沒有影響。

GPU 的記憶體

  • Memory Coalescing（記憶體合併）：warp 裡 32 個執行緒同時發 load 時，如果位址是連續的（例如執行緒 i 讀 a[i]），硬體把它們合併成少數幾個大的記憶體交易，充分利用頻寬；位址散亂（例如執行緒 i 讀 a[i × 32]）就要拆成很多次交易，有效頻寬大幅下降。CPU 的 scalar 程式一次只發一個存取，比較不需要這個機制。
  • Shared Memory（共享記憶體，scratchpad）：每個 SM 裡由程式自己管理的晶片內小記憶體，同一個 thread block 的執行緒共用，用來放會重複使用的資料。它分成多個 bank，同一個 cycle 內多個執行緒存取同一個 bank 的不同位址就是 bank conflict，只能排隊依序服務。
  • 快取：GPU 也有 L1、L2，但相對於它的運算量小很多，主要用來減少對 DRAM 的頻寬需求，而不是降低延遲。
  • GDDR 是焊在顯示卡上的晶片，HBM 是用矽中介層和 GPU 封裝在一起的堆疊 DRAM，兩者的介面都和主機板上的 DDR 插槽不同，不能互換。
看程式碼：warpCycles() 與 warpsToHide()
warp divergence 的時間、隱藏延遲需要的 warp 數
/* 一個 warp 的 thread 依條件分兩路：只要兩路都有人走，兩路都要依序執行 */
int warpCycles(const int takeIf[], int lanes, int ifCycles, int elseCycles) {
  int nIf = 0;
  for (int t = 0; t < lanes; t++) nIf += takeIf[t];
  int cycles = 0;
  if (nIf > 0) cycles += ifCycles;          /* 有人走 if：全 warp 跑 if，其他 lane 被 mask */
  if (nIf < lanes) cycles += elseCycles;    /* 有人走 else：再跑一次 else */
  return cycles;
}

/* 每個 warp 連續算 compute 個 cycle 後發一次要等 latency 個 cycle 的 load；
   要讓排程器每個 cycle 都有 warp 可發，至少需要幾個 warp */
int warpsToHide(int compute, int latency) {
  return (latency + compute - 1) / compute + 1;
}

向量處理器與 SIMD 指令

GPU 之前，資料層級平行的經典做法是 Vector Processor（向量處理器）：有一組向量暫存器，每個能放一整串元素（例如 64 個 double），一條向量指令就對整串做同一個運算，例如把 X 整串乘上 a 再加到 Y 上，只要向量 load、向量乘、向量加、向量 store 幾條指令，取代 64 次純量迴圈。好處：

  • 指令數大幅減少：一條指令做 64 個運算，取指與解碼的能量、迴圈的分支都少了很多。
  • 元素之間保證獨立：硬體不用檢查同一條向量指令內的資料危障，可以放心管線化，也可以用多條 Lane（通道）同時處理不同元素。
  • 存取模式事先知道：連續、固定間隔（stride）或用索引的 gather / scatter，記憶體系統可以整批搬。

Strip mining：長度不是剛好的時候

向量暫存器有最大長度 MVL，陣列長度 n 卻是任意的。做法是把迴圈切成幾段，每段最多 MVL 個，用 向量長度暫存器 VL 告訴硬體這一段有幾個：n = 1000、MVL = 64 時，1000 = 15 × 64 + 40，共 ⌈1000 ÷ 64⌉ = 16 段，第一段 VL = 40 先處理餘數，之後 15 段 VL = 64。同一份程式碼不論 n 是多少都能跑，硬體換成更長的 MVL 也不用重新編譯。

看程式碼：daxpyStrip()
daxpyStrip()：Y = a × X + Y，用 strip mining 切成好幾段
/* 向量長度上限 mvl：n 個元素切成好幾段，第一段先處理餘數 */
int daxpyStrip(int n, double a, const double x[], double y[], int mvl) {
  int low = 0, segments = 0;
  int vl = n % mvl;                             /* 第一段先處理餘數（可能是 0） */
  if (vl == 0) vl = mvl;
  for (int j = 0; j <= (n - 1) / mvl; j++) {    /* 共 ceil(n / mvl) 段 */
    for (int i = low; i < low + vl; i++)        /* 這一段等於一組向量指令 */
      y[i] = a * x[i] + y[i];
    low += vl;
    vl = mvl;                                   /* 之後每一段都是最長 */
    segments++;
  }
  return segments;
}

SIMD 擴充指令

一般 CPU 的 SIMD 擴充（x86 的 SSE、AVX，ARM 的 NEON）是比較陽春的版本：暫存器寬度固定，一條指令能處理幾個元素就是暫存器寬度 ÷ 元素寬度。128-bit 暫存器放 4 個 32-bit 整數，所以理想上快 4 倍；256-bit 放 4 個 double 或 8 個 float。要注意：

  • 寬度寫死在指令裡，換更寬的硬體要用新指令、重新編譯；沒有 VL，剩下不滿一個暫存器的元素要另外處理。
  • 多半只支援連續存取，像 B[j][i] 這種按欄走的存取位址不連續，要先轉置或用 gather，實際加速達不到理想值。
  • SIMD 與向量都要編譯器（或程式設計師）把可平行的迴圈找出來改寫；多核心（MIMD）則要作業系統把執行緒排到不同核心。

加速器、Roofline 與功耗

判斷一個工作在 GPU 或 AI 加速器上會卡在哪裡，最常用的是 roofline：可達效能 = min(峰值運算量, 記憶體頻寬 × arithmetic intensity)。公式、轉折點與 memory-bound／compute-bound 的判斷已經在 CPU Time and CPI CPU 時間與 CPI 的 Roofline 一節講過，這裡只整理和加速器有關的結論：

  • 例如峰值 100 TFLOP/s、頻寬 10 TB/s 的加速器，轉折點在 100 ÷ 10 = 10 FLOP/byte；intensity 4 的 kernel 只能跑到 10 × 4 = 40 TFLOP/s，是 memory-bound。
  • 大模型推論每產生一個 token 要把所有參數讀一遍、每個參數只用一兩次，intensity 很低，幾乎都是 memory-bound。所以加速器設計最在意的是晶片內與晶片間的持續頻寬（HBM、NVLink），加更多運算單元碰不到屋頂；指令窗口、分支預測這些 CPU 單執行緒的技巧對它幫助不大。
  • 峰值 ops/s 不等於實際效能，LLM 推論常用 tokens/s 衡量使用者感受到的速度。
  • CPU 和 GPU 之間、GPU 和 GPU 之間的資料搬移常常才是瓶頸：PCIe 的頻寬遠低於 HBM，把資料放在比較慢的記憶體（例如用 unified memory 讓 GPU 用 CPU 的記憶體）可以放更大的模型，但 memory-bound 的工作會跟著變慢。
  • GPU 一樣受功耗牆限制：它的時脈通常比 CPU 低，是靠大量平行的運算單元提高效能，而不是「避開」了功耗對時脈的限制；資料中心的電力與散熱更是 AI 系統最主要的成本之一。

易錯點

  • 系統有 cache coherence，共享變數就不會出錯 → coherence 只保證同一位址的寫入順序一致，不會讓 load／運算／store 變成不可分割，照樣會遺失更新 例題
  • ll 會把記憶體鎖住，沒有 context switch 時 sc 一定成功 → ll 不上鎖；其他核心在中間寫入同一位址，sc 也會失敗回 0 例題
  • strong scaling 是每個核心的工作量固定 → strong 固定總問題大小（每核 S ÷ P）；每核固定、總量隨 P 變大的是 weak scaling 例題
  • 工作分得不平均，speedup 只少一點點 → 平行階段的時間由最忙的處理器決定；一個人多做一倍，整體就可能慢四成 例題
  • GPU 靠很深的管線或很大的快取隱藏 DRAM 延遲 → 靠大量 warp 輪流執行（硬體多執行緒），一個 warp 等記憶體就換另一個 例題
  • warp 分歧時，每個執行緒只執行自己要走的那一路 → warp 共用 PC，兩路依序都要執行，不走的執行緒被 mask，時間是兩路相加 例題
  • 寫入 S 狀態的 block 不用上 bus；MESI 的 E 寫入也要送 BusRdX → S 可能有別人的副本，一定要先 invalidate；E 確定只有自己，可以不上 bus 直接變 M 例題
  • 兩個核心存取不同變數，就不會互相影響快取 → 落在同一個 block 就會 false sharing，block 越大越容易發生 例題
  • TSO 下，兩個核心各自先 store 再 load 對方的變數，不可能都讀到 0 → TSO 允許 store 留在 store buffer、後面的 load 先做，兩個都讀到 0 是可能的 例題
  • 128-bit SIMD 處理 32-bit 整數，快 2 倍（或和字長 64-bit 有關） → lane 數 = 128 ÷ 32 = 4，理想快 4 倍；多核心的 speedup 和字長無關 例題
  • 多 GPU 做 all-reduce，最重要的是單一跳的延遲 → 大量資料同時交換，看的是 bisection bandwidth 例題
  • 平行加總浮點數的結果一定和循序版本相同 → 浮點加法沒有結合律，加總順序改變，結果可能不同 例題
