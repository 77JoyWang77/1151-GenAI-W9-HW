Data Hazards and Forwarding 資料危障與轉送硬體怎麼判斷要轉送、要停：forwarding unit 與 hazard detection unit

Ch4 The Processor 難度 RAW forwarding unit hazard detection load-use scheduling

從管線化接著往下：硬體怎麼知道要轉送

Pipelining 管線化那一頁已經講過三種危障、forwarding 的基本想法、load-use 為什麼一定要停 1 個週期，也可以在動畫裡切換有／無 forwarding 看時序圖。這裡快速複習三句話就好：

  • 後面的指令要讀前面還沒寫回的暫存器，就是 Data Hazard（資料危障）。
  • ALU 的結果在 EX 結束就算好了，放在 EX/MEM 管線暫存器裡；把它直接送到下一條指令的 ALU 輸入，叫 Forwarding（轉送，又叫 bypassing）。
  • lw 的資料要到 MEM 結束才有，下一條指令馬上要用的話，轉送也來不及，要 stall 1 個週期。

那一頁是用「看時序圖、數格子」的方式判斷要不要停。但真正的硬體沒有時序圖可以看：它每個週期只看得到管線暫存器裡存的東西——每條指令的暫存器編號、控制訊號。考題也越來越常問硬體層級的細節，例如「第 5 個週期 ForwardA 是多少」「插入 bubble 要設哪些訊號」「拿掉某一條轉送路徑後哪段程式會錯」。這一頁就是把那些規則拆開來講：

  1. 先學會辨識三種相依（RAW、WAR、WAW），知道哪一種才會造成危障。
  2. 用「相依距離」一次整理出各種情況要停幾個週期，包含暫存器檔前半寫後半讀的影響。
  3. Forwarding Unit（轉送單元）的判斷條件：EX hazard、MEM hazard、為什麼要檢查 rd ≠ 0、兩個來源都命中時選誰。
  4. Hazard Detection Unit（危障偵測單元）怎麼認出 load-use、怎麼把 bubble 塞進管線。
  5. 延伸：分支提早到 ID 比較、轉送路徑的數量、軟體怎麼用重排指令把 stall 消掉。

這一頁的例子都用 MIPS 五階段管線（IF、ID、EX、MEM、WB），暫存器檔前半週期寫、後半週期讀。RISC-V 的題目規則完全一樣，只是暫存器名稱寫成 x5、x10，欄位叫 rs1、rs2、rd。

三種相依：RAW、WAR、WAW

兩條指令用到同一個暫存器，而且至少有一條要寫它，順序就不能隨便換，這叫 Dependence（相依）。設 i 在前、j 在後，依「誰讀誰寫」分成三種：

名稱情況本質能不能靠改暫存器名字消除
RAW（Read After Write）i 寫 r，j 讀 rTrue Dependence（真相依）：j 真的需要 i 算出來的值不能，只能等或轉送
WAR（Write After Read）i 讀 r，j 寫 rAnti-dependence（反相依）：只是剛好用同一個名字能，j 改寫別的暫存器
WAW（Write After Write）i 寫 r，j 也寫 rOutput Dependence（輸出相依）：最後留下的必須是 j 的值能，其中一條改寫別的暫存器

WAR 和 WAW 合稱 Name Dependence（名稱相依）：兩條指令之間其實沒有資料流動，只是暫存器不夠用、重複用了同一個名字。把其中一條的暫存器換掉（Register Renaming（暫存器重新命名）），相依就消失了；RAW 不行，因為 j 要的就是 i 的結果，換名字只是把結果搬到別的地方，j 還是要等。

為什麼五階段管線只怕 RAW

五階段管線是依序（in-order）的：每條指令照順序進每個階段，而且所有指令都在 ID 讀暫存器、在 WB 寫暫存器。所以：

  • WAR 不會出事：i 在 j 前面，i 的 ID（讀）一定比 j 的 WB（寫）早好幾個週期，i 不可能讀到 j 寫進去的新值。
  • WAW 不會出事：i 的 WB 一定比 j 的 WB 早，最後留下的一定是 j 的值。
  • RAW 會出事：j 的 ID（讀）比 i 的 WB（寫）早，j 會讀到舊值——這就是 data hazard。

WAR、WAW 什麼時候會變成問題？當指令可以不照順序執行（out-of-order）、有不同長度的執行單元（例如浮點乘法比整數加法慢），或是編譯器想把指令重排的時候。例如 loop unrolling 把迴圈攤開後，每一份都用同一組暫存器，彼此之間到處是 WAR、WAW，不 rename 就排不動。這些在 Instruction-Level Parallelism 指令層級平行主題（籌備中）會詳細講；這一頁的硬體只需要處理 RAW。

判斷時先問「誰寫、誰讀」：前寫後讀是 RAW，前讀後寫是 WAR，兩個都寫是 WAW。RAW 只算「最近一次」寫的那一條；中間有別人又寫過，就不是它的 RAW。

看程式碼：Inst 結構與 findDeps() 找出三種相依
Inst：每條指令讀寫哪些暫存器（用暫存器編號）
typedef struct {
  char op[8];
  int dst;            /* 寫入的暫存器編號（R 型的 rd、addi 與 lw 的 rt）；不寫暫存器為 -1 */
  int rs, rt;         /* 讀取的暫存器編號；沒用到為 -1。rs → ALU 上方輸入，rt → 下方輸入或 sw 要存的資料 */
  int regWrite;       /* 會寫回暫存器 */
  int memRead;        /* lw：資料要到 MEM 結束才拿得到 */
  int memWrite;       /* sw */
  int off;            /* lw / sw 的位移，base 就是 rs */
} Inst;
findDeps()：逐對檢查 RAW、WAR、WAW
void findDeps(const Inst *in, int n) {
  for (int j = 1; j < n; j++)
    for (int i = 0; i < j; i++) {
      int r = in[i].dst, newest = 1;
      for (int k = i + 1; k < j; k++)       /* 中間有人又寫了 r，j 讀到的就不是 i 的結果 */
        if (in[k].dst == r) newest = 0;
      if (r > 0 && newest && (r == in[j].rs || r == in[j].rt))
        printf("  I%d → I%d：RAW（true dependence），$%d\n", i + 1, j + 1, r);
      r = in[j].dst;
      if (r > 0 && (r == in[i].rs || r == in[i].rt))
        printf("  I%d → I%d：WAR（anti-dependence），$%d\n", i + 1, j + 1, r);
      if (r > 0 && r == in[i].dst)
        printf("  I%d → I%d：WAW（output dependence），$%d\n", i + 1, j + 1, r);
    }
}

相依距離：要停幾個週期一次整理

判斷 RAW 要不要停，關鍵只有一個數字：相依距離 d = 使用者的位置 − 生產者的位置。相鄰的兩條 d = 1，中間隔一條 d = 2。

暫存器檔前半寫、後半讀

五階段管線的暫存器檔在一個週期的前半寫入、後半讀出，所以生產者在 WB 寫回的同一個週期，使用者在 ID 就已經讀得到新值。生產者在第 k 個週期 ID，第 k + 3 個週期 WB；使用者沒有 stall 時在第 k + d 個週期 ID。要 k + d ≥ k + 3，也就是 d ≥ 3 就完全不用管。沒有 forwarding 時：

沒有 forwarding：stall（或要插的 NOP 數）= max(0, 3 − d)
d = 1 → 2 個；d = 2 → 1 個；d ≥ 3 → 0 個

如果題目說暫存器檔不能同一個週期先寫後讀，每處要多停 1 個（變成 max(0, 4 − d)）。這是常見的陷阱：五階段管線的標準設定是可以，題目沒特別說明就照前半寫後半讀算。

各種情況的 stall 數

下表是同一組例子在不同硬體下要停幾個週期（「只有 EX/MEM」「只有 MEM/WB」是指只做了其中一種轉送路徑，後面會用到）：

生產者 → 使用者距離 d沒有 forwarding完整 forwarding只有 EX/MEM 路徑只有 MEM/WB 路徑使用者是 ID 比較的 beq
ALU 指令 → 使用120011
ALU 指令 → 使用210100
lw → 使用121212
lw → 使用210101
任何 → 使用≥ 300000

每一格都可以用「資料什麼時候在哪裡」推出來：ALU 結果在生產者 EX 的下一個週期待在 EX/MEM，再下一個週期待在 MEM/WB；lw 的資料只會出現在 MEM/WB（EX/MEM 裡的是 lw 算出的位址，不是資料）。使用者在 EX 的那個週期，資料剛好在哪一個管線暫存器、那條路徑有沒有做，就決定要不要停。例如「只有 MEM/WB」時，相鄰的 ALU 相依要多停 1 個週期，等結果從 EX/MEM 移到 MEM/WB 才拿得到；「只有 EX/MEM」時，lw 的資料永遠送不過去，只能等它寫回暫存器檔，相鄰的 load-use 要停 2 個。

沒有硬體偵測時：軟體插 NOP

有些處理器（或考題）沒有 hazard detection unit，硬體不會自動停下來，正確性要靠編譯器或寫程式的人在指令之間插入 nop。算法和 stall 一樣：從第一條往下，每遇到一個 RAW 就看「目前的距離」還差幾格，補足後再繼續——前面補進去的 nop 會拉長後面的距離，所以要依序算，不能每對各算各的。

例子（沒有 forwarding）：

add $t1, $s1, $s2
sub $t2, $t1, $s3      # 讀 add 的 $t1，d = 1 → 前面補 2 個 nop
or  $t3, $t1, $t2      # 讀 sub 的 $t2：補完後 d = 1 → 再補 2 個；$t1 已經夠遠
sw  $t3, 0($s0)        # 讀 or 的 $t3，d = 1 → 再補 2 個

共 6 個 nop，總週期 = 5 + (4 + 6 − 1) = 14，比沒有相依時的 8 個週期多了 75%。若有完整 forwarding 但沒有偵測單元，這段完全不用插（三處都是 ALU → 使用）；只有 lw 後面緊接著使用時，才需要 1 個 nop。

不插的話會怎樣？硬體照樣往下走，使用者就讀到舊值。有些架構乾脆把這件事寫進規格：lw 後面那一格叫 Load Delay Slot（載入延遲槽），放在裡面的指令看到的是載入之前的值，由編譯器負責塞一條有用的指令或 nop。這時「硬體會不會停」會直接改變程式的結果；反過來，只要硬體有正確處理（不管是用 stall 還是 forwarding），差別只在花幾個週期，程式看得到的暫存器、記憶體內容完全一樣。

延伸：浮點指令的題目常直接給「latency」，意思是後面的使用者至少要隔幾個週期才能拿到結果。算法和上面一樣：使用者若緊接在生產者後面，就要空等 latency 個週期，中間每多一條無關指令就少等一個。

Forwarding Unit：什麼時候轉送、從哪裡轉送

ALU 的兩個輸入前面各加一個三選一的 mux：上方輸入（rs）的叫 A、下方輸入（rt）的叫 B。每個 mux 可以選三個來源，選擇線就是 ForwardA、ForwardB：

選擇值來源代表什麼
00ID/EXID 階段從暫存器檔讀出來的值（不用轉送）
10EX/MEM上一條指令剛算好的 ALU 結果（EX hazard）
01MEM/WB上上一條指令要寫回的值：ALU 結果或 lw 讀到的資料（MEM hazard）

判斷條件

Forwarding unit 放在 EX 階段，比較的是「正在 EX 的指令要讀哪些暫存器」（ID/EX 裡的 rs、rt 編號）和「前面兩條指令要寫哪個暫存器」（EX/MEM、MEM/WB 裡的 rd 編號）。lw 和 addi 的目的暫存器在指令的 rt 欄位，但經過 ID 階段選目的暫存器的 mux 之後，存進管線暫存器的都叫 rd。以 ForwardA 為例：

EX hazard（ForwardA = 10）：
    EX/MEM.RegWrite = 1
    且 EX/MEM.rd ≠ 0
    且 EX/MEM.rd = ID/EX.rs

MEM hazard（ForwardA = 01）：
    MEM/WB.RegWrite = 1
    且 MEM/WB.rd ≠ 0
    且 MEM/WB.rd = ID/EX.rs
    且「不是」EX hazard（EX/MEM 沒有命中）

ForwardB 一模一樣，只是把 rs 換成 rt。三個條件各有道理：

  • RegWrite = 1：前面那條真的會寫暫存器。sw、beq 的 rd 欄位裡雖然有數字，但它們不寫暫存器，不能轉送；bubble 的控制訊號全是 0，也自然不會被轉送。
  • rd ≠ 0：MIPS 的 $zero 永遠是 0，寫進去的值會被丟掉。如果有指令以 $zero 為目的地（例如 add $zero, $t1, $t2，常用來當 nop），後面讀 $zero 的指令必須拿到 0，不能拿到被轉送過來的運算結果。少了這個檢查，結果就會錯。
  • rd = rs：編號一樣才是真的相依。

兩個常被忽略的細節：

  • sw 要存的資料也會轉送：sw 的 rt 是要寫進記憶體的值，在管線裡走的就是 B mux 的輸出，所以 add $t2, … 後面緊接著 sw $t2, 4($s0)，ForwardB = 10。
  • I 型指令的 ForwardB 不重要：addi、lw 的第二個 ALU 運算元是立即值（ALUSrc = 1），B mux 的結果不會被用到。這一頁的程式把它們的 rt 當成「沒有讀」，ForwardB 一律算 00。
看程式碼：forwardSel() 決定 ForwardA / ForwardB
forwardSel()：先檢查 EX/MEM，沒命中才看 MEM/WB
int forwardSel(int src, const Inst *exmem, const Inst *memwb) {
  if (src < 0) return 0;                                  /* 沒用到這個運算元 */
  if (exmem && exmem->regWrite && exmem->dst != 0 && exmem->dst == src)
    return 2;                                             /* EX hazard：上一條剛算完 */
  if (memwb && memwb->regWrite && memwb->dst != 0 && memwb->dst == src)
    return 1;                                             /* MEM hazard：EX/MEM 沒命中才輪到它 */
  return 0;
}

Double Data Hazard：兩個來源都命中時選誰

MEM hazard 條件最後那一句「不是 EX hazard」是為了處理這種情況：連續好幾條指令都寫同一個暫存器，例如累加：

add $t1, $t1, $t2
add $t1, $t1, $t3
add $t1, $t1, $t4

這叫 Double Data Hazard（雙重資料危障）。依照程式的意思，第三條要的是「最近一次」寫入的 $t1，也就是第二條的結果，所以 EX/MEM 的優先權比 MEM/WB 高。寫成程式就是先檢查 EX/MEM，命中就直接回傳，沒命中才輪到 MEM/WB——上面 forwardSel() 的 if 順序正好做到了「不是 EX hazard」那個條件。

判斷 ForwardA / ForwardB 的考題，步驟固定：

  1. 先排出時序（有 load-use 要先把 stall 算進去），找出題目問的那個週期 EX 是哪條指令。
  2. 往前看：EX/MEM 裡是它的前一條、MEM/WB 裡是前兩條——注意 stall 插進來的 bubble 也佔一格，可能讓 EX/MEM 是空的。
  3. 對 rs、rt 各自比對：EX/MEM 命中 → 10；否則 MEM/WB 命中 → 01；都沒有 → 00。距離 ≥ 3 的相依已經寫回暫存器檔，是 00。

Hazard Detection Unit：偵測 load-use、插入 bubble

Forwarding 解決不了 load-use，硬體必須主動讓管線停一下。負責的是 hazard detection unit，它放在 ID 階段：使用者還在 ID 時就要決定，因為下一個週期它就要進 EX 了，到 EX 才發現已經來不及。

load-use 條件（停 1 個週期）：
    ID/EX.MemRead = 1                        # EX 的指令是 lw
    且 ( ID/EX.rt = IF/ID.rs  或  ID/EX.rt = IF/ID.rt )   # lw 要寫的正是 ID 的指令要讀的

lw 的目的暫存器在 rt 欄位，所以這裡比的是 ID/EX.rt。偵測到之後做三件事：

動作訊號目的
PC 不更新PCWrite = 0IF 下一個週期重抓同一條指令
IF/ID 不更新IF/IDWrite = 0ID 的指令留在原地，下一個週期再解碼一次（這次就能接到轉送）
往 EX 塞 bubble送進 ID/EX 的控制訊號全部清 0這一格什麼都不寫（RegWrite = 0、MemWrite = 0），等於一條 nop

注意不是把 IF/ID 清空（flush）：清空是分支猜錯時丟掉抓錯的指令用的；stall 時 IF/ID 裡的指令是對的，只是要晚一點執行，必須留著。

從圖 4 可以直接回答「第 n 個週期 MEM 是誰」這種題目：bubble 是一個真實佔位的格子，週期 5 的 MEM 就是那個 nop，不是 lw 也不是 add。總週期也很好算：每個 bubble 讓所有後面的指令晚 1 個週期，總週期 = 5 + (n − 1) + stall 次數。

兩個邊界情況

  • lw 後面緊接著 sw 存同一個值（lw $t0, 0($s0)、sw $t0, 4($s0)）：sw 其實到 MEM 才需要資料，理論上可以多做一條「MEM/WB → MEM」的路徑而不用停。但標準的偵測條件只看暫存器編號，sw 讀 rt，條件成立，照樣停 1 個週期。考題沒特別說明時照標準的算。
  • 比對 rt 欄位時不管指令型態：如果硬體直接拿 IF/ID 的 rt 欄位去比，遇到 addi 這種 rt 是目的暫存器（不是讀）的指令，可能多停一次。結果仍然正確，只是保守。這一頁的程式只比對真的要讀的暫存器。
看程式碼：loadUseStall() 與 simulate() 逐週期模擬
loadUseStall()：EX 是 lw、ID 的指令要讀它的目的暫存器
int loadUseStall(const Inst *idex, const Inst *ifid) {
  return idex && ifid && idex->memRead &&
         (idex->dst == ifid->rs || idex->dst == ifid->rt);
}
simulate()：每個週期先算 ForwardA / B、偵測 load-use，再一起往後移
int simulate(const Inst *in, int n, int verbose, int *nStall) {
  int pc = 0, ifid = EMPTY, idex = EMPTY, exmem = EMPTY, memwb = EMPTY;
  *nStall = 0;
  for (int cycle = 1; ; cycle++) {
    int fetch = pc < n ? pc : EMPTY;        /* 這個週期 IF 抓的指令 */
    if (fetch < 0 && ifid < 0 && idex < 0 && exmem < 0 && memwb < 0) return cycle - 1;
    if (idex >= 0) {                        /* EX 的指令：forwarding unit 選 ALU 的兩個輸入 */
      fwdA[idex] = forwardSel(in[idex].rs, AT(exmem), AT(memwb));
      fwdB[idex] = forwardSel(in[idex].rt, AT(exmem), AT(memwb));
    }
    int stall = loadUseStall(AT(idex), AT(ifid));   /* ID 的指令要用 EX 那條 lw 的結果？ */
    if (verbose) {
      int st[5] = {fetch, ifid, idex, exmem, memwb};
      trace(cycle, st, stall);
    }
    /* 時脈邊緣：管線暫存器一起往後移 */
    memwb = exmem;
    exmem = idex;
    if (stall) {                            /* PCWrite = 0、IF/IDWrite = 0：PC 和 IF/ID 不動 */
      idex = BUBBLE;                        /* 控制訊號清 0 送進 ID/EX：往 EX 塞一個 bubble */
      (*nStall)++;
    } else {
      idex = ifid;
      ifid = fetch;
      if (fetch >= 0) pc++;
    }
  }
}

動手操作：forwarding unit 與 hazard detection unit

輸入 2～7 條指令（用分號隔開），按「執行」後逐個週期看：上排是五個階段各是哪條指令，下面是兩個單元的判斷過程——forwarding unit 把 EX/MEM、MEM/WB 的 RegWrite、rd 和 EX 指令的 rs、rt 一個一個比，算出 ForwardA、ForwardB；hazard detection unit 檢查 ID/EX 是不是 lw、它的 rt 和 ID 的指令有沒有撞。最後一步整理出每條指令在 EX 時的 ForwardA / ForwardB，可以拿來對答案。

預設的例子（共 10 個週期，1 個 stall）：

指令EX 週期ForwardAForwardB原因
I1 add $t1,$s1,$s230000前面沒有人寫 $s1、$s2
I2 sub $t1,$t1,$s341000$t1 是上一條 I1 剛算的
I3 lw $t0,0($t1)510—I1、I2 都寫 $t1（double hazard），選比較新的 I2
I4 add $t2,$t0,$t170100load-use 停 1 後從 MEM/WB 拿 $t0；I2 的 $t1 在週期 6 已寫回
I5 sw $t2,4($s0)80010要存的 $t2 是上一條 I4 剛算的

分支提早到 ID 比較時的資料危障

為了減少分支的損失，常把 beq 的比較器和目標位址計算搬到 ID 階段（分支預測和 flush 的細節在 Control Hazards and Branch Prediction 控制危障與分支預測主題（籌備中）介紹）。代價是：beq 在 ID 就要用到暫存器的值，比一般指令在 EX 才用早了一個週期，資料危障變得更嚴重：

  • ALU 指令 → beq（d = 1）：ALU 結果在生產者 EX 結束才有，beq 的 ID 和生產者的 EX 在同一個週期，來不及 → stall 1，下一個週期再從 EX/MEM 轉送到 ID 的比較器。
  • lw → beq（d = 1）：資料要到 lw 的 MEM 結束才有 → stall 2，beq 的 ID 和 lw 的 WB 同一個週期，直接讀暫存器檔。
  • lw → 無關指令 → beq（d = 2）：仍要 stall 1。

所以考題問「load 後面緊接著用它的結果做分支（在 ID 比較），要停幾個週期」，答案是 2 不是 1。同時硬體要多兩條轉送路徑：EX/MEM → ID 比較器的兩個輸入。MEM/WB → ID 不需要，因為那時生產者正在 WB，前半週期寫、後半週期讀，ID 直接從暫存器檔就讀得到。

例子：lw $t0, 0($s0)、addi $t1, $t0, 4、beq $t1, $s3, L。lw → addi 是 load-use，停 1；addi 停完之後，beq 的 ID 正好和 addi 的 EX 同一個週期，又要停 1。共 2 個 stall（還不算分支本身的控制危障）。

轉送路徑有幾條、拿掉一條會怎樣

一條「轉送路徑」就是一個來源接到一個目的地。標準五階段管線（分支在 EX 或 MEM 決定）：

ALU 前的轉送路徑 = 來源 2 個（EX/MEM、MEM/WB）× 目的地 2 個（A、B 兩個 mux）= 4 條
Forwarding unit 的比較器 = 4 組（EX/MEM.rd、MEM/WB.rd 各和 rs、rt 比）
分支在 ID 比較時再加：EX/MEM → 比較器兩個輸入 = 2 條，共 6 條

考題常反過來問：「如果只做了某幾條路徑」或「某條路徑壞了」，哪些程式會錯、要多停幾個週期。做法是把相依一個一個分類：

相依用到的路徑
ALU 指令 → 下一條，用在 rsEX/MEM → A
ALU 指令 → 下一條，用在 rt（含 sw 要存的資料）EX/MEM → B
任何寫暫存器的指令 → 隔一條，用在 rs／rtMEM/WB → A／B
lw → 下一條（停 1 之後）MEM/WB → A／B
距離 ≥ 3不用轉送，讀暫存器檔

有兩個陷阱。第一，如果同一個暫存器在中間又被寫過，要看的是最近的那一條：例如 I1、I2 都寫 $s1，I3 讀 $s1，I3 用的是 I2 經 EX/MEM 轉送的值，MEM/WB 那條路徑壞了也沒關係。第二，「只有 EX/MEM 路徑」救不了 load-use：lw 的資料只會出現在 MEM/WB，路徑不存在的話只能等它寫回暫存器檔，相鄰的 load-use 要停 2 個週期，跟沒有 forwarding 一樣。

目的暫存器編號要跟著指令走

Forwarding unit 比對用的 rd 必須是「那條指令自己的」目的暫存器，所以 rd 編號要從 ID/EX、EX/MEM 一路傳到 MEM/WB，WB 寫回時用的也是 MEM/WB 裡的 rd。如果有一級沒接好（例如 WB 拿到的是 EX/MEM 裡的 rd），每個結果都會被寫進「下一條指令」的目的暫存器——這是考題愛出的「找 bug」題型，判斷方法就是逐個週期寫出 WB 的值和實際被寫的暫存器編號。

重排指令避開 load-use

硬體做完 forwarding，剩下的 load-use stall 可以交給編譯器：在 lw 和使用它的指令中間塞一條無關的指令，距離變成 2，就不用停了。這叫 Instruction Scheduling（指令排程，又叫 code reordering），完全不用改硬體。

什麼時候可以搬

把指令 j 往前搬，越過原本在它前面的指令 i，要確定兩者交換順序不會改變結果：

  • 沒有 RAW：j 不讀 i 寫的暫存器（否則 j 會拿到舊值）。
  • 沒有 WAR：j 不寫 i 要讀的暫存器（否則 i 會讀到 j 的新值）。
  • 沒有 WAW：兩者不寫同一個暫存器（否則最後留下的值會變）。
  • 記憶體：兩者至少有一個是 sw 時，必須能確定存取的不是同一個位址。同一個 base 暫存器、位移差 4 以上的 word 一定不重疊；base 不同就可能指向同一處，保守起見不換。

例子

原本順序重排後
lw $t0,0($a0)lw $t0,0($a0)
lw $t1,4($a0)lw $t1,4($a0)
stall（sub 要用 $t1）lw $t3,12($a0)（搬上來）
sub $t2,$t0,$t1sub $t2,$t0,$t1
sw $t2,8($a0)sw $t2,8($a0)
lw $t3,12($a0)addi $t4,$t3,1
stall（addi 要用 $t3）sw $t4,16($a0)
addi $t4,$t3,1
sw $t4,16($a0)
13 個週期11 個週期（少 15%）

lw $t3 往上越過 sw $t2,8($a0) 和 sub：和 sub 沒有任何暫存器相依；和 sw 都用 $a0 當 base，位址 12 和 8 不重疊，所以可以搬。搬完之後 sub 和 lw $t1 的距離變成 2，addi 和 lw $t3 的距離變成 3，兩個 stall 都消失。

不一定能全部消除

重排只能用程式裡現成的獨立指令。如果 lw 後面每一條都直接或間接依賴它（例如 lw $t0、add $t1, $t0, …、sw $t1, …），就沒有東西可以填，stall 留著；有時能填的指令不夠，只能從 2 個 nop 減到 1 個。另外，移動會受 WAR 限制：例如想把 addi $s0, $s0, 8 搬到 lw $t2, 4($s0) 前面，lw 就會讀到加過 8 的 $s0，位址錯了——除非同時把位移改成 −4，但那已經是「改指令」而不只是重排。

下面的程式用貪婪法：每個位置依原本順序找第一條可以合法搬上來、又不會和上一條形成 load-use 的指令；都不行就照原本順序放，接受那次 stall。這不保證是最佳解，但考題規模的程式通常都能找到最好的排法。

看程式碼：conflict() 與 reorder() 重排指令
conflict()：a 原本在 b 前面，能不能交換
int conflict(const Inst *a, const Inst *b) {
  if (a->dst > 0 && (a->dst == b->rs || a->dst == b->rt)) return 1;   /* RAW */
  if (b->dst > 0 && (b->dst == a->rs || b->dst == a->rt)) return 1;   /* WAR */
  if (a->dst > 0 && a->dst == b->dst) return 1;                       /* WAW */
  if ((a->memWrite && (b->memRead || b->memWrite)) || (b->memWrite && a->memRead))
    if (!(a->rs == b->rs && abs(a->off - b->off) >= 4)) return 1;    /* 可能是同一個位址 */
  return 0;
}
reorder()：每個位置挑一條不會 load-use 的指令
void reorder(const Inst *in, int n, int *order) {
  int used[MAXN] = {0};
  for (int k = 0; k < n; k++) {
    int pick = -1, first = -1;
    for (int j = 0; j < n && pick < 0; j++) {
      if (used[j]) continue;
      int ok = 1;
      for (int i = 0; i < j; i++)           /* 要跳過的每一條（原本在 j 前面、還沒排）都要能交換 */
        if (!used[i] && conflict(&in[i], &in[j])) { ok = 0; break; }
      if (!ok) continue;
      if (first < 0) first = j;
      if (k == 0 || !loadUseStall(&in[order[k - 1]], &in[j])) pick = j;
    }
    if (pick < 0) pick = first;             /* 每一條都會停：照原本順序，接受這次 stall */
    order[k] = pick;
    used[pick] = 1;
  }
}

動手操作：重排前後比較

左邊是原本的順序和 load-use stall 的位置，右邊一個位置一個位置填。每一步會說明檢查了哪些候選、為什麼不能選（RAW、WAR、WAW、可能同一個位址，或放了會造成 load-use）。快捷例子示範了被 WAR 擋住、因為 base 暫存器不同而不能越過 sw 的情況。

易錯點

  • 有了 forwarding 就沒有 data hazard stall → lw 的資料 MEM 結束才有，下一條馬上用（load-use）仍要停 1 個週期 例題
  • forwarding 把資料傳給前面的指令 → 是把前面指令的結果傳給後面、還沒讀到新值的指令 例題
  • RAW 可以用 register renaming 消除 → RAW 是真相依，只能等或轉送；renaming 只能消除 WAR、WAW 例題
  • 五階段依序管線裡 WAR 也要 stall → 前面的指令一定先在 ID 讀完，後面的才在 WB 寫，WAR、WAW 不會出錯 例題
  • 沒有 forwarding 時相鄰相依要停 3 個週期 → 暫存器檔前半寫後半讀，ID 可以和 WB 同一個週期，停 2 個 例題
  • EX/MEM 和 MEM/WB 都命中時用 MEM/WB 的值 → 選最新的 EX/MEM（ForwardA = 10），MEM/WB 的值已經被蓋過 例題
  • rd ≠ 0 的檢查可有可無 → 寫 $zero 的結果不能轉送，否則讀 $zero 的指令會拿到非 0 的值 例題
  • ForwardB 只影響 ALU 的輸入 → sw 要存的資料也經過 B mux，緊接在生產者後面的 sw 也要轉送 例題
  • stall 時要把 IF/ID 清空 → 是 PCWrite = 0、IF/IDWrite = 0 保留指令，並把 ID/EX 的控制訊號清 0；flush 是分支猜錯用的 例題
  • bubble 插進去就不見了 → bubble 像一條 nop 依序經過 EX、MEM、WB，問「第 n 個週期 MEM 是誰」時答案可能是 bubble 例題
  • lw 後面緊接著 beq（在 ID 比較）只要停 1 個週期 → beq 在 ID 就要值，比一般指令早一個週期，要停 2 個 例題
  • 只要有 EX/MEM 轉送路徑，load-use 停 1 個就夠 → lw 的資料只在 MEM/WB，沒有 MEM/WB 路徑就要等寫回，停 2 個 例題
  • 重排指令一定能消除所有 stall → 要有足夠的獨立指令可以填；搬動還受 RAW、WAR、WAW 和記憶體位址限制 例題
