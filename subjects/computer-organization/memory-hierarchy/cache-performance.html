Ch5 Memory Hierarchy 難度 AMAT CPI miss penalty L2 write buffer

為什麼要算快取效能

在 Cache Organization and Mapping 快取組織與映射 已經講過快取「怎麼放、怎麼找、滿了換誰」：直接映射與集合關聯、位址切成 tag／index／offset、LRU、3C 失誤分類、write-through 與 write-back。這一頁接著回答下一個問題：快取到底讓程式快了多少？miss 又讓程式慢了多少？

處理器和 DRAM 的速度差距越來越大，這個現象叫 Memory Wall（記憶體牆）。CPU 一個 cycle 不到 1 ns，主記憶體一次存取要幾十 ns，換算下來 miss 一次就要等上百個 cycle。只要 miss rate 有幾個百分點，等記憶體的時間就可能比真正執行指令的時間還長。所以考題幾乎都在問同一件事：給你 miss rate、miss penalty、指令組成，算出平均每次存取多久、每條指令平均多等幾個 cycle。

先複習三個量，這頁的公式都是用它們組出來的：

  • Hit Time（命中時間）：資料在快取裡時，存取一次要多久（包含比對 tag 的時間）。L1 通常是 1～4 個 cycle。
  • Miss Rate（失誤率）：存取中有多少比例不在快取裡。注意是「每次存取」的比例，不是「每條指令」的比例。
  • Miss Penalty（失誤代價）：miss 時多付的時間，也就是從下一層把整個區塊搬上來（再交給 CPU）的時間。

同一個 penalty 可能用 ns 或 cycle 表示：cycle 數 = 時間 ÷ cycle time = 時間 × 時脈頻率。例如 2 GHz 的 cycle time 是 0.5 ns，40 ns 的記憶體存取就是 80 cycles。題目給 ns 時，第一步一定是換算，這也是後面「時脈加倍」題型的關鍵。

這頁所有公式只有兩條：AMAT = hit time + miss rate × miss penalty；CPI = 理想 CPI + 每條指令的記憶體停頓。多層快取、寫入策略、記憶體組織，都只是在改 miss rate 或 miss penalty 這兩個數字。

AMAT：平均一次存取要多久

衡量一個快取最直接的指標是 AMAT（Average Memory Access Time，平均記憶體存取時間）：

AMAT = hit time + miss rate × miss penalty

為什麼 hit time 前面沒有乘 hit rate？因為不管最後有沒有命中，都要先查一次快取才知道結果，每一次存取都付了 hit time；只有 miss 的那部分再多付 miss penalty。把機率樹畫出來就看得很清楚：

上面的 5 cycles 意思是：快取命中率高達 95%，平均存取時間卻是命中時的 5 倍，因為那 5% 的 miss 每次都要等 80 倍的時間（0.05 × 80 = 4 cycles，佔了 AMAT 的 80%）。如果處理器是 2 GHz，AMAT = 5 × 0.5 ns = 2.5 ns。

同一台機器的 I-cache miss rate 只有 1% 的話，取指令的 AMAT = 1 + 0.01 × 80 = 1.8 cycles。miss rate 從 5% 降到 1%（降了 4 個百分點），AMAT 從 5 降到 1.8，降了 64%：miss penalty 越大，miss rate 的一點點差距影響越大。

兩種寫法：miss 時要不要再加 hit time

有些題目把 AMAT 寫成 hit rate × hit time + miss rate × (存取下一層的時間)，意思是 miss 時只算下一層的時間，不再加查快取的時間。兩種模型差的就是 miss rate × hit time，用上面的數字是 0.95 × 1 + 0.05 × 80 = 4.95 vs 5，差很小。考試時先看題目怎麼定義 miss penalty：如果 penalty 是「多付的時間」就用標準式；如果題目給的是「到下一層的總時間」，兩種解讀都寫出來最保險。

看程式碼：amat() 與 amat2()
amat()、amat2()：一層與兩層快取的 AMAT
double amat(double hitTime, double missRate, double missPenalty) {
  return hitTime + missRate * missPenalty;
}

double amat2(double h1, double m1, double h2, double m2Local, double memPenalty) {
  double l1Penalty = h2 + m2Local * memPenalty;   /* 先付 L2 hit time，L2 也 miss 才到主記憶體 */
  return h1 + m1 * l1Penalty;
}

把記憶體停頓算進 CPI

AMAT 只描述記憶體本身；要知道程式跑多快，還要把 miss 換算成「每條指令多等幾個 cycle」，加到 CPI 上。執行時間 = 指令數 × CPI × cycle time（這條公式在 CPU Time and CPI（CPU 時間與 CPI） 有詳細講解），快取只會改變其中的 CPI：

CPI = 理想 CPI + memory-stall cycles per instruction

memory-stall cycles per instruction
  = 每條指令取指令的次數 × I-cache miss rate × miss penalty    ← 每條指令都要取指令
  + 每條指令的資料存取次數 × D-cache miss rate × miss penalty  ← 只有 load/store 才存取資料

這裡的 Memory-Stall Cycles（記憶體停頓週期） 是「每條指令平均」的值，所以要先把「每次存取的 miss rate」乘上「每條指令有幾次存取」：

  • 指令存取：每條指令都要從 I-cache 取一次，次數是 1（題目若沒特別說明）。
  • 資料存取：只有 load/store 會存取 D-cache，次數 = load/store 佔指令的比例，例如 30% 就是每條指令平均 0.3 次。
  • 理想 CPI：所有存取都命中時的 CPI。管線處理器的 hit time 已經包含在管線的某個階段裡，所以 hit 不另外算停頓，只有 miss 才會讓管線停下來。這個 CPI 也可能已經包含管線危障造成的 stall（見 Pipelining 管線化 的「把 stall 算進效能」）。

理想 CPI 1.5，30% 的指令是 load/store，I-cache miss rate 1%，D-cache miss rate 5%，miss penalty 80 cycles：

看程式碼：breakdown() 拆解 CPI
Config、Breakdown 與 breakdown()：L1 miss penalty、I／D 停頓、CPI
typedef struct {
  double baseCPI;      /* 沒有任何 miss 時的 CPI（hit time 已經算在管線裡） */
  double instrRefs;    /* 每條指令取指令的次數，通常是 1 */
  double dataRefs;     /* 每條指令的資料存取次數 = load/store 佔的比例 */
  double iMiss, dMiss; /* I-cache、D-cache 的 miss rate */
  double memPenalty;   /* 到主記憶體的 miss penalty（cycle） */
  int hasL2;           /* 有沒有 L2 */
  double l2Hit;        /* L2 hit time（cycle） */
  double l2LocalMiss;  /* L2 的 local miss rate */
} Config;

typedef struct { double penalty, iStall, dStall, cpi; } Breakdown;

Breakdown breakdown(Config c) {
  Breakdown b;
  b.penalty = c.memPenalty;                          /* L1 miss 要付的代價 */
  if (c.hasL2)                                       /* 有 L2：先問 L2，L2 也 miss 才去主記憶體 */
    b.penalty = c.l2Hit + c.l2LocalMiss * c.memPenalty;
  b.iStall = c.instrRefs * c.iMiss * b.penalty;      /* 取指令造成的停頓 */
  b.dStall = c.dataRefs * c.dMiss * b.penalty;       /* load/store 造成的停頓 */
  b.cpi = c.baseCPI + b.iStall + b.dStall;           /* 實際 CPI */
  return b;
}

動手操作：CPI 計算器

輸入理想 CPI、每條指令取指令的次數、load/store 比例、兩個快取的 miss rate（百分比）和到主記憶體的 penalty（cycle）。要加 L2 就填「L2 hit」和「L2 local miss %」兩格，留空代表沒有 L2。動畫依序算出 L1 miss penalty、I-cache 停頓、D-cache 停頓、CPI，每一步上方用藍色標出用到的參數，最後畫出長條圖看理想 CPI 和兩種停頓各佔多少。

「和沒有 L2 比較」用同一組參數，只拿掉 L2 再算一次；「時脈加倍比較」只把 penalty（以及 L2 hit time）換算成 2 倍的 cycle，其他參數都不變，一次只改一個變因。三個快捷按鈕分別是上一節的例子、加上 L2（hit 10 cycles、local miss 20%）、時脈加倍。

時脈變快，記憶體沒有跟著變快

把處理器時脈加倍，DRAM 並不會因此變快：主記憶體存取一次還是那麼多 ns，但一個 cycle 只剩一半的時間，換算成 cycle 的 miss penalty 就變成 2 倍。理想 CPI 和 miss rate 都不變（同樣的程式、同樣的快取）。

延續上面的例子，原本 penalty 80 cycles，時脈加倍後變 160 cycles：

原本時脈加倍
miss penalty80 cycles160 cycles（同樣的 ns）
停頓0.8 + 1.2 = 2.01.6 + 2.4 = 4.0
CPI3.55.5
每條指令的時間3.5 × T5.5 × T/2 = 2.75 T
停頓佔的比例57%73%

加速 = 3.5T ÷ 2.75T = 1.27 倍。時脈快了 100%，程式只快了 27%，因為多出來的速度大部分都花在等記憶體。比較兩台機器時一定要比時間（CPI × cycle time），不能直接比 CPI：只看 CPI 會以為時脈加倍反而變慢（3.5 → 5.5）。

反過來看，處理器越快，miss 的代價（以 cycle 計）就越大，快取反而越重要。同樣的道理也適用於降低理想 CPI：把理想 CPI 從 1.5 降到 0.75，停頓還是 2.0，CPI 從 3.5 只降到 2.75，只快 27%。這和 Amdahl's Law（籌備中）是同一個道理：沒改善的那部分（記憶體停頓）限制了整體的加速。

有 L2 時差別就出來了：上面的機器加上 L2（hit 10 cycles、local miss 20%，假設 L2 的 ns 時間也固定），時脈加倍的加速是 1.54 倍，比沒有 L2 的 1.27 倍好，因為停頓在 CPI 裡佔的比例變小了。

看程式碼：clockSpeedup() 時脈變成 k 倍的加速
clockSpeedup()：penalty 以 ns 固定，換算成 cycle 變 k 倍
double clockSpeedup(Config c, double k) {
  Config f = c;
  f.memPenalty = c.memPenalty * k;
  f.l2Hit = c.l2Hit * k;
  double oldTime = breakdown(c).cpi * 1.0;          /* 每條指令的時間 = CPI × cycle time */
  double newTime = breakdown(f).cpi * (1.0 / k);    /* cycle time 變成 1/k */
  return oldTime / newTime;
}

多層快取：local 與 global miss rate

要降低 miss penalty，最有效的做法是在 L1 和主記憶體之間再加一層 L2（甚至 L3）。L1 miss 時先問 L2，L2 有就只要等 L2 的 hit time（約 10 cycles），L2 也沒有才去主記憶體。於是 L1 的 miss penalty 本身就變成「L2 的 AMAT」：

AMAT = hit timeL1 + miss rateL1 × (hit timeL2 + local miss rateL2 × miss penaltyL2)
     = hit timeL1 + miss rateL1 × hit timeL2 + global miss rate × miss penaltyL2

L2 的 miss rate 有兩種算法，考題很愛問：

  • Local Miss Rate（區域失誤率）：L2 自己的 miss 次數 ÷ 到達 L2 的存取次數（也就是 L1 miss 的次數）。
  • Global Miss Rate（全域失誤率）：L2 的 miss 次數 ÷ CPU 送出的全部存取次數 = L1 miss rate × L2 local miss rate。它代表「CPU 的存取有多少比例真的走到主記憶體」。

例子：加上 L2 前後

沿用圖 2 的數字（L1 hit 1 cycle、miss rate 5%，L2 hit 10 cycles、local miss 20%，主記憶體 80 cycles）：沒有 L2 時 AMAT = 1 + 0.05 × 80 = 5 cycles；加上 L2 後 L1 的 miss penalty = 10 + 0.2 × 80 = 26 cycles，AMAT = 1 + 0.05 × 26 = 2.3 cycles，存取時間降到原本的 46%。用第二行的寫法驗算：1 + 0.05 × 10 + 0.01 × 80 = 1 + 0.5 + 0.8 = 2.3，一樣。

換成 CPI：前面的例子（I-cache miss 1%、D-cache miss 5%、30% load/store）加上這個 L2，停頓 = (1 × 0.01 + 0.3 × 0.05) × 26 = 0.025 × 26 = 0.65，CPI 從 3.5 降到 2.15，快了 1.63 倍。

為什麼 L2 的 local miss rate 看起來很高

L1 已經把容易命中的存取（迴圈變數、剛用過的資料）都擋掉了，會走到 L2 的是比較「難」的存取，所以 L2 的 local miss rate 常常是 20%～50%。這不代表 L2 沒用，要看的是 global miss rate 和最後的 AMAT。

L1 和 L2 的設計目標不同

  • L1 追求 hit time 短：每次存取都要付 L1 的 hit time，它直接影響 clock cycle，所以 L1 做得小、關聯度低、I／D 分開。
  • L2 追求 miss rate 低：只有 L1 miss 才會用到 L2，hit time 稍長影響不大，所以 L2 做得大、關聯度高、區塊也可以大一點。

多層快取還有內容要不要重複的問題：Inclusive Cache（包含式快取）保證 L1 的內容一定也在 L2，coherence 只要查 L2 就知道上層有沒有，但同一份資料存兩次；Exclusive Cache（互斥式快取）各層不重複，總有效容量是各層相加。這部分在 Cache Coherence（籌備中）會再細談。

寫入策略對停頓的影響

write-through、write-back 的定義在 快取組織與映射 的「寫入的處理」已經講過，這裡只看它們怎麼改變停頓的計算。

write-back：dirty 區塊讓 miss penalty 變大

write-back 的快取在 miss 時，如果被換掉的區塊是 dirty，就要先把它寫回下一層，再讀新的區塊進來（沒有額外緩衝時）。設被換掉的區塊有 d 的比例是 dirty，平均每次 miss 的代價變成：

有效 miss penalty = penalty × (1 + dirty 比例)

上面的例子若 D-cache 是 write-back、30% 被換掉的區塊是 dirty，D-cache 每次 miss 平均要 80 × 1.3 = 104 cycles，D 停頓從 1.2 變 0.3 × 0.05 × 104 = 1.56，CPI 從 3.5 變 3.86。I-cache 不會被寫入，不會有 dirty 區塊，停頓不變。這也是為什麼 read miss 也可能造成寫入：要換掉的區塊是 dirty 時，讀取也得先寫回。

write-through：每次寫入都要等，除非有 write buffer

write-through 的每次 store 都要寫到下一層。如果沒有緩衝，CPU 每次 store 都要等主記憶體：假設 10% 的指令是 store，每次寫入等 80 cycles，每條指令就多 0.1 × 80 = 8 cycles，是前面所有 miss 停頓（2.0）的 4 倍。所以 write-through 幾乎一定搭配 Write Buffer（寫入緩衝區）：CPU 把資料丟進 buffer 就繼續執行，buffer 自己慢慢寫回記憶體，只有 buffer 滿了才需要停。

write buffer 有效的前提是 store 的頻率低於記憶體能吸收的速度。上例 CPI 約 1.5、10% store，平均每 15 個 cycle 就有一次 store，但主記憶體寫一次要 80 cycles，buffer 很快就會滿。所以實際上 write-through 多半只用在 L1，下一層是寫得夠快的 L2（通常是 write-back）。

讀寫比例的 AMAT（write-through、沒有 write buffer）

這是一種固定題型：讀取有 hit 有 miss，寫入不管 hit 或 miss 都要寫到主記憶體。設讀取佔 70%、讀取的 hit rate 95%、快取 1 ns、主記憶體 50 ns，miss 時只算主記憶體的時間：

AMAT = 0.7 × (0.95 × 1 + 0.05 × 50) + 0.3 × 50
     = 0.7 × 3.45 + 15 = 2.415 + 15 = 17.415 ns

只佔 30% 的寫入貢獻了 15 ns，是 AMAT 的 86%，這就是沒有 write buffer 的代價。檢查答案的方向也很有用：read hit rate 越高，AMAT 一定越小，如果你的式子裡 hit rate 的係數讓 AMAT 變大，就是寫錯了。若題目認為 miss 時要先查快取再去主記憶體，讀取 miss 的時間要改成 1 + 50，寫入也可能是 1 + 50，兩種模型的結果都寫出來比較保險。

看程式碼：writeBackPenalty() 與 amatWriteThrough()
writeBackPenalty()、amatWriteThrough()
double writeBackPenalty(double penalty, double dirtyFrac) {
  return penalty * (1 + dirtyFrac);
}

double amatWriteThrough(double readFrac, double readHit, double cacheTime, double memTime) {
  double readTime = readHit * cacheTime + (1 - readHit) * memTime;   /* miss 只算主記憶體時間 */
  return readFrac * readTime + (1 - readFrac) * memTime;
}

Miss penalty 從哪裡來：記憶體組織

miss penalty 不是一個神秘的常數，它是搬一整個區塊的時間，可以拆成三段：

  1. 送位址到記憶體（例如 1 cycle）。
  2. DRAM 存取：記憶體找到資料（例如 12 cycles）。
  3. 匯流排傳送：每傳一次（例如 1 word）花 1 cycle。

區塊有 4 個 word 時，記憶體怎麼組織，決定了這三段要做幾次：

組織方式miss penalty頻寬（16 B ÷ penalty）代價
(a) 1 word 寬1 + 4 × 12 + 4 × 1 = 530.30 B/cycle最便宜
(b) 4 words 寬1 + 12 + 1 = 141.14 B/cycle匯流排、記憶體都要 4 倍寬，快取端還要 mux
(c) 4 bank 交錯1 + 12 + 4 × 1 = 170.94 B/cycle匯流排不用加寬，只要把記憶體分 bank

Interleaving（交錯）把連續的 word 輪流放在不同 bank（位址 0 在 bank 0、位址 1 在 bank 1……），循序讀一個區塊時 4 個 bank 同時工作，12 cycles 的存取時間互相重疊。它用很少的成本得到接近寬記憶體的效果：penalty 從 53 降到 17，只比 4 倍寬的 14 多 3 個 cycle。但 bank 越多不一定越好：如果存取一直落在同一個 bank（bank conflict），平行度就沒了。

把 penalty 帶回前面的 CPI 例子：penalty 53 時 CPI = 1.5 + 0.025 × 53 = 2.825；改用 4 bank 交錯，penalty 17，CPI = 1.925，快了 1.47 倍，而快取本身一點都沒改。

還有兩個不用改記憶體、只縮短 CPU 等待時間的技巧：Early Restart（提早重新開始）是要的那個 word 一到就交給 CPU，不等整個區塊搬完；Critical Word First（關鍵字優先）更進一步，先從記憶體拿 CPU 要的那個 word，其餘的再依序補齊。區塊越大，這兩招省得越多。

看程式碼：missPenalty() 依記憶體組織算 penalty
missPenalty()：送位址＋存取輪數 × DRAM 存取＋傳送次數 × 傳送
int missPenalty(int addr, int access, int xfer, int blockWords, int busWords, int banks) {
  int transfers = blockWords / busWords;                 /* 匯流排要傳幾次 */
  int rounds = (transfers + banks - 1) / banks;          /* 各 bank 同時存取，要存取幾輪 */
  return addr + rounds * access + transfers * xfer;
}

實測：用模擬器跑出 miss rate

考題裡的 miss rate 通常直接給，但它其實是由程式的存取模式決定的。用一個小模擬器實際跑一段程式就能看到：同樣的快取、同樣的資料，換個走訪順序，miss rate 可以差 4 倍。

設定：int a[64][64]（每個 4 bytes，一列 256 bytes，整個陣列 16 KiB，從位址 0 開始以 row-major 存放），D-cache 是 1 KiB 的直接映射快取、區塊 16 bytes（64 個區塊，每塊放 4 個 int）。分別一列一列（a[i][j]，j 在內層）和一行一行（a[j][i]）把整個陣列讀一遍：

走訪順序實測 miss rate原因
一列一列25%每 4 個相鄰的 int 共用一個區塊，只有每塊的第一次是 compulsory miss，其餘 3 次命中：空間區域性用滿了
一行一行（直接映射）100%相鄰兩次存取差 256 bytes = 16 個區塊，區塊編號 16i 對 64 取餘數只會落在 4 個 set；一行 64 個區塊搶 4 格，每次都把下次要用的擠掉
一行一行（2-way、4-way）100%set 數減半，但一行還是只用到 4 格（2 個 set × 2 格、1 個 set × 4 格），問題沒解決
一行一行（全關聯）25%64 格剛好放下一整行的 64 個區塊，接下來 3 行都命中：前面的 100% 全是 conflict miss

把實測值帶進公式（理想 CPI 1、每條指令 0.25 次資料存取、penalty 40 cycles，迴圈很小所以 I-cache 不 miss）：

  • 一列一列：CPI = 1 + 0.25 × 0.25 × 40 = 3.5，D-cache 的 AMAT = 1 + 0.25 × 40 = 11 cycles。
  • 一行一行：CPI = 1 + 0.25 × 1 × 40 = 11，AMAT = 41 cycles。同一個運算慢了 3.14 倍，91% 的時間都在等記憶體。

解法通常不是買更好的快取，而是改程式：Loop Interchange（迴圈交換）把兩層迴圈對調，讓內層沿著記憶體連續的方向走；矩陣太大時再用 Blocking（分塊），一次只處理一塊放得進快取的子矩陣，讓資料在被換掉之前多用幾次。

看程式碼：cacheAccess() 與 traverse() 實測 miss rate
cacheAccess()：一次存取（LRU）；traverse()：走訪 n×n 陣列
void cacheAccess(long addr) {          /* byte 位址，LRU 替換 */
  long block = addr / blockBytes;
  int set = (int)(block % sets);
  long tag = block / sets;
  now++;
  for (int w = 0; w < ways; w++)
    if (cache[set][w].valid && cache[set][w].tag == tag) {
      cache[set][w].lastUsed = now;
      hits++;
      return;
    }
  misses++;
  int v = 0;
  for (int w = 0; w < ways; w++) {
    if (!cache[set][w].valid) { v = w; break; }
    if (cache[set][w].lastUsed < cache[set][v].lastUsed) v = w;
  }
  cache[set][v].valid = 1;
  cache[set][v].tag = tag;
  cache[set][v].lastUsed = now;
}

double traverse(int n, int byRow) {
  for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++) {
      int r = byRow ? i : j, c = byRow ? j : i;      /* byRow = 0：一行一行往下走 */
      cacheAccess((long)(r * n + c) * 4);
    }
  return (double)misses / (hits + misses);
}

改善快取效能的方法比較

回到 AMAT = hit time + miss rate × miss penalty，所有改善方法都是在壓這三項之一，而且常常壓了一項、另一項就變大。考題的「下列敘述何者正確」大多出自這張表：

方法改善哪一項代價、副作用
加大區塊miss rate ↓（利用空間區域性，減少 compulsory miss）；tag 總數 ↓miss penalty ↑；容量固定時區塊數變少，太大時 conflict miss ↑、miss rate 反而回升
加大快取miss rate ↓（capacity miss）hit time ↑、面積與功耗 ↑；不影響 compulsory miss
提高關聯度miss rate ↓（conflict miss）hit time ↑（多個比較器＋mux），可能拖慢時脈
加 L2／L3L1 的 miss penalty ↓面積；L2 的 local miss rate 看起來很高是正常的
加寬記憶體、interleavingmiss penalty ↓、頻寬 ↑匯流排或 bank 的成本；bank conflict 時沒效果
early restart、critical word firstCPU 等待的時間 ↓控制邏輯較複雜；區塊小時幫助不大
write bufferwrite-through 的寫入停頓 ↓buffer 滿了還是要停；read miss 時要檢查 buffer 裡有沒有較新的資料
write-back寫入流量 ↓換掉 dirty 區塊時 penalty ↑；多一個 dirty bit
I-cache、D-cache 分開IF 和 MEM 可以同時存取，消除 structural hazard；可各自調整同容量下 miss rate 可能比 Unified Cache（統一快取）略高
loop interchange、blockingmiss rate ↓要改程式（編譯器只能做一部分）
Prefetching（預取）把 miss 提前到用之前，等待時間 ↓抓錯會浪費頻寬、擠掉有用的資料

I／D 分開時常考的一點：指令的區域性很好，I-cache miss rate 通常很低；資料的 miss rate 較高。把兩者合成一個同樣總容量的 unified cache，整體 miss rate 會落在兩者之間（比原本的 I-cache 高、比原本的 D-cache 低），可是每個 cycle 只能服務一個存取，管線的取指令和 load/store 會互搶，所以 L1 幾乎都分開，L2 以下才 unified。

最後，快取不只影響延遲，也影響頻寬。運算量相對於搬移資料量很少的程式（例如矩陣乘向量、大型模型推論），瓶頸在記憶體頻寬，常用 Arithmetic Intensity（運算強度） = 運算次數 ÷ 搬移的 bytes 來判斷。讓資料留在快取裡、或把資料壓小（例如量化成 8 位元），搬移量減少，速度就跟著提高。

判斷敘述對錯時，問自己三件事：它改的是 hit time、miss rate 還是 miss penalty？另外兩項有沒有變差？題目有沒有寫「always」「一定」這種絕對的字？

易錯點

  • AMAT = miss rate × miss penalty → 每次存取都要先付 hit time，AMAT = hit time + miss rate × penalty；漏掉 hit time 是最常見的陷阱選項 例題
  • 題目給 penalty 50 ns，直接當 50 cycles 用 → 先換算：cycle 數 = ns × GHz，4 GHz 時 50 ns 是 200 cycles 例題
  • D-cache 停頓 = D miss rate × penalty，或只算其中一個快取 → D-cache 要先乘上 load/store 比例，I-cache 每條指令都要算；兩者都要加進 CPI 例題
  • 時脈加倍，程式就快 2 倍；或看 CPI 變大就說變慢 → penalty 的 cycle 數跟著加倍；要比時間 = CPI × cycle time，通常只快一點點 例題
  • 加了 L2 後，算出停頓就當作 CPI → CPI = 理想 CPI + 停頓，0.56 這種只有停頓的數字是陷阱選項 例題
  • L1 的 miss penalty 就是下一層的 hit time → 下一層也可能 miss，要再加上它的 local miss rate × 更下一層的 penalty 例題
  • L2 的 local miss rate 20%，表示 L2 沒什麼用 → 到 L2 的都是 L1 擋不住的存取；要看 global miss rate 和 AMAT 例題
  • write-through 只有寫入 miss 才要到主記憶體 → write-through 的每次寫入都要寫到下一層，沒有 write buffer 時每次都要等 例題
  • write-back 的 read miss 不會產生寫入 → 被換掉的區塊是 dirty 時要先寫回，有效 penalty = penalty × (1 + dirty 比例) 例題
  • 處理器越快，快取越不重要 → 剛好相反，處理器越快，miss penalty 換算成的 cycle 越多，快取越重要 例題
  • 區塊越大，miss rate 一定越低 → 容量固定時區塊太大會讓區塊數太少，miss rate 回升，而且 miss penalty 一定變大 例題
  • 一行一行走陣列一定比一列一列差 → 陣列放得進快取、而且沒有對到同一個 set 時，兩種順序的 miss rate 可以一樣；要實際算 set 例題
