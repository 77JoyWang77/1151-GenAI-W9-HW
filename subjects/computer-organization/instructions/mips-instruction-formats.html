MIPS Instruction Formats MIPS 指令格式R、I、J 三種格式，組語與機器碼互轉、分支與跳躍位址

Ch2 Instructions 難度 R-type I-type J-type branch offset lui/ori

指令也是一個 32 位元的數字

CPU 不認得 add $t0, $s1, $s2 這串文字。程式在記憶體裡和資料一樣，都是一個個的二進位數字，CPU 每次從 PC 指到的位址讀出一個數字，再依照固定的規則把它「切開」，才知道要做什麼運算、用哪幾個暫存器。這種把組語寫成二進位數字的規則，就叫做 Instruction Format（指令格式），翻出來的數字叫 Machine Code（機器碼）。

MIPS 是典型的 RISC（Reduced Instruction Set Computer，精簡指令集電腦），它的格式設計有幾個一定要記住的特點，考題幾乎都從這裡出：

  • 每條指令都是 32 位元（4 bytes），位址也一定對齊 4 的倍數。所以 branch、jump 的位址欄位不用存最低 2 位（一定是 00），範圍可以大 4 倍。
  • 只有三種格式：R、I、J，而且 opcode 永遠在最高 6 位（第 31～26 位）。硬體先看 opcode 就知道後面怎麼切，解碼很簡單。
  • Load-store 架構：算術指令的運算元只能是暫存器或立即值，只有 lw、sw 這類指令會碰記憶體。
  • 32 個通用暫存器，每個暫存器欄位 5 位元（2⁵ = 32）。

對照一下 CISC（Complex Instruction Set Computer，複雜指令集電腦），例如 x86：

比較項目RISC（MIPS、ARM、RISC-V）CISC（x86）
指令長度固定（MIPS 都是 32 位元）不固定（x86 是 1～15 bytes）
格式少而整齊，opcode 位置固定多，欄位位置依指令而變
記憶體運算元只有 load / store 能存取算術指令可以直接用記憶體運算元
通用暫存器多（MIPS 32 個）傳統 x86 只有 8 個
定址模式少（MIPS 5 種）多
每條指令做的事簡單，單條執行時間短，但同一個程式需要較多指令複雜，指令數少，但每條要的週期數差異大
管線化每條指令工作量相近，很適合要先把指令拆成類似 RISC 的 micro-op

「固定長度、格式整齊、每條指令都走一樣的步驟」正是 Pipelining 管線化能順利運作的前提：取指令時一定抓 4 bytes、解碼時欄位位置固定，每個階段的工作量相近。這也是為什麼考題常把「RISC 的格式設計」和「適合管線化」放在一起問。

四個設計原則

MIPS 的格式常被拿來說明四個 ISA 設計原則，選擇題很愛考「這個設計對應哪一個原則」：

原則在 MIPS 格式上的例子
Simplicity favors regularity（簡單來自規律）所有指令 32 位元；算術指令都是「一個目的、兩個來源」三個運算元；opcode 都在同一個位置
Smaller is faster（越小越快）暫存器只有 32 個：暫存器越多，register file 越大、越慢，欄位也要更寬
Make the common case fast（讓常見情況變快）常用的小常數直接放在指令裡（立即值），不用另外 load；分支只比「相等、不相等」，其他比較用 slt 組合
Good design demands good compromises（好的設計需要好的妥協）為了固定 32 位元長度，不得不分成三種格式，立即值也只能有 16 位元

記法：MIPS = 固定 32 位元、三種格式、opcode 在最高 6 位、32 個暫存器、只有 load / store 碰記憶體。看到這五個關鍵字，RISC 和 CISC 的比較題就能直接判斷。

R、I、J 三種格式

MIPS 用 opcode 決定格式：opcode 是 0 就是 R-type，2 或 3 是 J-type（j、jal），其他都是 I-type。三種格式的欄位如下：

欄位位元意義
op31:26（6）opcode，決定格式與大部分指令；R-type 一律是 0
rs25:21（5）第一個來源暫存器；lw / sw 的 base 暫存器；jr 的目標暫存器
rt20:16（5）R-type：第二個來源；I-type：目的暫存器（addi、lw）或第二個來源（sw 要存的資料、beq 比較的對象）
rd15:11（5）R-type 的目的暫存器
shamt10:6（5）shift amount（位移量），只有 sll、srl、sra 用，其他填 0
funct5:0（6）R-type 的運算種類（add、sub、and……）
imm15:0（16）I-type 的立即值、位移量或分支 offset
address25:0（26）J-type 的跳躍位址（word 位址的低 26 位）

為什麼 R-type 的 opcode 都是 0、再用 funct 區分？因為 R-type 指令很多，若每條都佔一個 opcode，6 位元的 64 種 opcode 很快就不夠用。R-type 不需要立即值，剛好有空位放 funct，等於把 opcode 延長成 12 位元。

rt 的角色在兩種格式不同，是最容易搞混的地方：add $t0, $s1, $s2 的結果寫進 rd（$t0），而 addi $t0, $s1, 5 沒有 rd 欄位，結果寫進 rt。所以單一週期資料路徑需要一個 mux（RegDst）選擇寫回 rd 還是 rt，這在 Single-Cycle Datapath 單一週期資料路徑（籌備中）會再看到。

兩個常被拿來出陷阱的歸類：jr 是 R-type（目標在暫存器裡，不需要位址欄位）；MIPS 只有 sll 沒有「算術左移」，因為左移時右邊都補 0，邏輯左移和算術左移結果完全一樣，只有右移需要分 srl（補 0）和 sra（補符號位）。

看程式碼：指令表 OPS 與 findOp()
OpInfo 指令表與查表
typedef enum { FMT_R, FMT_I, FMT_J } Format;

typedef struct {
  const char *name;
  Format fmt;
  int op;       /* 31:26 */
  int funct;    /* 5:0，只有 R-type 用到 */
} OpInfo;

static const OpInfo OPS[] = {
  {"add", FMT_R, 0, 0x20}, {"sub", FMT_R, 0, 0x22}, {"and", FMT_R, 0, 0x24},
  {"or",  FMT_R, 0, 0x25}, {"slt", FMT_R, 0, 0x2A}, {"sll", FMT_R, 0, 0x00},
  {"srl", FMT_R, 0, 0x02}, {"jr",  FMT_R, 0, 0x08},
  {"beq", FMT_I, 4, 0},    {"bne", FMT_I, 5, 0},    {"addi", FMT_I, 8, 0},
  {"slti", FMT_I, 10, 0},  {"andi", FMT_I, 12, 0},  {"ori", FMT_I, 13, 0},
  {"lui", FMT_I, 15, 0},   {"lw",  FMT_I, 35, 0},   {"sw",  FMT_I, 43, 0},
  {"j",   FMT_J, 2, 0},    {"jal", FMT_J, 3, 0},
};

#define NOPS ((int)(sizeof OPS / sizeof OPS[0]))

const OpInfo *findOp(const char *name) {
  for (int i = 0; i < NOPS; i++)
    if (strcmp(OPS[i].name, name) == 0) return &OPS[i];
  return NULL;
}

組語與機器碼互轉

組譯：組語 → 機器碼

  1. 查表：指令名稱 → 格式、opcode（R-type 再查 funct）。
  2. 把組語的運算元對應到欄位：注意組語的順序和欄位順序不同。add rd, rs, rt 的 rd 寫在最前面，欄位卻是 op rs rt rd shamt funct；lw rt, offset(rs) 的 base 放 rs。
  3. 每個欄位寫成固定寬度的二進位；負的立即值用 16 位元 2's complement。
  4. 32 個位元從左到右每 4 個一組，換成 8 個十六進位數字。

例 1：add $t0, $s1, $s2（$t0 = 8、$s1 = 17、$s2 = 18）

欄位oprsrtrdshamtfunct
值017（$s1）18（$s2）8（$t0）032（add）
二進位00000010001100100100000000100000

接起來：0000 0010 0011 0010 0100 0000 0010 0000 = 0x02324020。

例 2：sw $5, -7($9)（sw 的 opcode = 43）

欄位oprs（base）rt（要存的資料）imm
值4395−7
二進位10101101001001011111 1111 1111 1001

結果是 1010 1101 0010 0101 1111 1111 1111 1001 = 0xAD25FFF9。−7 要用 2's complement：65536 − 7 = 65529 = 0xFFF9。常見的錯誤是寫成 1000 0000 0000 0111（最高位當符號、後面放 7 的 sign-magnitude），硬體做符號延伸時會把它當成 −32761。

解碼：機器碼 → 組語

  1. 十六進位展開成 32 個位元。
  2. 先看最高 6 位的 opcode 決定格式，再照格式切開其他欄位。
  3. R-type 查 funct 得到指令名稱；I-type 依指令決定立即值做符號延伸或零延伸。
  4. 照組語的順序寫回去，branch、jump 再算出目標位址。

例 3：0x8FA8FFF8 = 1000 1111 1010 1000 1111 1111 1111 1000。opcode = 100011 = 35 → lw（I-type）；rs = 11101 = 29（$sp）；rt = 01000 = 8（$t0）；imm = 0xFFF8，最高位是 1，符號延伸後是 −8。所以是 lw $t0, -8($sp)。

切欄位在 C 裡就是「右移到最低位，再用遮罩留下該欄位的寬度」；組譯則反過來，把每個欄位左移到自己的位置再 OR 起來。

看程式碼：組譯 encodeR / encodeI / encodeJ 與解碼 decode
encodeR()、encodeI()、encodeJ()：欄位移到位置再 OR
uint32_t encodeR(int rs, int rt, int rd, int shamt, int funct) {
  return (0u << 26)                     /* R-type 的 opcode 一律是 0 */
       | ((uint32_t)rs << 21) | ((uint32_t)rt << 16)
       | ((uint32_t)rd << 11) | ((uint32_t)shamt << 6)
       | (uint32_t)funct;               /* 真正的運算由 funct 決定 */
}

uint32_t encodeI(int op, int rs, int rt, int imm) {
  return ((uint32_t)op << 26) | ((uint32_t)rs << 21) | ((uint32_t)rt << 16)
       | ((uint32_t)imm & 0xFFFFu);     /* 負數取低 16 位，就是 2's complement */
}

uint32_t encodeJ(int op, uint32_t target) {
  return ((uint32_t)op << 26)
       | ((target >> 2) & 0x03FFFFFFu); /* 去掉最低 2 位（必為 00）與最高 4 位 */
}
decode()、formatOf()：右移再遮罩取出欄位
typedef struct {
  int op, rs, rt, rd, shamt, funct;
  uint32_t imm;    /* 15:0，尚未延伸 */
  uint32_t addr;   /* 25:0 */
} Fields;

Fields decode(uint32_t x) {
  Fields f;
  f.op    = (int)((x >> 26) & 0x3F);
  f.rs    = (int)((x >> 21) & 0x1F);
  f.rt    = (int)((x >> 16) & 0x1F);
  f.rd    = (int)((x >> 11) & 0x1F);
  f.shamt = (int)((x >> 6) & 0x1F);
  f.funct = (int)(x & 0x3F);
  f.imm   = x & 0xFFFFu;
  f.addr  = x & 0x03FFFFFFu;
  return f;
}

Format formatOf(int op) {
  if (op == 0) return FMT_R;              /* opcode 0：看 funct */
  if (op == 2 || op == 3) return FMT_J;   /* j、jal */
  return FMT_I;                           /* 其他都是 I-type */
}

立即值：符號延伸、零延伸與 32 位元常數

I-type 的立即值只有 16 位元，但 ALU 做的是 32 位元運算，所以使用前要先「延伸」成 32 位元。延伸方式有兩種：

  • Sign Extension（符號延伸）：把第 15 位（符號位）複製到高 16 位，數值不變。0xFFF8 → 0xFFFFFFF8 = −8。
  • Zero Extension（零延伸）：高 16 位一律補 0。0xFFF8 → 0x0000FFF8 = 65528。
延伸方式指令立即值範圍理由
符號延伸addi、slti、lw / sw 的位移、beq / bne 的 offset−32768～32767要能表示負數（減法、往前的位移、往回的分支）
零延伸andi、ori、xori0～65535邏輯運算是在處理位元樣式，高位補 1 會把高 16 位也改掉
不延伸lui0～65535直接放到高 16 位，低 16 位清 0

所以「所有 I-type 都做符號延伸」是錯的。另外 addiu、sltiu 的 u 只代表「不檢查溢位」或「無號比較」，立即值仍然是符號延伸，這也是常見的混淆點。

看程式碼：signExt16() 與 zeroExt16()
16 位元立即值延伸成 32 位元
int32_t signExt16(uint32_t imm) {        /* addi、slti、lw、sw、beq、bne */
  int32_t v = (int32_t)(imm & 0xFFFFu);
  return v >= 0x8000 ? v - 0x10000 : v;  /* 最高位是 1 → 負數，高 16 位補 1 */
}

uint32_t zeroExt16(uint32_t imm) {       /* andi、ori：高 16 位補 0 */
  return imm & 0xFFFFu;
}

32 位元常數要兩條指令

一條指令最多只能帶 16 位元的立即值，如果常數的高、低 16 位都不是 0（例如 0x0120001A），就要用兩條指令：

lui $t1, 0x0120        # $t1 = 0x01200000（288 = 0x0120）
ori $t1, $t1, 0x001A   # $t1 = 0x0120001A（26 = 0x001A）

第二條用 ori 而不是 addi，是因為 ori 做零延伸，低 16 位填什麼就是什麼。如果改用 addi，低半的最高位是 1 時（≥ 0x8000）會被符號延伸成負數，等於多減了 0x10000，所以 lui 的值要先 +1 補回來。例如 0x1234ABCD：

寫法第一條第二條驗算
lui + orilui $t0, 0x1234ori $t0, $t0, 0xABCD0x12340000 OR 0x0000ABCD = 0x1234ABCD
lui + addilui $t0, 0x1235addi $t0, $t0, 0xABCD（= −21555）0x12350000 − 0x5433 = 0x1234ABCD

RISC-V 沒有 ori 搭配 lui 的慣例，一律用 lui + addi，所以這個「+1」的陷阱在 RISC-V 題目更常出現（見最後一節）。組譯器的虛擬指令 li（load immediate）就是幫你自動展開成這兩條。

看程式碼：把 32 位元常數拆成高低兩半（ori 版／addi 版）
splitOri()：低半零延伸，直接拆
void splitOri(uint32_t c, uint32_t *hi, uint32_t *lo) {
  *hi = c >> 16;          /* lui $t, hi  → $t = hi << 16 */
  *lo = c & 0xFFFFu;      /* ori $t, $t, lo：零延伸，直接填進低 16 位 */
}
splitAddi()：低半符號延伸，高半要先修正
void splitAddi(uint32_t c, uint32_t *hi, uint32_t *lo) {
  *lo = c & 0xFFFFu;                    /* addi 會把 lo 符號延伸 */
  *hi = ((c + 0x8000u) >> 16) & 0xFFFFu; /* lo ≥ 0x8000 時等於減了 0x10000，hi 先加 1 補回來 */
}

Branch 與 Jump 的目標位址

程式要能跳到別的地方執行，MIPS 用兩種不同的方式表示目標位址，這是計算題的主戰場：

beq / bne：PC-relative addressing

條件分支通常跳到附近（迴圈、if-else），所以用 PC-relative Addressing（PC 相對定址）：16 位元欄位存的是「相對位移」而不是位址。

分支目標 = (PC + 4) + 符號延伸(offset) × 4
offset   = (目標 − (PC + 4)) ÷ 4
  • 基準是 PC + 4：硬體在 IF 階段就已經把 PC + 4 算好，拿它當基準最方便。所以 offset = 0 代表「跳到下一條」，等於沒跳。
  • 單位是 word（一條指令）：指令一定對齊 4 bytes，最低 2 位一定是 00，存了也浪費。offset 以 word 計，範圍就是以 byte 計的 4 倍。
  • 範圍：offset 是 −32768～32767，也就是 PC + 4 往前 2¹⁵ 條、往後 2¹⁵ − 1 條指令，約 ±128 KB（−131072～+131068 bytes）。

例：下面這段迴圈從 0x00400000 開始。

0x00400000  loop: beq  $t0, $zero, done   # offset = (0x00400010 − 0x00400004) ÷ 4 = 3
0x00400004        add  $s0, $s0, $t0
0x00400008        addi $t0, $t0, -1
0x0040000C        j    loop
0x00400010  done: ...

beq 的 offset 是 3：從下一條（0x00400004）往後數 3 條就到 done。常見錯誤是從 beq 自己數，得到 4。往回跳的分支 offset 是負的，例如在 0x0040000C 放 bne $t0, $zero, loop，offset = (0x00400000 − 0x00400010) ÷ 4 = −4，欄位是 0xFFFC。

看程式碼：branchTarget() 與 branchOffset()
分支目標與 offset（含範圍檢查）
uint32_t branchTarget(uint32_t pc, uint32_t imm) {
  return pc + 4 + (uint32_t)signExt16(imm) * 4u;
}

int branchOffset(uint32_t pc, uint32_t target, int *off) {
  int64_t diff = (int64_t)target - ((int64_t)pc + 4);
  if (diff % 4 != 0) return 0;                     /* 目標沒有對齊 4 */
  int64_t words = diff / 4;
  if (words < -32768 || words > 32767) return 0;   /* 16 位元放不下：超出 ±2^15 words */
  *off = (int)words;
  return 1;
}

目標太遠：beq 改寫成 bne + j

如果目標超出 ±2¹⁵ 條指令，beq 放不下。組譯器會把條件反過來，讓 bne 跳過下一條，再由 j 負責遠跳：

beq $s0, $s1, Far          bne $s0, $s1, L2   # 不相等就跳過 j
                     →      j   Far
                       L2:  ...

這樣改寫的原因是距離，不是 beq 比 bne 慢。考題會故意給「因為 bne 和 j 比較快」這種錯誤理由。

j / jal：pseudodirect addressing

J-type 除了 opcode 之外 26 位元全部拿來放位址，叫 Pseudodirect Addressing（虛擬直接定址）：

jump 目標 = (PC + 4)[31:28] ‖ address[25:0] ‖ 00
address   = 目標[27:2]　（= (目標 >> 2) 再只留低 26 位）
  • 26 位 address 是「word 位址」，左移 2 位補回 00，得到 28 位元。
  • 剩下的最高 4 位沒地方放，直接沿用 PC + 4 的最高 4 位。所以 j 只能跳到和 PC + 4 同一個 256 MB（2²⁸ bytes）區塊裡的任何位置。
  • 它不是「前後 ±2²⁵」的相對跳躍：只要跨過 256 MB 區塊的邊界，距離再近也跳不過去。最極端的例子是 j 放在 0x0FFFFFFC，PC + 4 = 0x10000000 已經是下一個區塊，它反而跳不回只差 12 bytes 的 0x0FFFFFF0。
  • 組譯時很多人只做「目標 >> 2」，忘了去掉最高 4 位。例如目標 0x88004004 右移 2 位是 0x22001001，但 address 欄位只能放低 26 位 0x2001001，接上 opcode 2 後是 0x0A001001，而不是把 0x22001001 塞進去。

給定 PC 求 j 能跳到的最大位址：高 4 位取 PC + 4 的，後面 28 位全 1 再把最低 2 位清 0。例如 PC = 0xAB05FF84，PC + 4 = 0xAB05FF88，高 4 位是 0xA，最大目標就是 0xAFFFFFFC。

jal 和 j 格式相同，只是多把 PC + 4 存進 $ra；要跳到任意 32 位元位址（例如函式指標、或從函式返回）就用 jr，目標放在暫存器裡，不受 256 MB 限制。

看程式碼：jumpTarget() 與 canJump()
pseudodirect：接上 PC + 4 的高 4 位
uint32_t jumpTarget(uint32_t pc, uint32_t addr26) {
  return ((pc + 4) & 0xF0000000u) | (addr26 << 2);
}

int canJump(uint32_t pc, uint32_t target) {
  return target % 4 == 0 &&
         ((pc + 4) & 0xF0000000u) == (target & 0xF0000000u);  /* 同一個 256MB 區塊 */
}

MIPS 的五種定址模式

到這裡已經看過 MIPS 全部五種 Addressing Mode（定址模式），簡單整理（細節與其他 ISA 的比較在 Addressing Modes 定址模式（籌備中）主題）：

模式運算元或目標在哪裡格式例子
Register暫存器Radd、jr
Immediate指令裡的 16 位元常數Iaddi、ori、lui
Base（displacement）記憶體[rs + 符號延伸(imm)]Ilw、sw
PC-relative(PC + 4) + imm × 4Ibeq、bne
Pseudodirect(PC + 4)[31:28] ‖ address ‖ 00Jj、jal

注意 PC-relative 也是 I-type。另外，真實的 MIPS 硬體在分支後面有一個 branch delay slot（分支後的那一條指令一定會執行），它和管線的控制危障有關，在 Control Hazards and Branch Prediction 控制危障與分支預測（籌備中）說明；本頁計算目標位址時都不考慮 delay slot。

欄位寬度的取捨

指令長度固定時，各欄位是在搶同一塊 32 位元，一邊變寬另一邊就要變窄。設計題、改格式題都是用這幾條關係在推：

欄位寬度能表示的東西
opcode n bits最多 2ⁿ 種 opcode
暫存器欄位 k bits最多 2ᵏ 個暫存器（和暫存器本身幾位元無關）
有號立即值 m bits−2ᵐ⁻¹～2ᵐ⁻¹ − 1（2's complement），不是 −2ᵐ～2ᵐ − 1
無號立即值 m bits0～2ᵐ − 1
分支 offset m bits（以 word 計）PC + 4 前後 −2ᵐ⁻¹～2ᵐ⁻¹ − 1 條指令，乘 4 才是 bytes

例：一部 16 位元電腦的 I-type 是 op 4 bits、rs 3 bits、rt 3 bits、imm 6 bits。它最多 2⁴ = 16 種 opcode、2³ = 8 個暫存器（每個暫存器仍是 16 位元寬，3 bits 只決定「個數」），imm 範圍是 −32～31。

回到 MIPS：如果暫存器加倍到 64 個，每個暫存器欄位要 6 bits。I-type 有 rs、rt 兩個欄位，立即值就從 16 bits 縮成 14 bits；R-type 三個暫存器欄位共多用 3 bits，funct 和 shamt 要讓位。反過來，暫存器減半成 16 個，I-type 可以多出 2 位立即值。所以：

  • 暫存器多的好處：變數可以留在暫存器裡，減少 register spilling（把變數暫存回記憶體）的 load / store，指令數可能下降。
  • 暫存器多的代價：欄位變寬，立即值、opcode 空間變小，甚至指令得變長；register file 變大也變慢（smaller is faster）。

為什麼 MIPS 沒有 blt（小於就跳）或 blti？比大小要做減法再看符號，比只檢查「相等」複雜，做進分支會拉長關鍵路徑；而 blti 需要兩個立即值（比較用的常數、分支 offset）加一個暫存器，32 位元放不下。MIPS 的做法是 slt / slti 先算出 0 或 1，再用 beq / bne 和 $zero 比較，讓最常用的相等分支保持簡單快速（make the common case fast）。

ISA 的設計會同時影響 CPU time 公式裡的三個因素（指令數 IC、CPI、時脈週期），例如加複雜的定址模式可以減少 IC，但可能拉長時脈週期，這類取捨的算法見 CPU Time and CPI CPU 時間與 CPI。

RISC-V 對照

台大等學校的考題已改用 RISC-V（第五代 RISC 開放指令集），它的設計和 MIPS 很像（固定 32 位元、32 個暫存器 x0～x31、load-store），但格式切得更細，有六種：

比較MIPSRISC-V（RV32I）
opcode 位置最高 6 位（31:26）最低 7 位（6:0），再加 funct3、funct7
暫存器欄位位置rt 在 R-type 是來源、在 I-type 是目的，寫回要用 mux 選 rd 或 rtrd、rs1、rs2 在所有格式位置固定，解碼時可以先讀暫存器
算術立即值16 bits12 bits（I-type）
store 的位移和 lw 同一個 I-typeS-type：12 位拆成兩段，讓 rs2 保持原位
條件分支16 bits × 4（以 word 計），基準 PC + 4，約 ±128 KBB-type 12 bits × 2（以 2 bytes 計），基準是分支自己的 PC，−4096～+4094 bytes，約 ±2¹⁰ 條指令
無條件跳躍j：26 bits，pseudodirect，256 MB 區塊jal：J-type 20 bits × 2，PC-relative，±1 MB，約 ±2¹⁸ 條指令
載入 32 位元常數lui（16 位）+ orilui（20 位）+ addi（12 位，符號延伸）

RISC-V 分支以 2 bytes 為單位，是為了支援 16 位元的壓縮指令（C 擴充），指令只保證對齊 2 bytes。用 lui + addi 載入常數時，若低 12 位的最高位（第 11 位）是 1，addi 會把它當成負數，lui 的值要 +1。例如 0x11232334 的低 12 位 0x334 最高位是 0，直接 lui 0x11232、addi 0x334 即可；0x12345FFF 的低 12 位 0xFFF 會變成 −1，lui 要放 0x12346。

RISC-V 的 shift 指令（slli 等）把位移量放在 I-type 的立即值欄位：RV32 是 0～31、RV64 是 0～63，範圍由資料寬度決定，和暫存器有幾個無關。

  • offset 以 byte 為單位 → 以 word 為單位，使用時乘 4（左移 2），範圍才有 ±2¹⁵ 條指令 例題
